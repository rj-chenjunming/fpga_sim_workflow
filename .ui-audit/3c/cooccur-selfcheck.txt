## 3 判据判别性：3 个必然共命中 + 3 个必然不共命中
必然共命中（前 3 个在输入清单内，后 2 个用到附加探针 button / #btnS0）：
  - .btn                ↔ .btn-sm              count=651   （同一元素同时有这两个类）
  - .btn                ↔ .btn:disabled        count=228   （`:disabled` 是静态伪类，保留后可命中）
  - .btn-ghost          ↔ .btn-ghost:hover     count=369   （跨 sanitize：:hover 剥掉后才命中）
  - .rail-entry         ↔ #btnS0               count=33    （#btnS0 本身带 rail-entry 类）
  - .btn                ↔ button               count=1161  （元素选择器 vs 类选择器，最典型的竞争）
  `.btn-ghost` ↔ `.btn-ghost:hover` 是跨 sanitize 的对：`:hover` 在 querySelectorAll 里恒不命中，
  sanitize 成 `.btn-ghost` 后与静态版共命中 ⇒ 这正是「剥交互态」要保住的那类证据。
必然不共命中（实测 count=0，且两者都在输入清单里 ⇒ 不是「没测量」造成的假阴性）：
  - .dp-list ↔ .rail-entry（0）
  - .run-item ↔ .agent-open（0）
  - .aw-layout ↔ .aw-intervene（0，容器与后代不是同一元素）

## 6 blocked_pairs 回填（Lead 的竞争对）
- 去重后 329 对；co_match 真出现过的：[('.btn', '.btn-sm', 651), ('.btn', '.btn-primary', 195)]
- 其余 327 对在这些受控状态下**没有共命中**，逐对结果（含 count / 样例 / measured 标记）在
  cooccur.json 的 blocked_pairs 里；blocked_pairs_unmeasured = 0，即所有对的两方都在被测集合内
  （凡是一方没被测的选择器，工具会记 measured=false 而不是记成「不共命中」）。
- 口径：pairs_checked = C(214,2) = 22791（214 = 输入 212 + 探针 2）；co_match_pairs = 68。
- sanitize 实际改动 3 条（其余 211 条原样可用）：
  - .btn-ghost:hover       → .btn-ghost     交互态 :hover 已剥（querySelectorAll 恒不命中）
  - .mark:after            → .mark          pseudo-element :after 已剥
  - .pulse:after           → .pulse         pseudo-element :after 已剥
  剥掉的伪元素不在 querySelectorAll 的可匹配范围内，伪元素之间的互斥只能由静态判据处理；
  剥掉交互态伪类会让命中集合变成「该规则目标元素」的**上界近似**（宁可多算共命中，不假绿）。
