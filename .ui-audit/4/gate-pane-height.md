## 0 先说三个硬事实（会改变方案取舍）

1. **常数管的是"窗格多高"，不是"窗格在屏幕的哪个位置"。** `max-height` 在双栏卡片正文上，
   放宽它**不会**把 `#gateMaterial` 的 `y` 提前 —— 实测 `y=828.3(720) / 832.3(900) / 811.9(1080)` 与常数无关。
   所以"让闸门材料在 1280×720 首屏进入"**不可能靠改常数达成**（差 108.3px，见 §2.3）。
2. **现状常数在 1920×1080 已经自相矛盾**：`calc(100dvh - 340px)` = **740px**，但上限 `720px` 把它截到 720
   （实测 `#gateMaterial.h = 720`）。"放宽"有一个**可辩护的锚点**：让 `clamp` 的上限不再截断它自己的推导值。
3. **任务书里提到的 `#gateActions` 全仓不存在**（`grep -rn gateActions loop/ doc/ kb/` = **0** 命中）。
   闸门操作栏的 id 是 **`#gatePanel`**（`index.html:377`）。本文所有读数用 `#gatePanel`。

### 2.2 token 解析值 = 实测窗格高（**现状常数被运行时证实**）

| 视口 | `clamp(300, vh-340, 720)` | `#gateMaterial.h` | `#gatePanel.h` |
|---|---|---|---|
| 1280×720 | **380** | **380** | **380** |
| 1440×900 | **560** | **560** | 461.1（内容只到 461.1，未触顶） |
| 1920×1080 | 740 → 截 **720** | **720** | 461.1 |

→ `#gateMaterial` 三档全部**内容溢出、被上限截住**（`h` == 上限）；`#gatePanel` 在 900/1080 是**内容不足、按内容收缩**（461.1），正是 A11「内容不足时不滚动」的现行证据。

### 2.3 1280×720 上方占用链与"要压掉多少"

由实测边界 + 已知 CSS 边距推导（挂靠：`#gateHead` 顶 206.2 = `header` 72 + `main` padding-top 28 + 共享 `.page-head` 88.2 + 下边距 18；`#gateHead` 下边距 14；`.card` 下边距 20）：

```
header                0      →  72
(main padding-top)            → 100
.page-head(共享)      100     → 188.2      ← M6_fold@1280 实测 .page-head y=100 bottom=188.2
(page-head margin)            → 206.2
#gateHead             206.2   → 300.6   (h=94.4)
(gateHead margin)             → 314.6
四段流程卡            314.6   → 808.3   (高 493.7，推导值)
(.card margin 20)             → 828.3
#gateMaterial         828.3   → 1208.3  (h=380)
```

- **要让顶边进入首屏（y < 720）**：需上方压掉 **108.3px**。
- **要让整栏进入首屏（bottom ≤ 720）**：需压掉 **488.3px** —— 且它自身就高 380px，**必须同时折叠结构+缩小窗格**才可能。

可压块（实测/推导）：

| 块 | 可省 | 压完后的 `#gateMaterial.y` |
|---|---|---|
| A 共享页头 `.page-head`（88.2 + 18，**四视图共用**） | 106.2 | **722.1**（差 2.1px 仍不进） |
| B `#gateHead` 94.4 → 1920 档的 56 | 38.4 | 789.9 |
| C **四段流程卡折叠成仅卡片头**（493.7 → 52） | **441.7** | **386.6** ✅ |
| A+C | 547.9 | 280.4 |

**结论**：1280×720 首屏进入的**唯一现实路径是 C（结构折叠）**；A 单独差 2.1px，且删共享页头会伤四视图标题。

> **测量缺口（诚实登记）**：`measure_gate_fold()` 没抓两栏的 `scrollHeight`（只有 `clientHeight` 一侧），所以"材料总高多少 px、放宽多少才不滚"无法从本轮读数直接算出。若要精确选常数，需给 `measure.py` 的 targets 加 `#gateMaterial/#gatePanel` 的 `scrollHeight`（`.ui-audit/measure.py` 是临时件，可改；`doc/evidence/**` 只增不改，另存新读数）。

## 3 候选方案

> 三档共同点：都**不改**两栏结构、**不改** `.gate-pane` 的其它声明、**不改** `#gateMaterial/#gatePanel` 的 id/class；
> 都要改 `doc/spec/WEB_UI_SPEC.md` §14（+ §5 若有引用原文）+ `tests/browser/test_gate_panes.py:17-19`。

### 方案 A1（**推荐**）：`clamp(300px, calc(100dvh - 300px), 860px)`

推导锚点：`300` 不是拍脑袋 —— 1280×720 实测**上方 chrome 到 `#gateHead` 底 = 300.6**（header 72 + padding 28 + page-head 88.2 + 18 + gateHead 94.4），
即"窗格高 = 视口高 − 到闸门视图标题底为止的 chrome"；上限 `860` 让 `calc` 自己的值在 1080 不被截断（740），且只在 vh ≥ 1160 时才触顶。

| 视口 | 现 `maxHeight` | A1 | Δ | 页 `scrollHeight`（推算） | 两栏底边 |
|---|---|---|---|---|---|
| 1280×720 | 380 | **420** | +40（+10.5%） | 1324 → 1364 | 1208.3 → 1248.3 |
| 1440×900 | 560 | **600** | +40（+7.1%） | 1504 → 1544 | 1392.3 → 1432.3 |
| 1920×1080 | 720 | **780** | +60（+8.3%） | 1648 → 1708 | 1531.9 → 1591.9 |

- **改动文件**：`app.css`（1 行 token + 该块注释里的"判定值"文字）、`WEB_UI_SPEC.md` §14 那一条（1 行公式 + 增补说明）、`tests/browser/test_gate_panes.py:17-19`（3 个常量）。
- **对 A11「内容不足时不滚动」**：无影响（`max-height` 仍是上限；`#gatePanel` 在 900/1080 仍是内容 461.1 < 600/780 → 依旧不滚）。
- **对 A11「滚一栏另一栏不动」**：无影响（容器/`overscroll-behavior`/`scrollbar-gutter` 未动）。1280 下两栏仍超上限（材料 12 条夹具远超 420），B2「真的溢出」仍成立。
- **对 A12**：无影响（`y` 不变；1440 判据 `y<900` 仍由 `y=832.3` 满足）。
- **风险**：页高各增 40/40/60 → 页面级滚动略多；两栏底边更靠下（1080 下底边 1591.9，视口 1080 → 仍需页滚 512px 才能看到栏底，现状 452px）。**不声称"1280 首屏进入"**。
- **好处**：修掉 1080 的 20px 自相矛盾；`340` 是批次 1+2 压缩留白前的旧口径，A1 把它对齐到实测 chrome。

### 方案 A2（激进放宽）：`clamp(240px, calc(100dvh - 260px), 880px)`

| 视口 | A2 | Δ |
|---|---|---|
| 1280×720 | 460 | +80 |
| 1440×900 | 640 | +80 |
| 1920×1080 | 820 | +100 |

- 改动文件同 A1（数值不同）；`min` 由 300 → 240 只在小视口（vh < 500）才起作用，**与验收视口无关**，**没有实测依据**，属于"为了让数字看起来更宽"而调，不建议。
- **风险**：1280 下两栏 460 + 上方 828.3 = 底边 1288，页面越滚越长；一旦有人把页面滚动当成"窗格滚动"来用，就出现双层滚动的操作混淆（现状已如此，A2 放大）。对 A11 判据仍全部成立。

### 方案 A3（结构式，**非当前阶段**）：常数不动，闸门视图折叠四段流程

- 改动：`index.html`（闸门视图的四段流程卡加折叠态 + 摘要行）、`app.css`（折叠态样式，**仍用同一个 token**）、`app.js`（折叠状态记忆，别在 1.5 s 重绘里丢）、`WEB_UI_SPEC.md` §5/§14（结构增补 1 条）、`tests/browser/test_ui_visual_20261030.py`（新增 1280 首屏断言）+ 可能 `test_gate_panes.py`（几何不变，预计不红）。
- 效果：`#gateMaterial.y` 828.3 → **386.6**，1280×720 **首屏进入成立**（`visibleRatio = (720-386.6)/380 = 0.877`）。
- **对 A11「内容不足时不滚动」「滚一栏另一栏不动」**：无影响（窗格没动）；但会**隐藏阶段进度**（§4.2「折叠+展开当前段」的语义要在闸门视图里重新约定：保留卡片头里的聚合信息 + `aria-expanded` 可展开）。
- **风险**：改结构、改规格两条（§5 §14）、新增浏览器用例；人在做闸门决策时看不到"现在卡在哪一段"（可用卡片头摘要缓解）。人裁已把它归为"非当前阶段"。

## 4 推荐与逐条落点

**推荐 A1**，理由：
1. 人裁 ③ 明确要"常数放宽" → A1 是三项里唯一**只动常数**的落地；
2. 它修掉一个客观矛盾（1080 的 `calc` 740 被上限 720 截断），并且把 `340` 这个"批次 1+2 压缩留白前"的旧口径改成实测 chrome（300.6）；
3. 对 A11 四条判据零影响，改动面最小，回滚只需 revert 1 行 + 3 个常量；
4. **不冒充解决 1280 首屏**——那需要 A3，人裁已把它放到非当前阶段。

### 4.1 逐条落点

| # | 文件 | 位置（选择器/锚） | 改法 |
|---|---|---|---|
| 1 | `doc/spec/WEB_UI_SPEC.md` | §14「闸门双栏局部滚动（2026-10-29 增补）」那条的公式（快照 `:839`） | `clamp(300px, calc(100dvh - 340px), 720px)` → `clamp(300px, calc(100dvh - 300px), 860px)`，并追加一句「**2026-10-30 批次 4 放宽**：`300` = 实测上方 chrome 至 `#gateHead` 底（1280×720 实测 300.6）；`860` 使 1920×1080 的 `calc` 值（780）不再被上限截断（原 720 会截断 740）。**只放宽上限，不改「上限不是定高」语义**。」 |
| 2 | 同上 | §5 第 2 条（快照 `:406`） | 只写「同一口径 `--gate-pane-max-h`」，未抄数值 → **不需改**（复核一遍再确认） |
| 3 | `loop/web/app.css` | `.gate-pane{}` 内 `--gate-pane-max-h`（快照 `:626`） | 值改 `clamp(300px, calc(100dvh - 300px), 860px)`；同块注释（快照 `:624-625`）里的"判定值 = clamp(…)"同步 |

| 5 | `doc/STATUS.md` | 新段（Lead 唯一数字源） | 记录：新常数、三视口实测 `maxHeight`、`scrollHeight` 变化、A11/A12 仍绿、**1280 首屏仍未进入（缺口 108.3px，需结构折叠）** |

### 4.2 为什么"改常数 = 改 §14 承诺"（必须先改规格）

§14 与 §5 都把 `--gate-pane-max-h` 的**具体公式**写进了契约；`test_gate_panes.py:17-19` 把同一公式抄成期望值。
所以顺序必须是：**Lead 改 §14（+ 必要时 §5）→ 改测试常量（先红）→ 改 `app.css` → 绿 → STATUS**。
若先改代码后改规格，就是"实现定义契约"，违反 AGENTS §2「改契约先于改代码」。
