### Q2 `raw2cpu()` 的字节序翻转等价性是否成立？

**结论：等价性成立（逐位可证 + 实测可印证）。若不成立，用例的 3 条复位值断言会全部**假失败**（FAIL 而非假通过）。**

**依据 A — 逐位证明（TB 侧代码）**：

- `PCIE_REG_RD` 返回**未翻转的镜像原始字**：`pcie_sequence.sv:570` `rdata = pcie_pkg::FPGA_RAM_MIRROR[addr][…]`。
- 项目惯用的翻转分支：`pcie_sequence.sv:589-594`：
  ```systemverilog
  589: if (big_d) begin
  590:   rdata_tmp = pcie_pkg::FPGA_RAM_MIRROR[addr][…];
  592:   for (int i=0;i<4;i++) rdata[i*8+:8] = rdata_tmp[31-i*8-:8];
  ```
  展开：`rdata[7:0]=tmp[31:24]`、`rdata[15:8]=tmp[23:16]`、`rdata[23:16]=tmp[15:8]`、`rdata[31:24]=tmp[7:0]`。
- 用例 `raw2cpu`（`:228-230`）`return {raw[7:0], raw[15:8], raw[23:16], raw[31:24]}`，按拼接语义：`result[31:24]=raw[7:0]`、`[23:16]=raw[15:8]`、`[15:8]=raw[23:16]`、`[7:0]=raw[31:24]`。
- ⇒ 两者**逐位相同**（同一置换：byte0↔byte3、byte1↔byte2）。**依据 A 成立**。

**依据 B — 实测印证**：`LOG/tc_rtc_07_1_run.log:943` `@ADDR[0x2000] -> DATA[0x4e000000]`（裸 `PCIE_REG_RD`），紧接 `:944` `[set_rdchk] @ADDR[0x2000] -> DATA[0x4e]`（翻转后）⇒ 同一地址 raw `0x4e000000` ↔ 翻转后 `0x4e`，与 `raw2cpu(0x4e000000) = 0x0000004e` 完全吻合。

### Q3 `pcie_sequence.sv:799-803` 的 `base_addr` 形参/局部重定义，对"地址敏感性"的影响；该 API 能否用于地址断言？
