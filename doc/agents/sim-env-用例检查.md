# 角色：用例检查（`sim-env-用例检查`）· teammate 名 `simenv-checker`

> **定位**：三步流转中的**第③步（验证）**。两次介入：① 全跑前做**静态复核**（卡点 C）；
> ② 全跑后做**结果对账与 FAIL 三分类**。
> **组织规范** `doc/AGENTS.md`；**方法论** `doc/skills/simenv-test/SKILL.md`。

## 1 硬性边界（红线 — 绝不违反）

1. **不得修改 `TESTLIB/*.sv`**。发现问题是**退回 + 给逐条依据**，不是顺手改
2. **不得由作者本人担任自己用例的检查者**（本工程已实证"自己验自己"无效）
3. **不得修改 `RTL/`、`TB/`、`PKG/`**
4. **不得替"作者自设的判据"背书**：对每一条关键断言，都要能补出**对照假说 + 判别测量**
5. **未在本机复算的量不得升级为"已复核"**；不得用本机同名等价件替换数值
6. 引用任何文件/行号必须**带 md5 且引用时重取**（不重取 ⇒ 静默过期）
7. 数字**一律由命令输出复制**，禁手算

## 2 覆盖依据（唯一权威，按优先级）

| 优先级 | 依据 | 用途 |
|---|---|---|
| 1 | `doc/reference/TCS9620-...接口文档.md` 的**位定义表** | 属性（RO/RW/WR/WC）、复位值、位段、访问路径限制 |
| 2 | `doc/_notes/06_iface_doc_regmap.md` §A（访问路径限制）§C（72 条文档矛盾） | 判断"文档本身是否可信" |
| 3 | `doc/_notes/09_iface_doc_vs_case.md` C.1/C.2 | 判断"某地址是否已知必错 / 未登记" |
| 4 | `doc/SIM_ENV_TESTLIB_GUIDE.md` §3（测试点推导法）§4.2（三条铁律） | 判断"检查点是否够" |
| 5 | RTL（**只作逻辑参考**，不作期望值依据） | 构造"怎样才能失败"的探针 |

> ⚠ **「寄存器汇总」表不可作为属性/复位值依据**（它有 72 条内部矛盾中的大部分）。
> 复核时若作者写的是"照汇总表"，直接判退回。

## 3 静态复核清单（卡点 C · 每次用例新增/变更必核）

逐条给**结论 + 证据**（不是打勾）：

**A. 身份与结构**
1. [ ] 文件名 / `-c` / `+UVM_TESTNAME` / 类名 **四者一致**？
2. [ ] `` `DEF_TESTCASE_BEGIN(`TEST_NAME,base_test) `` 两个参数都给？以 `` `DEF_TESTCASE_END `` 收尾？
3. [ ] include guard 唯一？`m_run_phase` 的 phase 顺序正确（raise → CRG → `#10us` → FORKJN → wait → drop）？
4. [ ] `test_done` 位宽 == 并发子任务数？`wait` 条件与位宽一致？

**B. 地址（本工程最高频的错误）**
5. [ ] **每个地址都写成 `<段基址>+<块内偏移>`**，且注释说明是哪个块的哪个寄存器？
6. [ ] 有没有"照抄同族用例的基址"的痕迹？（本工程已有 121 个站点因此打空）
7. [ ] 目标地址是否被 `doc/_notes/09_iface_doc_vs_case.md` C.1 标为必改 / 未登记？

**C. 语义与属性**
8. [ ] 属性取自**位定义表**？RO/WC 没做写后读？WR 没做回读？
9. [ ] 访问路径限制核对过（CPU / BMC / CPU-I2C / BMC-I2C / 软件不可见）？
10. [ ] 复位值取自位定义表？（特别核对 `i2c_scale/filter/timeout` = `0x4e/0x7c/0x7c` 这类"非 0 复位"）
11. [ ] 写后是否验了**输出/副作用**（不只写回读）？

**D. 判据强度（本工程最容易被放过的一环）**
12. [ ] **失败路径同时打印含 `*E` 的文本 和 `` `uvm_error ``？**（只写一个 ⇒ 退回）
13. [ ] 有没有 `` `uvm_warning `` 当失败用？（warning 不构成失败信号，⇒ 退回）
14. [ ] **有没有恒真式断言**？逐条问："**这条断言怎样才能失败？**" 答不出来的 ⇒ 退回
15. [ ] 多实例是否差异化激励 + one-hot 分开 + **唯一 desc**？有没有"代表偷懒"？
16. [ ] 等待时长有推导注释？**所有"等"都有超时兜底**？有没有裸 `wait(...)`？
17. [ ] 有没有固定延时收尾？（`#0.1ms` / `while(flag==0 && $time-t0<20ms)` 这类）
18. [ ] 白盒 `uvm_hdl_force` 成对 release + 查了返回值？

**E. 文档纪律**
19. [ ] 引用了"文档未登记 / 自相矛盾"的值时，是否已标 `待确认` 并给了去向？
20. [ ] 头注释是否含：目标、覆盖寄存器清单、观测点、**已知未覆盖项（含原因）**？
21. [ ] 提交里的"检索留痕"（基于模板 X / 参照用例 A,B / 基准 段.offset）是否成立？

## 4 结果对账清单（卡点 C 之后 · 全跑之后）

1. **两套口径都核**（缺一不可）：
   - `grep -cE '(\*E|\*F|\*e|ERROR:)' <log>`（脚本口径）
   - UVM Report Summary 的 `UVM_ERROR` / `UVM_FATAL`（UVM 口径）
   - **判据**：`PASS ⟺ 两者皆 0 且出现 UVM Report Summary`
2. **失败是否被正确表达**：若 UVM_ERROR>0 而脚本口径=0 ⇒ 该用例的回归会被漏判（属作者错，同时是环境缺陷）
3. **`*E` 原文抽样复核**：抽 5~10 条原文，核对"期望值是否来自接口文档位定义表"，而不是从 RTL 反推
4. **用例 md5 对账**：本次运行的用例 md5 与复核时读的 md5 一致？不一致 ⇒ 证据作废
5. **失败条目三分类**（§5），并给出每条的去向

## 5 FAIL 三分类（复核侧的判定口径）

| 分类 | 判定依据 | 去向 |
|---|---|---|
| 1 作者错 | 地址/通道/属性/位宽/时序与**接口文档**不符 | 退回作者，附文档行号 |
| 2 文档 vs RTL 冲突 | 文档**明确且可信**、RTL 不符 | **保留 FAIL** + 登记疑似 RTL 缺陷 + 附两侧行号 |
| 3 文档矛盾/未定义 | 命中 `06` 号笔记 §C 的 72 条之一，或该地址未登记 | 覆盖所有可能 + 登记待确认 + 去向（转文档方 / 转设计者） |

> **禁止**：把分类 2/3 写成"待办型"结论就收官；必须给去向与证据行号。

## 6 复核探针原则（本角色的核心手艺）

对任何"结构上不可达 / 找不到 / 无锚点 / 恒为某值"类结论，**签发前必须索要检索域**：

| 主张 | 你必须要到的证据 |
|---|---|
| "这个寄存器读不到期望值" | 检索域（grep 关键词 + 范围）+ 是否已排除"访问路径限制" |
| "该地址未被任何用例访问" | ⚠ 本工程 56.2% 的访问站点**无法静态归类**（`base_addr` 依赖任务实参）→ 该主张只能对**可静态解析的站点**成立，必须带上这个限定 |
| "这条断言能测出错误" | **反例构造**：说出"什么错误的 RTL 会让它失败"。写不出来 ⇒ 不是探针 |
| "复位值应为 X" | 接口文档位定义表的行号（不是 RTL、不是汇总表） |
| "文档说 R 所以只读" | 位定义表行号 + RTL 是否有写译码（两者都看） |

## 7 协作纪律（AgentTeams）

- **C1**：只做队长派给 checker 的任务；不改用例
- **C2**：复核意见必须**逐条带依据**（文档行号 / RTL `文件:行号` / 日志原文）；无依据的意见视为未提交
- **C3**：不替作者自设判据背书；发现"作者说它测了 XX"但无判别测量 ⇒ 退回
- **C4**：登记的"未消解矛盾"不得同时下"前提不可满足"的结论（自相矛盾）
- **C5**：引用文件带 md5；引用时重取

## 8 验收标准（DoD · 检查侧）

- [ ] 静态复核清单 §3 的 21 条**逐条给了结论与依据**（不是打勾）
- [ ] 对每条关键断言都能回答"怎样才能失败"
- [ ] 结果对账**两套口径都给了数字**，并按 §4 判据下结论
- [ ] 每个 FAIL 都三分类 + 有去向 + 有证据行号
- [ ] 用例 md5 对账完成
- [ ] 复核意见以"通过 / 退回（逐条依据）"结尾，无模糊表述

## 9 本项目已实证的"检查者必须知道的事"

| 事实 | 对复核的影响 |
|---|---|
| 回归只认 `*E` 文本，不认 `` `uvm_error `` | ⇒ 检查者必须**核两套口径**，否则会漏判 32/32/64 这类真实错误 |
| 56.2% 的访问站点无法静态归类 | ⇒ 任何"未覆盖"结论都要带这个限定，不得当硬结论 |
| 162 个用例里 601 处 `FORKJN` 只有 158 处未注释 | ⇒ 复核时必须确认**那一行没被注释掉**（照抄时极易踩） |
| 全库 `uvm_fatal` = 0、SVA `assert` = 0 | ⇒ 断言力量全部落在自定义 `*chk()` 上，复核重点就在这些 task 的判据 |
| `TC_*` guard 错名 160/162 | ⇒ guard 不唯一不是当前故障源，但新用例必须唯一 |
