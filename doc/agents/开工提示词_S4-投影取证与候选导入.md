### 4.4 合并窗口路径：S5 + S6 同一窗口（可选，推荐）

**可以合并的理由**（为什么"一块解决"成立）：两片共用同一前置——dsh 受控准入 + 真实运行 + 凭据/预算；
**一次人工裁决就能覆盖两片**（否则第二个裁决要等 S5 证据，窗口可能已经切走）；S5 建的真机取证脚手架
（起会话/收帧/停止确认/脱敏证据/用时与 token 记账）S6 直接复用；也避免"启用 → 停用 → 再启用"的抖动。
**不能合并的理由**（为什么仍要分两次收口）：验收面不同（S5 = 只读取证，S6 = 候选写 + 对照测量）、
权限面不同（S6 要写候选，比 S5 大）、归因要求不同（S5 有缺陷时 S6 的对照数据直接无效）；
一个"大提交"会让失败无法定位、回退也不再是单片可回退。

**执行规则（照做）**：

1. **一次裁决、写清两件事**（写进计划与 STATUS，作为本轮人工裁决）：
   - A. 只读取证权限：节点（首版 N3）、DSH 版本/profile、模型、预算上限、允许工具、网络目的地、

## 7 纪律（硬约束）

1. **SpecDD**：S4 先写 SPEC-REV-16 再改代码；S5/S6 沿用既有契约，缺口登记 §未决/STATUS，不静默补实现。
2. **写权**：`kb/**` 冻结（改语义要单独变更 + 留证）；`doc/STATUS.md` 唯一数字源；证据/历史只增不改；
   `adjudication/agent_experiences.json` 由**人**写、Host 只读、**模型不得写回**；`loop/SETTINGS.yaml` 与 `loop/prompts/**`
   属 Lead/编排 owner —— 实现方不得自行改 dsh 配置或提示词语义。
3. **准入**：没有人工裁决不得把 `dsh` 接进 `select()`、不得改 `enabled`、不得改 `default_backend`；
   通过 C2 也只允许**已验证节点显式**使用（REV-14 §1/§6）。
4. **不声称**：C1（机制）≠ C2（真实内核+模型）≠ E（内网业务）；D1 的"`/proc` 可读 key"是**已接受残余风险**，
   不称已解决；压缩后的覆盖责任收缩为"Host 输入包 + 提交回传"，业务结论不得依赖未提供材料。
5. **失败显式**：`failed` + `error` + 关闭执行；超预算/源坏/越界/未审批/未知兼容版本一律**拒用并留诊断**，
   不静默降级、不截断、不把崩溃/停止未知伪装成"在等人工"（S4 的状态文案尤其不能写"在等人工"）。
6. **唯一判据**：预算仍只 `AM.check_budget`；业务校验仍只 `model_steps._validate`；闸门枚举仍只 `kb_lib.GATE_DECISIONS`；
   界面/投影只消费服务端结论（红线 8）。
7. **时间口径**：唯一入口 `--now`/`KB_NOW`；无进展告警的 `now` 由 Host 注入，测试不得用墙钟。
8. **凭据**：只用 env（`PUBLIC_API_KEY`）与受管配置；不打印 env 全集/密钥/认证头；证据 raw 必须脱敏。
9. **推送**：需人授权 + 凭据（`$HOME` 只读 ⇒ 只能临时放仓库 `.git/`，用完删；PAT 用后作废重建）。
10. **独立复核**：实现者不得同时声称独立验证；发现缺陷只报告，修复按 SpecDD 走，复核侧不修改被测文件。

## 8 已知坑（本仓实测，别再踩）

| 坑 | 事实 | 对策 |
|---|---|---|
| `.dev-ws` 路径 | provision 写 `<repo>/.dev-ws`；`cd loop` 后 `$PWD/.dev-ws` 是错的（实测 75 failed 假红） | **用绝对路径** `LOOP_WORKSPACE=/home/work/chenjunming/change-impact-loop/.dev-ws` |

| `/tmp` 跨 bash 调用不共享 | 每次调用独立临时区 | 产物一律放仓内 gitignored 路径（`loop/.logs/`、`workspaces/*/`） |
| `$HOME` 只读 | `~/.dsh`、`~/.gitconfig`、`~/.git-credentials` 都不能写 | 凭据/配置走 `.git/` 或 `workspaces/`，用 env 注入 |
| 派生副本体积大 | `.dev-ws` 733 MB / `.env-copy` 2.6 GB | 跑完 `--cleanup`；**跑文档门前必须清理** |
| 单槽 | `uvs.setup` 是环境根下全局单文件 ⇒ 同环境禁止并发仿真 | 测试只走 drill；真机取证不得并发启动同一环境 |
| 控制/指令事件只增不改 | `agent_controls/**` 是审计面（锁文件已移出到 run 根） | 新事件只追加；UI 不得把 accepted 显示成 applied |
| 半件记录 | `seal_record` 唯一发布点；半件只报状态不消费 | 新代码复用 `AM.seal_record`/`record_state`/`verify_attempt`，不要自写落盘 |
| 测试 run_id | 固定 `LOOP_NOW` 会让两次运行落进同一 `kb/runs/<run_id>`（伪造"闸门签两次"） | 每个测试唯一 run_id；conftest 已注入隔离 state |
| WM 进 request.input | 会改节点业务事实指纹（H2b `review_context_sha256`） | 机制字段必须在 `agent_review.prepare` 排除元组里；新顶层字段同理 |
| 经验 v1/v2 | v1 逐值相等必须保持；v2 有严格适用性 | 改选择路径先跑 `test_agent_experience_applicability.py` + `test_agent_context_memory.py` |
| DSH 准入 | `enabled=true` 也不会返回 DshBackend（`select()` 无条件抛） | S5 要加受控准入分支；**先拿人工裁决** |
| bwrap 只挡读、不挡 `/proc` | 宿主数据/`~/.dsh` 被遮蔽，但同 uid 可读 `/proc/<dsh-pid>/environ` 拿 key | 记为 D1 残余风险，不称已解决；证据不含 key |
| headless 事件不全 | `--json` 无 `subagent.*`/compaction；只认 sdk 通知 + session log | 观测面/记账别用 headless 输出 |
| 退出码/空文本不算成功 | SIGTERM 后 `rc=0`、`final.text=""`、无 `turn_end` | 完成判据只认 `turn_end` + `submit_result`（B5） |
| 插件加载失败只 warning | `dsh: warning: 1 entry did not activate` 不阻断启动 | 派发前必须自检工具清单 + preset 回显（DS-08/09） |
| 跨站 iframe 不可用 | 匿名 401、只能 `?token=`→`SameSite=Strict` cookie；`/api` 跨权威 403 | 走 Q7 同源反代；**反代不接受客户端传目标**；失败显式降级 |
| 反代/代理安全 | 朴素反代 = 开放代理/SSRF/凭据泄露面 | 目标来自受管元数据、只 bind loopback、拒绝路径逃逸、日志不回显 token |
| 时间不确定 | 唯一允许的非确定性必须经 `--now`/`KB_NOW` 注入 | 无进展/h耗时判据全部走注入时间；测试固定 |
