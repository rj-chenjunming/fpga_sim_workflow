### 4.3 S7c DSH Web 实例与同源反代真机（对象：`host/agent_backends/dsh*` 落账 + `services/instance_proxy.py`/`api.py` + `loop/web/**`）

**目标**：让 S4 建好的同源反代**对着真实 DSH Web 跑通**，或给出"不可用 + 原因"的决定性证据。

1. **Host 起常驻 Web 实例**：`DSH_HOME=<实例 home> node <dsh bin> --profile web --host 127.0.0.1 --port <preferred|0> --no-open`（命令与 stdout 形态见 p1p8：`dsh web: http://127.0.0.1:<port>/?token=<43 chars>`）；端口优先固定、占用回落随机、**页面/证据显示实际端口**。

3. **真机验证清单**：① 可用性端点 `ready` 且 `url` 指向正确 attempt；② iframe 加载真实页面；③ **`/api` 不 403**（同源：Origin/Referer 改写已实现，需真机确认）；④ cookie 由同源投递（`?token=` 交换后浏览器携带）；⑤ token 不出现在日志/响应/错误页；⑥ 目标缺失/上游挂了 ⇒ 显式降级块。
4. **上游绝对路径问题（必须给证据再选方案）**：先抓 `index.html` 与资源引用（`/assets`、`/api`、`/connect`…）。三选一并写清代价：

   - (b) 上游 **base path** 配置（若 0.2.1-rc.2 支持，优先）；
   - (c) **第二个 loopback 反代端口**（child origin：iframe 直接指代理根，页面内 `/api` 天然同源；但看板与实例变成跨源，cookie/脚本不可共享，需实测 `/api` 是否仍 403）。
5. **WebSocket**：若页面需要，先实测；不支持就显式 405 + 界面降级（登记 §9-2），不得静默半死。
6. **验收**：真机反代打通（或"不可用+原因"）；证据含响应头原文（`curl -D -`）、iframe 截图或 DOM 断言、token 不回显的 grep 证据；**Q5 降级线**仍可用（不可嵌时新标签页/导出会话副本）。
7. **不做**：反代不接受客户端目标（仍只读受管元数据）；不 bind 0.0.0.0；不把 Web 实例当执行通道；不因内嵌成功就改默认后端。

## 7 纪律（硬约束）

1. **SpecDD**：S7a/S7b/S7c 沿用既有契约；**改行为先改规格**（`doc/spec/**` 是 Lead 写权）；缺口登记 §未决/STATUS，不静默补实现。

## 8 已知坑（S4/S5/S6 实测新增，别再踩）

| 坑 | 事实 | 对策 |
|---|---|---|
| **dsh 应用层 `workspace-write` 边界 = cwd** | 写兄弟目录（如 `<attempt>/candidate`）会要求 `danger-full-access` 升级审批，headless `approval/decided=unavailable` ⇒ 拒写；**OS 层 `--bind` 修不了它** | 候选必须落在 **cwd 子目录**（现为 `work/candidate`）；任何"新增可写面"都要先验应用层，不只验 bwrap argv |
| **`--json` 值是 CLI 参数** | 任务文本首行以 `- ` 开头会被当成选项 ⇒ `unknown option`、boot 即死（S5 六节点前两轮全灭） | `_compose_task` 首行固定 `[task] …`；新增任务模板都要用例钉"首字符不是 `-`" |
| **bwrap `--ro-bind / /` 只挡写、不挡读** | 宿主 home 被 `--tmpfs` 遮蔽，但宿主 home 之外路径**只读可见**；`/proc/<pid>/environ` 仍可读 key | 证据只写"写隔离 + home 遮蔽"，**不写"越界读被挡"**；D1 残余不称解决 |
| **headless 事件流没有 compaction/subagent** | 压缩事实只在 session log（`session*.v4.jsonl.zstd`），事件流与 projcache 都没有 | 压缩计数只认 `dsh_sdk.read_session_log`；`session_log_ref` 用**相对 run_dir** 路径 |
| **`max-tokens` 终态不放行** | `turn_end.reason.kind=max-tokens` ⇒ 失败，不是"完成" | 完成判据仍只 `turn_end` 合法 + `submit_result` accepted |
| **模型会扫宿主 FS** | 不给工作区路径时模型 `find /` 找材料，烧光时间预算 | attempt `input/` 给足材料 + 输入里给绝对工作区路径 + prompt 明确"不要扫宿主 FS" |
| **345 KB 材料诱导反复解析** | `n5_impact.json` 全文让 N6 300 s 仍未进写候选 | 材料面瘦身/派生摘要；证据记派生来源 + md5 |
| **并发跑门 = 假红** | `test_start_honors_now` 撞 `RUN-20310101-000000`（`运行目录已存在`）；浏览器 `test_gate_option_flags_*` 并发时偶发 | 独占窗口跑门；假红要用**全新数据根单独复跑**取证后再定性 |
| **`.dev-ws` 路径** | provision 写 `<repo>/.dev-ws`；`cd loop` 后 `$PWD/.dev-ws` 是错的 | 用绝对路径 `LOOP_WORKSPACE=/home/work/chenjunming/change-impact-loop/.dev-ws` |
| **浏览器门缺 env** | 不带三组 env ⇒ 100+ errors（会被误当代码红） | 照 §6 三组 env 跑；这是独立门 |
| **`seal_record` 唯一发布点** | 半件记录只报状态不消费 | 新代码复用 `AM.seal_record`/`record_state`/`verify_attempt`，不自写落盘 |
| **测试 run_id 必须唯一** | 固定 `LOOP_NOW` 会让两次运行落进同一 run 目录（伪造"闸门签两次"） | 每个测试唯一 run_id；conftest 已注入隔离 state |
| **WM 进 request.input 会改指纹** | 影响 H2b `review_context_sha256` | 机制字段必须在 `agent_review.prepare` 排除元组里；新顶层字段同理 |
| **插件加载失败只 warning** | `dsh: warning: 1 entry did not activate` 不阻断启动 | 派发前必须自检工具清单 + preset 回显（DS-08/09）；S7b 的 allowlist 插件同样要回显 |
| **`resume` 写句柄互斥** | `already owned by an active write handle` | 人只能在两次 attempt 之间说话；attempt 进程退出后再写 |
| **单槽** | `uvs.setup` 是环境根下全局单文件 ⇒ 同环境禁止并发仿真 | 测试只走 drill；真机取证不得并发启动同一环境 |
