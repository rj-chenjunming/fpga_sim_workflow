## 5 每个切片强制流程（缺一不算完成）

0. **读规格与现状**（相关 spec + STATUS + playbook 卡），确认 owner 与唯一判据。
1. **提交「计划 + 规格」**（`docs(spec)`/`docs(plan)`）：切片、落点、不变量、验收门、环境限制；**本提交不含实测数字**。
2. **提交「红灯用例」**（`test(...)`）：先失败、贴原始输出；**禁止先实现再回退/stash 造红**。纯重构切片改为“先固定特征基线并跑绿”，在计划中注明不适用红灯。
3. **提交「实现」**（`fix(...)`/`refactor(...)`）：一次只承担一种目的；保持行为重构不得夹带契约变化。
4. **独立复核**：用 teammate 或 subagent；**只许它写 `doc/audit/<SLICE>-verify-<YYYYMMDD>.md`**，不得改被测文件、不得做 git 写；报告含命令+原始输出+结论+残余。把报告 md5 记入 STATUS。
5. **复核整改**（如有）：单独提交，逐条对应复核意见；不得为了“好看”放宽标准。
6. **STATUS 新章节**（§22 起，逐切片递增）：命令与原始输出逐字复制；通过/失败/跳过/未运行分别记录；不声称四道门全绿。
7. **门禁与回归**（见 §6）：受影响测试 + 默认根 + 软件层 + 文档门；失败集与基线对照，新增失败必须解释。

## 6 验证命令与判定

```bash
cd loop
# 受影响用例（按切片替换文件）
LOOP_LLM_MODE=standin .venv/bin/python -m pytest -q tests/<slice_tests>.py
# 默认根全套（环境只读；46 项环境失败是已知基线，不得新增失败）
LOOP_LLM_MODE=standin .venv/bin/python -m pytest -q --tb=no
# 软件层（可写影子根；期望：排除环境层后 0 failed）
bash spikes/run_software_checks.sh --tb=no
# 前端语法（改 app.js/s0.js/agent-window.js 时）
node --check web/app.js
# 文档门（只记退出码与 missing）
cd .. && python3 doc/audit/check_doc_links.py
```

判定规则：
- **默认根**：失败数/失败集不得比基线新增；新增失败必须定位（代码回归 vs 环境）。
- **软件层**：阶段 1 完成后应达到 `0 failed`（环境层被显式标记/排除，不得用 skip 冒充通过）。
- **文档门**：退出码 0、`missing=0`；不记录 `checked/skipped`。
- **kb 自测/端到端**：未运行就写未运行（附原因），**不得**用软件层结果替代。
