## 5 卡点纪律（不做就等于没做）

- **卡点 A（检索）**：没写清"基于哪个模板 / 参照哪两个用例 / 基准在哪行"⇒ 用例不予受理。
- **卡点 B（只编译）**：`./doc/tools/compile_only.sh -c <tc> -f <刚写的 .sv>` 必须打印 `[PASS] 卡点 B 通过`。
  **编译过 ≠ 功能对**；此卡点**只**证明"能编译"，任何"用例通过"的表述都是越界。
- **卡点 C（静态复核）**：由**不是作者本人**的 checker 做，逐条给**结论 + 依据（文档行号 / RTL `文件:行号` / 日志原文）**；
  必须能回答"**这条断言怎样才能失败**"，答不出来 ⇒ 判"不是探针"。
- **卡点 D（串行）**：`uvs.setup` 是**仓库根下的全局单文件**，库按 `<tc>_<seed>` 隔离
  ⇒ **同一目录并行跑两个用例会互相踩 `uvs.setup`**。跑前 `ps -ef | grep -E "uvlan|uvs"` 确认无人占用。
- **卡点 E（证据）**：每条运行证据必须含 `run_id + 时刻 + 用例名 + seed + 用例 md5 + 日志路径`。
  **不得只按 mtime 判"未改动"**（会被 checkout/reset 改掉）——必须内容 md5。

## 6 本项目三条最易踩的坑（每条都有实证）

1. **失败不带 `*E` ⇒ 回归判 OK。**
   回归脚本用 `run_uvs_new.sh:296` 的 `egrep -c '(\*E|\*F|\*e|ERROR:)'` 计数，它**看不见 `` `uvm_error ``**。
   实证：`LOG/tc_rtc_02/03/08_1_run.log` 各有 32/32/64 条真实 `UVM_ERROR`，脚本计数 **= 0**，
   `check_runsim.log` 判 `[OK] err_cnt 0`。
   ⇒ **失败路径必须"双写"**：① 打印含 `*E` 的文本；② 同时发 `` `uvm_error ``。

2. **地址不带段基址 ⇒ 同名不同址、静默打空。**
   本工程已确认 **121 个访问站点**打空：`base_addr = 32'hf00`（65 站，照抄了文档段头 `Offset：0x0F00` 的**笔误**，
   正确是 `0x800`）、`base_addr = 32'h200`（56 站，文档 BAR0 总表根本没有该段）、
   `tc_dom_polling_01[_2]` 硬编码 `32'h6000`（24 站，DOM 只实现 `0x4000~0x5FFF`）。
   **打空不报错**，只读到 `0xffffffff` 或写后读不回。
   ⇒ 地址一律写 **`<段基址> + <块内偏移>`**，并在注释里标明"这是哪个块的哪个寄存器"。

3. **走错驱动通道 ⇒ 静默失效只读到复位值。**
   实证：`TB/tbtop.sv:184-193` 里 `cplda_spi_s_*` 是**空连接**、`cpldb_spi_s_*` **整段被注释**
   ⇒ 只有 `SPI_MST(2)`（BMC SPI）真正可达；`spi_slave.v:309-310` 的地址门控
   `s_address <= {REG_ADDR_BYTE_NUM{8'hff}}` 因位宽匹配而**恒真**（门控形同虚设）。
   另有 25 处（去重后约 20 处）"只能由 CPU/BMC 接口访问"的标注，**走错通道时不报错**。

> 另附两条同等重要：**① 预期值只认位定义表，绝不迁就 RTL**（`0x4e/0x7c/0x7c` 这类复位值汇总表写错、
> 位定义表才对）；**② 每个"等"都要有超时兜底**——本环境未传 `+UVM_TIMEOUT=`，全局超时不生效。

## 7 红线（绝不违反，全文见 `doc/AGENTS.md` §5）

`RTL/`、`PKG/` 严格只读；`TB/` 默认只读；预期值以位定义表为准**绝不迁就 RTL**；

同一目录禁止并发跑用例；`uvm_hdl_force` 必须成对 release + 检查返回值；
不得为了 PASS 改断言；**报告里的数字一律由命令输出复制，禁手算**。
