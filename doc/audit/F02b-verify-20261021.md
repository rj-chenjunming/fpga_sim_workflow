## 2 唯一判据：detail 直接取 `BaselineInvalid.details`

实现（[api.py:196–208](../../loop/services/api.py#L196-L208)）：

```python
except ValueError as exc:
    from host.baseline import BaselineInvalid

    if isinstance(exc, BaselineInvalid):
        # 结构化拒绝（Web UI §9）：missing/errors 直接取判据（唯一来源），不在 API 层二次推导。
        details = exc.details
        raise HTTPException(status_code=400, detail={
            "error": str(exc),
            "baseline": exc.baseline_id,
            "missing": list(details.get("missing") or []),
            "errors": list(details.get("errors") or []),
        }) from exc
    raise HTTPException(status_code=400, detail={"error": str(exc)}) from exc
```

`BaselineInvalid.details` 来自 [baseline.py:44–52](../../loop/host/baseline.py#L44-L52)（`require` 在 [baseline.py:245–250](../../loop/host/baseline.py#L245-L250) 把 `inspect` 的整条 record 传入），判据实现只有 `host/baseline.py` 一处。API 只做 `list(... or [])` 归一化投影，**没有**重新扫描基线、没有拼字符串推导、没有第二套判据。

实测等同性（同一临时工作区分别走 API 与 `host.baseline.inspect`）：

```
v99 detail.missing == inspect.missing: True
v99 detail.errors  == inspect.errors : True
v99 detail.baseline: v99 | valid: False
v9 detail.missing == inspect.missing: True
v9 detail.errors  == inspect.errors : True
v9 detail.baseline: v9 | valid: False
```

**错误文本是否可能误导**：文本不误导（内容同源、无相反陈述），但 UI 端有冗余展示，见 §7 建议 1。`detail.error` 本身是 `BaselineInvalid.__str__` 的拼接摘要（[baseline.py:50–52](../../loop/host/baseline.py#L50-L52)），已包含全部 `missing`+`errors`；前端又追加格式化后的 `missing/errors`，造成同一原因出现两次。

## 3 前端

### 3.1 `errText` 只在 `detail` 为对象时追加

代码（[app.js:176–195](../../loop/web/app.js#L176-L195)）：`errDetailText` 先判 `if (!d || typeof d !== "object") return ""`，再分别用 `Array.isArray(d.missing) / Array.isArray(d.errors)` 且非空才拼装。用 Node 把这两个函数从**未修改的** `web/app.js` 原文抽出复算（脚本仓外）：

```
baseline detail (missing+errors) => "/api/runs → 基线 'v9' 未通过准入：x（缺件：a、b；违规：e1、e2、e3）"
only error object (non-baseline) => "/api/runs → mode 必须是 drill 或 real"
detail is string => "/api/runs → Error"
body null (network) => "/api/runs → Error"
detail null => "/api/runs → Error"
missing only => "/api/runs → x（缺件：a）"
```

说明：`detail is string`/`body null` 两行显示 `Error` 是探针造 `Error` 时未按真实 `api()` 填 message 的假象——真实 `api()`（[app.js:228–237](../../loop/web/app.js#L228-L237)）对字符串 detail 会把 `detail` 本身作为 message。关键结论成立：只有「对象 detail 且 `missing/errors` 为非空数组」才追加；字符串/null/只有 error 的对象都不追加。

### 3.2 XSS 面

`h()` 用 `textContent`（[app.js:135–140](../../loop/web/app.js#L135-L140)），`chipEl` 经 `h()`（[app.js:172–174](../../loop/web/app.js#L172-L174)），启动失败提示与目录选择器都经 `h(...)` 渲染（[app.js:687](../../loop/web/app.js#L687)、[app.js:2355](../../loop/web/app.js#L2355)）。全文件检索 `innerHTML|insertAdjacentHTML|outerHTML` 只有文件头注释一处命中（声明「不拼 innerHTML」），无实际写入。服务端下发的 `missing/errors` 被 `join` 成字符串后走 `textContent`，不构成 XSS。
