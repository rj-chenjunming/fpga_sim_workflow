### M2（阻断「口径唯一」）`_env_roots()` 是 §1 根解析的第二份实现，三处与 `kb_lib` 漂移

规格 §1 明文：「解析优先级（单一实现 `kb/tools/kb_lib.py::_resolve_env_root` / `_resolve_workspace_root`，**不许两套**）」；

- **A**：旧布局（`TOOL_ROOT/TESTLIB/` 存在、无注册表）下 `kb_lib` 解析出 `ENV_ROOT=TOOL_ROOT`、`WORKSPACE=TOOL_ROOT/kb`，
  检查器却是 `None/None`，把**真实存在**的 `kb/runs/<RUN>/view.json` 判成 `missing`、退出码 1（§1 第 4 条向后兼容回落丢失）。
- **B**：注册表有多个环境且 `LOOP_ENV=envB` 时，`kb_lib` 用 envB，检查器忽略 `LOOP_ENV`、固定用 `default`（envA），
  文档门校验的是**另一个环境**。
- **C**：注册表坏掉时 `kb_lib` fail closed 抛错；检查器吞异常后把「根不可知」表现为「环境缺件」（`env_missing`，退出码 0），
  即**失败被伪装成通过**，违反 AGENTS §2 硬性纪律 3 与 §1 第 5 条。带一条 env 资产引用的复现：


  （此例同时含数据根引用才会退出 1；若文档只引用环境资产，退出码为 0 —— 即坏注册表下文档门会**绿**。）

- **修复建议**：照 `loop/host/paths.py` 的方式复用 `kb_lib`（`sys.dont_write_bytecode` 守卫加载，冻结目录不写 `.pyc`），
  或把纯解析函数下沉为 `kb_lib` 的公开 API 再调用；根不可确定时**显式报错并退出非 0**，不要 `except: pass`；
  同步补「旧布局 / `LOOP_ENV` / 坏注册表」三条用例。
- **继承性说明**：`_env_roots()` 在旧实现（`407cfab` 第 63–74 行）就是这段逻辑，**非本提交新增**；但本提交在
  docstring 里声明「与 §1/§4.2 同口径，**唯一实现**」，该声明目前不成立，属于本次复核必须点名的口径问题。
