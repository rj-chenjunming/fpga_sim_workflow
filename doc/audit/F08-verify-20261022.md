## 1 结论

**不建议以现状合并；修掉 M1（符号链接回归）后可合并。** 其余为建议项。

成立的部分（均有原始输出，见 §3–§10）：

1. `AM.record_state` 四态语义正确，且**只读**：连续调用前后内容、mtime、mode、目录项完全不变。
2. `read_view` 对半写记录**不再整体抛错**：该尝试摘要标状态、不进 `records`、不被消费，其它
   committed 尝试照常可读（实测 attempt-1 仍被选中、request/result 可读）。
3. `corrupt`（篡改校验）仍是**显式失败**，未被静默降级；API 侧对应 422（[api.py:294](../../loop/services/api.py#L294)）。
4. 故障注入是**真实子进程**（`subprocess.run(subprocess.Popen)` + `os._exit(9)` / `SIGKILL`），不是内存模拟。
5. 新尝试序号只增不复用：空目录 `attempt-000002` 存在时，下一次分配为 `attempt-000003`。
6. `agent_control` 不再引用私有 `AM._sealed`（`_seal = AM.seal_record`），全仓无跨模块私有调用。
7. 记录格式未变：HEAD 写→基线读、基线写→HEAD 读都通过 `verify_attempt` 与 `read_view`。
8. 默认根失败集**逐条相同**（46 条，HEAD vs 基线 `6c4ee6e`，`diff` 为空）；`792bb48` 上
   `76 passed`、`46 failed, 402 passed, 3 skipped` 与提交信息逐字一致。

**阻断项 M1**：`read_view` 在 `record_state` 之前不再对记录文件做 `_safe()` 符号链接检查。基线对
`request.json` 是符号链接会 `ValueError: Agent 记录路径越界或使用符号链接`；现在只要该文件处于
`absent/incomplete`，就静默返回 `status: incomplete`（并且 `record_state` 已读过外部目标文件做哈希）。
规格明文要求「符号链接**显式失败**（安全信号，不得静默降级成普通状态）」，这是相对基线的契约回归。

## 3 四态语义与只读性

实现（[agent_memory.py:124](../../loop/host/agent_memory.py#L124)）按文件返回：`is_file()` 否 → `absent`；
`.sha256` 缺 → `incomplete`；读失败 `OSError` → `incomplete`；哈希不符 / JSON 不可解析 → `corrupt`；
否则 `committed`。函数只 `read_bytes`/`read_text`，无写、无删除。

实测（本机 HEAD）：

```
attempt-1: request=committed result=committed
attempt-2: request=absent    result=absent      # 空 attempt 目录
attempt-3: request=incomplete result=absent     # request 数据在、校验缺
attempt-4: request=committed result=incomplete  # request 完整、result 数据在、校验缺
0-byte request.sha256 -> corrupt
readonly_unchanged: True
```

只读性判据：对 committed 的 `request.json` 连续调用 `record_state` 3 次，比对
`(内容字节, st_mtime_ns, st_mode, 目录项列表)` 前后一致 = `True`。未检查 atime（读取本身可能更新
atime，属内核行为，不影响「不修改文件内容/结构」的结论）；`corrupt/incomplete` 分支同样只读（代码核对）。

## 6 故障注入真实性

`tests/test_f08_sealed.py` 用的是真实子进程，不是内存模拟：

- [test_f08_sealed.py:58](../../loop/tests/test_f08_sealed.py#L58) `subprocess.run([sys.executable, "-c", ...])`，
  子进程 `AM._write_once(request.json)` 后 `os._exit(9)`；父进程断言 `returncode == 9` 且
  `request.json` 在、`.sha256` 不在。**确定性覆盖矩阵第 3 行。**
- [test_f08_sealed.py:97](../../loop/tests/test_f08_sealed.py#L97) `subprocess.Popen` + `time.sleep(0.35)` +
  `send_signal(SIGKILL)`，循环写 2000 个 attempt。
- `corrupt` 用真实篡改 `.sha256`（chmod 后写 64 个 `0`）。

**但 SIGKILL 用例的断言是空的**：循环里 `summary["status"]` 只可能是 `validated`（完成）或
`record_state` 值，永远不会是 `"committed"`，所以
`if summary["status"] == "committed" or ...: assert summary["status"] == "validated"` 只对
`validated` 恒真；它也没有断言「确实产生了半写记录」。我按同一脚本复现 3 次：

```
trial 0: rc=-9 attempts=268 states=['committed', 'committed', 'committed', 'committed'] incomplete=0 corrupt=0 committed=268 absent=0
trial 1: rc=-9 attempts=242 states=['committed', 'committed', 'committed', 'committed'] incomplete=0 corrupt=0 committed=242 absent=0
trial 2: rc=-9 attempts=272 states=['committed', 'committed', 'committed', 'committed'] incomplete=0 corrupt=0 committed=272 absent=0
```

0.35 s 内子进程已发布 242–272 个完整尝试，SIGKILL 几乎总落在两次发布之间 ⇒ 该用例实际**没有**
命中发布边界，只证明了「不存在可消费的半写」（这本来就由 `_write_once` 的 O_EXCL 保证）。
建议：让子进程在写完数据后 sleep/等父进程信号再写校验（确定性卡边界），或循环 kill 直到观测到
`incomplete` 再断言；并把断言改成「不存在 `records` 消费」+「至少一个 `incomplete`/`absent` 目录」。

## 11 必改 / 建议

| 编号 | 级别 | 内容 | 证据 |
|---|---|---|---|
| **M1** | **必改（阻断）** | 符号链接记录文件不再显式失败：`record_state` 在 `_safe()` 之前读文件；`absent/incomplete` 时 `read_view` 静默返回摘要，基线是 `ValueError`。规格要求「符号链接显式失败」。修法：对 `request_file`/`result_file` 先 `_safe(root, file)`（或在 `record_state` 内拒绝 `is_symlink()`） | §4.1 第 8 行、§5 #8、基线 §4.2 对照 |

| S1 | 建议 | `.sha256` 0 字节/半截（SIGKILL 落在 open 与 write 之间）判为 `corrupt` ⇒ 整节点 422，**同节点其它 committed 尝试也不可读**；矩阵未覆盖该点。若按「校验缺」处理会更符合「半写不整体失败」的目标（能否区分与篡改需规格明确） | §5 #7、§3 |
