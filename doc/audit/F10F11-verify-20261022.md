## 2 必改项

### 必改 1（代码，阻断本切片验收）：预算区块把嵌套 `input` 当成 `request` 传入，真实记录下预算构成恒为空、合计恒为 0 B

- **事实**：
  - 模块判据按 `request` 顶层字段统计：`FIELDS = ["input", "info", "instruct", "schema", "offered", "scope"]`（[`context-explain.js:14`](../../loop/web/context-explain.js#L14)），`budget(request, limitBytes)` 对 `request` 做 `hasOwnProperty`（[`context-explain.js:38`](../../loop/web/context-explain.js#L38)）。
  - 记录写入时这些字段就在顶层：`AM.Attempt(ctx, node, {"prompt_key": ..., "input": request_input, **contract, "offered": offered, "scope": scope, ...})`（[`model_request.py:124-132`](../../loop/workflows/chunks/model_request.py#L124-L132)）。
  - 窗口只传内层：`var b = X.budget(request.input || {}, limit);`（[`agent-window.js:127`](../../loop/web/agent-window.js#L127)）。真实 `input` 的键是 `diffs`/`human_interventions`/… 等业务键，不在 `FIELDS` 里。
- **实测**（§4.6 原始输出）：窗口现状 `{"rows":[],"totalBytes":0,"limitBytes":120000,"usage":"known","usedPercent":0}`；按规格传整条 `request` 得到 `[["input",89],["info",8],["instruct",8],["schema",17],["offered",18],["scope",29]]`。
- **用户可见后果**：折叠块显示「合计: 0 B / 上限: 120000 B · 使用率: 0%」，摘要显示「0 B / 120000 B」。对一个刚通过 Host 预算闸门的请求，这会被读成「没占预算」，反而制造误解；规格「预算构成」条目等于未实现。
- **修复建议**：改为 `X.budget(request, limit)`（或显式构造 `{input: request.input, info: request.info, instruct: request.instruct, schema: request.schema, offered: request.offered, scope: request.scope}`）；更稳的做法是把「记录 → 预算行」下沉为纯函数 `budgetFromRecord(request, limit)` 并让窗口只做渲染，这样 node 用例可以直接用记录形状覆盖。修复后补一条按记录形状的断言（`rows.length > 0`、`totalBytes > 0`、行标签等于六字段的子集），避免同类实参错位再次漏过。
- **复验门**：`node --check web/context-explain.js web/agent-window.js` + 定向 3 文件 + 新增记录形状用例；无需改 Host/API/记录。

> 说明：以上只列 1 项代码层必改。若 Lead 认为「预算区块不可用」可以接受、先合入再修，则本切片只能算「UI 骨架」；但按计划 §2 目标 1 与规格第 1 条，本报告仍按不建议合并处理。

## 3 建议项

- **B1（展示失败隔离，对应检查 f）**：`explain(view)`（[`agent-window.js:115`](../../loop/web/agent-window.js#L115)）没有 try/catch，且调用点（`:53`）在 `awStatus`/attempt 下拉/输入/输出/时间线之前；一旦展示层抛异常，`load()` 的 catch（`:104-106`）会把 `data=null` 并把状态置「读取失败」，基本观察状态一起丢失。建议：给 `explain` 包 try/catch（失败时在预算/差异区块写「解释不可用」），或把调用移到基本状态渲染之后。目前所有输入都来自 JSON，实际抛错路径很窄，故按建议处理，不作为必改。
- **B2（口径提示，红线 8）**：修完 A1 后，窗口会显示 `usedPercent = 六字段 JSON 字节和 / MAX_CONTEXT_BYTES`；Host 的闸门判据是 `len(encoded({"input": request_input, **contract}))`（`agent_memory.py:97-99`），**含** JSON 结构与键开销、**不含** `offered`/`scope`。两者不是同一个数，直接标「使用率」有被读成同一判据的风险。建议把文案标成「字段字节合计 / 上限（不含序列化开销；闸门判据以 Host `check_budget` 为准）」，或让 Host 下发自己实测的 size（新增 API 字段需走 SpecDD，不在本切片）。
- **B3（测试缺口，对应检查 d）**：`previous_input` 没有任何用例。建议补：两次 committed 尝试时第 2 次取第 1 次 `input`；首个尝试返回 `None`；F08 `incomplete` 的更早尝试被跳过；`attempt=N` 时只与 `<N` 比较；corrupt 仍 422（既有 F08 语义）。这些不需要浏览器，直接 `C.read_view` 即可。
- **B4（文档对齐）**：计划 §2.1 写「input/prompt/info/instruct/schema」，规格写「input/info/instruct/schema 等」，实现是 `input/info/instruct/schema/offered/scope`（无 `prompt`，有 `offered`/`scope`）。建议把计划按规格改成同一字段清单（`prompt_key` 是否计入另说），避免下一轮按计划补出第二套清单。
- **B5（重置与文案）**：`reset()` 把 `awBudget`/`awAttempts` 置「读取中…」，但没有重置 `awBudgetSummary`（[`agent-window.js:169`](../../loop/web/agent-window.js#L169) 附近），切换节点时可能短暂显示上一节点的摘要；另窗口把 token 文案写死为「未知（未测量）」，未消费 `b.tokenEstimate`，模块将来若真接入估算会与 UI 脱节。均为一两行改动。

```python
    return {'run_id': Path(root).name, 'node': node, 'live': live_view(root, node),
            'attempts': summaries, 'selected_attempt': selected, 'request': request, 'result': result,
            'previous_input': previous_input,
            ...
```
