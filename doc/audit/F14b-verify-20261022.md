## 4 方法（为什么不用工作树）

验证开始时 `git status` 已显示 `M doc/plans/2026-10-22-R-block-execution.md`；验证过程中并行实现 owner 又提交了 `b832525` 并把工作树 `loop/web/app.css` 改成 `1eea23b5…`（≠ `70c4cfb` 的 `c28277ec…`）。所以：

```bash
# 全部在仓库内隐藏临时目录完成，验证后删除
W=$PWD/.f14b-verify-tmp
git archive 837d2aa~1 loop/web | tar -x -C $W/before
git archive 70c4cfb   loop/web | tar -x -C $W/after
git archive 70c4cfb   doc/evidence/R_BLOCK_C_20261022 | tar -x -C $W/ev
cd loop && mkdir -p $W/home && \
  HOME=$W/home XDG_CONFIG_HOME=$W/home/.config XDG_CACHE_HOME=$W/home/.cache \
  LOOP_BROWSER_EXECUTABLE=/usr/bin/google-chrome \
  .venv/bin/python $W/ev/doc/evidence/R_BLOCK_C_20261022/verify_style_equivalence.py \
    --before-web $W/before/loop/web --after-web $W/after/loop/web
```

`--help` 与源码确认：`--before-web`/`--after-web` 必填/默认、退出码 0=等价 1=差异 2=采集失败；脚本只读（两个 127.0.0.1 静态服务 + `collect_f14a.MockApi` 受控替身，不写文件）。
