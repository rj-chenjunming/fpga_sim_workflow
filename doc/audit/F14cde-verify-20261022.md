## 3 方法与口径

### 3.1 解析口径

不用 `doc/evidence/R_BLOCK_C_20261022/css_convergence.py`（它是实现方的删除工具，复用其解析器会让"删除理由"与"验证判据"同源）。本报告用**自写的只读探针**（`prove.py`，约 200 行，仅标准库），把 CSS 摊平成**有序声明 token 序列**：

- `ctx`：从根到该规则的 at-rule 前导**有序元组**（`@media`/`@supports`/`@layer`/`@container`/`@keyframes`），逐字规范化空白。
- `sel`：规则选择器列表按顶层 `,` 拆分后的**单个选择器**（规范化空白与 `> + ~` 两侧空格）。**选择器列表形式的规则按单选择器逐一展开**，一条源码声明在 N 个选择器下算 N 个 token。
- `prop`（小写）、`value`（规范化空白，保留 `!important` 前的原文）、`important`（布尔）、`line`（源文件行号，注释按字符替换为空格、保留换行，故行号精确）。
- **整规则删除不跳过内部声明**：解析器先把规则体内每条声明展开成 token，再算差集，所以被整条删掉的规则内部声明同样逐条进入证明。

**差集计算**：父/子 token 序列做 `difflib.SequenceMatcher`（`autojunk=False`），`delete`/`replace` 段的父侧 token 即"被删声明"（重复声明的具体出现由序列比对确定），`insert` 段的子侧 token 即"新增声明"。

### 3.2 支配定义

对每条被删声明 `d`（父文件下标 `i`，上下文 `Cd`），在**存活**声明中寻找 `j > i`：

| 类别 | 条件 | 语义 |
|---|---|---|
| **D1 同值后置支配** | `sel_j == sel_d`（规范化文本相同 ⇒ **特异性必然相等**）、`prop_j == prop_d`、`important_j == important_d`、`Cj` 是 `Cd` 的**前缀**（⇒ `Cj` 生效时 `Cd` 必然生效，即"同上下文或更宽/无条件"）、`value_j == value_d` | `d` 永远不是层叠胜者，且胜者与胜出值都不变 |
| **D2 后置同键（值不同）** | 同 D1 但 `value_j != value_d` | `d` 在父文件里**本来就不是胜者**（`j` 更靠后、同样适用），改动后胜者仍是存活的 `j`，计算值不变 |
| **D3 前值等价** | `d` 之后**没有**同键存活声明，但 `d` 之前最近的一条 `Cd`-适用同键声明存活且同值同重要性 | 计算值由该前一条提供，值不变（不满足"后置"形态但可证等价；本三切片为 0） |
| **BLOCK** | 以上都不成立 | 该键在 `Cd` 下可能换值 ⇒ **阻断项**，必须逐条列出 |

**为什么 D2 也算"完全覆盖"**：F14-b 的判据是"被后续同选择器、同属性、同重要性的声明覆盖"，**不要求同值**。层叠里两条同选择器同属性声明之间只由源顺序决定胜负，后置者恒定胜出；被删的那条因此从未参与渲染。反过来，如果被删声明是它那个键的**最后**一条（D3/BLOCK 区间），删掉它就会让更早的值"浮上来"，那才是真实的行为改变——本报告对这类情况一律判 BLOCK 并逐条列出。

**与上一份复核报告的口径一致**：D2 正是 [F14b-verify](F14b-verify-20261022.md) §6 抽查第 3 行用的判据（"值不同但同选择器更后 ⇒ 改前它就是输家，删除不改赢家"）。本报告只是把它形式化并**全量**套用，并额外把"同值"单列为 D1（29 条），让读者一眼看到哪些删除是逐字同值、哪些是靠后置层换值。两份报告的结论因此可比（都以"单选择器展开后的删除声明"为计数单位）：A/A2/B 为 140/140、C/D/E 为 274/274，未匹配均为 0；两边数字不相加（见 §4 累计段的口径说明）。

**最小判据（伪代码，任何独立实现按此应得同一结论）**

```
tokens = [(ctx, sel, prop, value, important, pos)]   # 按文件顺序摊平，选择器列表已拆成单选择器
del, ins = sequence_diff(tokens_parent, tokens_child)  # difflib；del 为父侧未匹配下标
survive  = [j for j in range(len(parent)) if j not in del]
for i in del:
    d = parent[i]
    later = [j for j in survive if j > i
             and parent[j].sel == d.sel and parent[j].prop == d.prop
             and parent[j].important == d.important
             and is_prefix(parent[j].ctx, d.ctx)]        # 支配者生效 => d 生效
    same  = [j for j in later if parent[j].value == d.value]
    kind  = 'D1' if same else ('D2' if later else check_D3_or_BLOCK(i))
# BLOCK 必须逐条列出；C/D/E 结果：D1=15/12/2 · D2=97/80/68 · BLOCK=0
```

**媒体条件的处理是保守的**：`Cj` 是 `Cd` 的前缀这一关系只依赖语法的嵌套结构，**不依赖对 `@media` 表达式的真值求解**（不判断 760/1000/`prefers-reduced-motion` 在某个宽度是否为真）。因为证明只需要"凡 `Cd` 生效处 `Cj` 也生效"，而前缀关系恰好给出这一蕴含，与条件的实际真值无关。这比按宽度枚举更严密（也规避了 v1 工具只测 139 个（宽度,状态）采样点的问题）。

2. 未改内联样式/JS/HTML（本报告 §2 已核对改动面）；
