## 2 语义一致：C1 的 `coverage.complete` 与实现

- **C1 定义**（`doc/spec/AGENT_CONTEXT_SPEC.md:28-30`）：`complete=true` 仅表示**该件的全部变更区域都已提供**（`full_file`=全文；`changed_regions`=所有变更组都已包含，只省略无关上下文）；不是「已做全文复核」的证明；存在未提供的变更组时不得置 true。
- **实现**（`loop/workflows/chunks/model_steps.py:1279-1295`）：`coverage = {mode, complete: True, scope: full_file|all_changed_regions, regions}`；`changed_regions` 模式下 `excerpt` 由**全部** `get_grouped_opcodes` 组拼成（第 1237–1253 行），`regions` = 全部组数。因为所有变更组始终都被提供，`complete=True` 与 C1 定义**一致**，不存在「声明 true 却漏组」的路径。
- **误读风险仍在（不是实现 bug，是字段/提示词问题）**：`complete` 在当前实现里**恒为 true**，无任何区分力；真正的「片段/全文」信号只有 `mode`/`scope`。N8 提示词只解释了 `mode`（`loop/prompts/loop_nodes.yaml:52`：「coverage.mode=changed_regions 表示该文件只提供了变更片段……不得据此声称做过全文复核」），**完全没解释 `complete`**。一个只看 `complete` 的消费者仍可能把它读成「全文已复核」。建议二选一：在 N8 规则里补一句 complete 语义，或让该字段在不成立时有真实取值（当前永远 true，等于摆设）。
- `coverage_summary` 的 `full_files/region_files/used_bytes/budget_bytes` 与逐件 `coverage` 自洽（§1.3 实测 0 全文 / 5 片段 / 50746 字节）。
