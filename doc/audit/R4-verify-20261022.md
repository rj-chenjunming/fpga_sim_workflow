### 4.2 独立复算「全文 vs 片段」成本（不读被测源码内部，只按文档化片段格式构造）

自建脚本对同一夹具分别调用父树/修复树的公开入口，并用**文档化片段格式**（`// lines a-b\n` + after
上下文文本、`changed_regions`/`coverage` 同名换值）独立构造片段条目：

```
tree=parent files=86 full_total=59341
tree=parent groups_per_file=1 region_total_independent=61835 delta=2494
tree=parent default_budget_call=RuntimeError 'N8 上下文预算不足：分片后 61835 > 60000 bytes（…）'
tree=parent budget=region_total(61835) -> used=61835 modes=['changed_regions']
tree=head   files=86 full_total=59341
tree=head   groups_per_file=1 region_total_independent=61835 delta=2494
tree=head   default_budget_call=SUCCESS
tree=head   budget=region_total(61835) -> used=59341 modes=['full_file']
```

- 独立构造的片段总字节 **61835** 与父树真实报错数字**逐字节一致**，说明该构造可代表真实片段条目。
- 父树只有在预算放宽到 61835 时才能产出（`used=61835`，全部片段）；修复树即使给 61835 也选
  59341 的全文（更便宜、信息更多）。
- 与 `doc/STATUS.md` §38.2 登记的 `full_bytes=59341, budget=60000, actual=61835 > 60000` 一致；
  本报告不改 STATUS，仅引用同一原始数字。

## 5 独立复算：工作区内临时夹具（不依赖被测测试文件，用后删除）

探针位于工作区临时目录（用后删除），只 import 被测公开入口 `build_sandbox_cases` 与 `AM.encoded`；
`CHECKS` 为断言数，`FAILS` 为失败数：

```
$ PYTHONPATH=…/loop LOOP_STATE_ROOT=…/.r4v/state loop/.venv/bin/python .r4v/probe_r4.py
one: files=6 full_total=4141
mixed: full_total=5926 oracle_min=3929 min_costs={'aa_all.sv': 691, 'bb_single.sv': 1452,
       'cc_cn.sv': 1289, 'dd_escape.sv': 492} full_costs={'aa_all.sv': 691, 'bb_single.sv': 2573,
       'cc_cn.sv': 1998, 'dd_escape.sv': 659}
mixed: budget_scan=[3889,4048] false_reject=[]
tie_fixture: {'pad': 16, 'groups': [(2, 8, 2, 8)], 'full_cost': 701, 'region_cost': 701}
CHECKS=940 FAILS=0
EXIT=0
```

探针覆盖（每条都独立构造夹具，不复用仓库测试）：

1. **全文可行而片段更大 ⇒ 选全文**：6 件、每件 20 行全部变更；独立确认片段（定位头 + 全部 after 文本 +
   更大的 `coverage.scope`）**大于**全文；`full_total=4141`；预算恰为 4141 时全部 `full_file`、
   `used_bytes=4141`、输出字节与无限预算调用完全相同；预算 4140 时显式失败且消息含 `4141 > 4140` 与
   逐件 `file(cost)`。
2. **只有最小成本和超限才拒绝 / 不误拒**：混合夹具（全行变更 / 单行变更 / 中文 / 转义 / 多文件）先用
   真实输出捕获片段条目，按 `n+1 + Σmin(全文,片段)` 独立算出 `oracle_min=3929`；对
   `budget ∈ [3889,4048]` 逐字节扫描：`>= 3929` 全部成功、无丢件、`used==len(AM.encoded(files))<=budget`，
   `< 3929` 全部显式 `RuntimeError`，无一次 false reject / false accept。预算恰为 3929 时
   `used_bytes=3929` 用满，逐件 `coverage` 与实发一致（`excerpt` 含全部区域文本、`changed_regions`
   区间 == difflib 分组、`md5`/`source_md5` 与文件内容一致、`full_files`/`region_files` 与模式计数一致）。
3. **全部候选超限仍显式失败、含逐件成本、不丢文件**：预算 3928 时消息为
   `全部候选件的最小可行成本合计仍需 3929 > 3928 bytes`，逐件 `aa_all.sv(691)`、`bb_single.sv(1452)`、
   `cc_cn.sv(1289)`、`dd_escape.sv(492)` 全部出现；无返回、无抽样。
4. **降级只在成本确实下降时发生**：扫描中所有 `changed_regions` 件的条目成本均 `<` 其全文本成本
   （如 `bb_single.sv` 1452 < 2573）。
5. **确定性**：同一输入两次调用 `AM.encoded` 字节相等、`summary` 相等、文件名/顺序相等；默认预算
   60000 与紧预算 3929 各验一次。
6. **并列成本（全文 == 片段）选全文**：独立构造到严格相等（`full_cost=region_cost=701`），
   数组总成本 703（条目 701 + 数组标点 2）时输出 `full_file`，预算 702 时显式失败（`703 > 702`）。
7. **受限大文件规则未被解除**：>6000 字符文件即使预算 10^7 仍 `changed_regions`，小文件仍 `full_file`；
   大文件缺源时显式失败并点名文件。
8. **常量未变**：`N8_SANDBOX_BUDGET_BYTES=60000`、`N8_FULL_FILE_CHARS=6000`、
   `N8_REGION_CONTEXT_LINES=6`。

## 8 实现细节复核（逐条读代码）

1. **成本口径**：`full_cost = len(AM.encoded(full_entry))`，`region_cost` 同理；条目含
   `file/md5/excerpt/source_md5/changed_regions/coverage{mode,complete,scope,regions}`，
   因此 coverage 与 changed_regions 的全部键名/标点都进入成本。无任何近似常量。
2. **可行成本与强制片段**：`forced_region = len(text) > 6000`（字符数，沿用既有语义）；
   强制件 `min_cost = region_cost`，且无片段时在算成本前 fail-closed；非强制件
   `min_cost = min(full, region)`（无片段时只有全文）。
3. **确定性顺序 + 预留**：`files = sorted(glob("*.sv"))`；对第 `i` 件判断
   `used + full_cost_i + Σ_{j>i} min_cost_j <= budget` 才用全文；`used` 初值含数组开销 `n+1`。
4. **只有最小成本和超限才拒绝**：`total_min = n+1 + Σ min_cost`；`total_min > budget` 才抛错，消息逐件
   `name(min_cost)`。选择循环中对每件「是否可全文」都预留了后续件的最小可行成本，因此不会被贪心吃光预算
   后误拒剩余件（本报告用 160 个预算值扫描验证，无 false reject）。
5. **并列成本**：当 `full_cost == region_cost` 时，`can_full` 成立即选全文（探针构造 701==701 验证）。
6. **最终复核**：选择完成后用 `len(AM.encoded(out))` 复核；兜底降级只在 `region_cost < full_cost` 时发生，
   不会把全文换成更大的片段；仍超限才抛错。
7. **覆盖一致性**：`_entry` 的 `coverage.complete=True` 仅表示「全部变更组已提供」——
   `full_file` 给全文；`changed_regions` 的 `excerpt` 由每组的 after 文本 + 行号头拼成，
   `regions` 计数与 `changed_regions` 同源，未提供组时不会出现 `complete=True`。
8. **汇总**：`summary = {budget_bytes, used_bytes(实际 AM.encoded(out)), full_files, region_files}`；
   计数在兜底降级分支同步递减/递增。

## 9 问题（均非阻断，P3 建议）

1. **两处不可达防御分支的消息信息量偏低**（低）：选择循环内 `entry is None or cost is None` 分支
   （[L798-805](../../loop/workflows/chunks/model_steps.py#L798-L805)）与兜底后仍超限分支
   （[L828-832](../../loop/workflows/chunks/model_steps.py#L828-L832)）只给文件名/剩余预算，未给逐件成本。
   按当前成本定义与预算不变量这两个分支不可达（本报告已证并扫描验证）；保留作为兜底合理，但若未来成本
   口径变化导致可达，排查信息不足。
2. **数组开销 `n+1` 为手工推导**（低）：`AM.encoded(list)` 对紧凑 JSON 数组确为
   `Σ条目 + n + 1`（探针在 ASCII/中文/转义/多文件条目上逐字节验证）。它依赖 `json.dumps(...,
   separators=(",", ":"))` 的格式；若 Host 计费序列化未来改变分隔符，`array_overhead` 与提前拒绝的算术会
   整体漂移（最终 `used` 仍由 `AM.encoded(out)` 复核）。建议后续从 `AM.encoded` 派生数组开销，
   而不是写常量式 `len(plans) + 1`。
3. **拒绝消息的「逐件成本之和」与打印总数差 `n+1`**（低）：总数 `total_min` 含数组标点，逐件列表是条目成本；
   直接相加会少 `n+1`。可接受（总数才是真实序列化字节），但排查时易误读。
4. **仓内缺严格并列成本用例**（低）：R4-A 的「临界相等」仓内由
   `test_budget_equal_to_real_min_total_is_feasible`（预算 == 最小成本和）覆盖；「全文成本 == 片段成本」的
   并列未落用例。本报告已独立构造并验证并列选全文（§5 项 6），建议后续补一条回归用例。
5. **N8 分片预算的计量范围**（说明，非缺陷）：60000 只约束 `sandbox_cases` 数组；
   `revision_points`/`applied_edits`/`checklist`/`rework_reasons` 仍受 120000 整请求预算守门。
   这是既有契约，R4 未改变；若希望 N8 分片预算覆盖全部 N8 输入，需另立契约。
6. **相邻风险（超出 R4）**：沙箱中多于 `applied_cases` 的残留 `*.sv` 会被 `glob("*.sv")` 收进复核并标
   `complete=true`。该项不是 R4 条款，复核期间已由他人在工作树（未提交）规格 §未决（R6）与 `doc/STATUS.md` 登记；
   本报告不验收、不阻断 R4 合并，但提醒 Lead 确保该登记最终可见。
