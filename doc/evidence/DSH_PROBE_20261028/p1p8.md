### 2.6 附加（直接决定目标态 N2/#3，因此一并实测）

**(D) 跨进程 `session/resume` 回同一会话** —— 前一 sdk 进程已退出后，新进程可恢复：

```text

t+ 2400ms session/resume => {"jsonrpc":"2.0","id":2,"result":{}}
```

**(D2) 在 `cwd` 与创建时不同的进程里 `resume` 同一会话** —— 也成功，且**不改写**原 cwd、**不新建**第二个目录：


```text
t+ 1785ms initialize => {"jsonrpc":"2.0","id":1,"result":{"serverInfo":{…}}}
t+ 2274ms session/resume => {"jsonrpc":"2.0","id":2,"result":{}}
child-exit => code=0 signal=null
$ find $H1/sessions -maxdepth 2 -name probe-p1-shared-1 -type d

$ zstd -dc <该日志>   # 头记录 cwd 仍为 /…/slots/p1p8/home1/work（未被改写），事件仍止于 seq 3
```

> 推论（对规格有用）：`session/resume` 按 `sessionId` 在 home 的会话库里查找，**不依赖调用进程的 cwd**；但**新建**会话的落点目录由该进程 cwd 决定（转义目录名），所以同一 home 下不同 cwd 的会话会散落在多个 `--<escaped-cwd>--/` 目录里，而 `session/list` 仍统一可见（§2.3）。

**(E) 同会话两个进程同时打开** —— 第二者被**显式拒绝**（不是静默抢占、不是库损坏）：

```text
# A 持有 probe-p1-lock 8s（session/working-directory/get 后 hold）
t+ 1807ms holding session for 8000ms (process stays alive, lock held)
# B 在 A 持有期间 session/resume：
t+ 2390ms session/resume => {"jsonrpc":"2.0","id":2,"error":{"code":-32603,"message":"session \"probe-p1-lock\" is already owned by an active write handle"}}
```

**(E2) 持有者退出后锁是否残留** —— 无残留，`resume` 立刻成功：

```text
### G) resume probe-p1-lock2 after its holder exited (no stale lock?)
t+ 2297ms session/resume => {"jsonrpc":"2.0","id":2,"result":{}}
```

**(F) attempt 进程持有写句柄时，Web 实例能否读同一会话** —— **能冷读**，但看不到活体 agent：

```text
# A 持有 probe-p1-lock2（9s），期间 Web 请求：
web1 session/page  => {"ok":true,"value":{"records":[{…permission/preset seq 0…},{…sandbox/mode…},{…approval/policy…}],"hasMore":false}}
web1 session/list  => ok= True n= 9
  held session row: {"sessionId":"probe-p1-lock2","agentAvailable":false,"running":false,"updatedAt":1793167198537}
```

即：**跨进程可见性 = 持久化日志的冷读**；`agentAvailable=false` / `running=false` 说明 Web 侧不知道该会话有一个活着的 attempt 进程。
另据 (E)，写句柄是**互斥**的 ⇒ 同一时刻只有一个进程能"拥有"该会话（第二个 `resume` 直接报错）。

**条件（必须在规格里写死）**：
1. "跨进程可见"的语义是**冷读持久化日志**，不是"接管活体会话"；`agentAvailable=false` 证明 Web 看不到活体 attempt。
2. 同一会话**写句柄互斥**：attempt 进程持有时，Web 侧任何"以该会话为写者"的操作（如 resume / 人说话的写路径）会被拒绝。⇒ "人可在 GUI 里对**正在跑的**会话说话"不是共用 home 就能自动得到的，需要另设仲裁（谁持有写句柄、何时交接）。
3. 隔离 home ⇒ 完全不可见：任何降级路径（"看板自建投影 + 导出会话副本"）都成立，且需要显式的导出/复制动作。

## 5 P8 结论

**部分** —— 分条判：

| 子判据 | 结果 | 证据 |
|---|---|---|
| 无凭据请求必须 401（不是 200） | **过** | §4.1 `401 Unauthorized`（index / connect / /api 三处一致） |
| `WWW-Authenticate` 形态 | **不存在**：401 无任何挑战头；**不支持** `Authorization: Bearer` | §4.1 完整头；文档口径：HTTP 只认 `?token=` 交换 + cookie |
| 401 门怎么过 | **过**：`?token=` 换签名 cookie（`HttpOnly; SameSite=Strict; Path=/; Max-Age=2592000`）；API 走 `/connect?token=` 换 v2 cookie | §4.2 |
| iframe 内嵌（`X-Frame-Options`/CSP） | **部分**：HTTP 头**不禁止** framing（无 `X-Frame-Options`、无 CSP `frame-ancestors`），但真实可用性受两道自己实现的围栏限制：① cookie 是 `SameSite=Strict` ⇒ **跨站** iframe 不发 cookie ⇒ 401；② `/api` 的 Origin/`sec-fetch-site`/Host 围栏 ⇒ 跨权威内嵌即使有 cookie 也 **403** | §4.3 14/15/17 |

**因此 P8 的"降级线"判定**：§7 Q5 的降级（"新标签页 + 用户已登录的浏览器会话"）**不需要**触发——但"内嵌 iframe 里直接说话"也**不能承诺**为跨机器/跨域形态：
- **同站内嵌可行**（看板与 DSH Web 同 host，如 `127.0.0.1:<另一端口>` ⇒ cookie 是 same-site、iframe 内请求为同源 ⇒ Origin 与 authority 一致 ⇒ 放行），但需要先在可用的顶层标签页完成一次 token 交换（mint cookie）；
- **跨站内嵌不可行**（cookie 不发 + `/api` 403），此时应按 §7 Q5 降级为"新标签页 + 已登录浏览器会话"。
- 本次**未用真浏览器验证** iframe 的实际 cookie 投递（只按响应头 + 第三方 cookie/SameSite 规则推断）——这条要在浏览器门里补测（Playwright 门是现成入口）。

## 6 对规格的含义（P1/P8 会改哪条契约/目标态）

1. **目标态 #11 / 执行器契约（S0, SPEC-08）**：可以写"每 attempt 一个隔离 DSH 进程 + **共用同一个 `DSH_HOME`**"——这是唯一能让人在 GUI 里看到会话的摆法。同时必须写清三件事：
   - 会话目录按 **cwd 转义**命名（`sessions/--<escaped-cwd>--/<sessionId>/session.v4.jsonl.zstd`，zstd **多帧追加**，另有 `session.lock`）。`resume` 本身**不看**调用进程的 cwd（§2.6 D2：跨 cwd 也能 resume，且保留原 cwd）⇒ attempt 副本 cwd 变化**不影响**同会话复用；但**新建**会话的落点由该进程 cwd 决定 ⇒ 规格不要把"从目录结构推会话归属"当判据，一律走 `sessionId` + `session/list`。
   - 写句柄**跨进程互斥**（`already owned by an active write handle`）⇒ 规格要把"谁持有写句柄"写成显式状态，并规定交接时机（旧 attempt 进程退出后新进程才 `resume`；实测持有者退出后无残留锁，§2.6 E2）。
   - 可见性 = **冷读**（`agentAvailable=false` / `running=false`），不要写成"Web 里能看到正在跑的 attempt 的活状态"。
2. **目标态 #9 / N7 会话投影**：可以去掉"看板自建会话摘要"的兜底的一半——同一 home 下 `session/list` + `session/page` 已够做投影；但"人直接在 GUI 里对正在跑的会话说话"仍需一道写句柄仲裁（D1 新增决策点，不是 P1 能直接给的）。
3. **目标态 #3 / N2（一个节点一个 session，跨 attempt 复用）**：`session/resume` 跨进程可用（§2.6 D）⇒ 该依赖**已消解**；但"同一会话不能两个进程同时拥有"要进 attempt 生命周期状态机。
4. **P8 → S4 界面切片**：把"内嵌"写成**条件能力**：同站可用、跨站降级为新标签页；并且**禁止**把 `Authorization` 头当作鉴权方案（无此支持）。runbook 要写"token 只在启动 stdout 出现一次，重开请重启或复用已 mint 的 cookie（30 天）"。
5. **安全面（新增，规格要登记）**：`/api` 已有 Host/Origin/`sec-fetch-site` 围栏（DNS rebinding 与 CSRF 防护），但 **index 页不做围栏**且静态资源公开——若将来把看板做成"内嵌 + 同源代理"，必须明确 `--trusted-host`/`--public-url` 的信任边界。
