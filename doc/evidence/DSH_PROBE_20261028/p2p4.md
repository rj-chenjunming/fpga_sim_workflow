# P2 提交工具 + P4 事件/终态（Lead 实测，2026-10-28）

> 探针产物，一次性。配方见 `workspaces/.probe-dsh/BRIEF.md`。

## 假设

1. 能在 sdk/headless profile 里用 `--patch` 挂自写插件，注册 `submit_result` 工具，模型真能调用且 handler 在 DSH 进程内执行（→ 桥的落点可行）。
2. headless 的 NDJSON 事件能区分"完成/失败/工具调用"，终态可判，不需要靠 idle 猜。
3. `--session-id` 能跨进程复用同一会话（→ "一节点一会话、跨 attempt 追加意见"）。

## 结论

- **P2：过**（ESM 插件 + `defineTool`；模型真调用；handler 在 DSH 子进程执行；返回值能回到模型）。
  附带两个必须写进契约的事实：
  1. `submit_result` **只能靠 patch/insert 挂载**，Python 侧无法直接注册（与"自写 TS 薄插件"裁决一致）。
  2. 插件加载失败**只报 warning、不阻断启动** ⇒ Host 不能以"进程起来了"当成功，必须验工具清单（否则 = 静默缺工具）。
- **P4：过（headless 层）**：终态是显式 `turn_end.reason.kind`（`completed` / `error`+`code`），事件里有 `session`/`turn/step`/`usage`/`tool_call`/`tool_result`；不需要靠 idle 猜完成。
  **未验**：sdk profile 的 stdio `session.event`/`session.status`/`session/wait`（本轮桥用 headless + plugin，未走 SDK 协议）。
- **跨进程复用会话：过**：`--session-id` 续跑同一会话（turn 从 1 → 2，`cacheReadTokens` 9216/`inputTokens` 147 表明历史被加载）。

## 对规格的含义

1. 桥的形态可定为：**每 attempt 一个 headless 进程** + `--patch` 挂"提交工具/事件转发"薄插件 + `--session-id` 复用同一会话。
2. 契约必须写"启动成功 ≠ 可用"：Host 收口前要验 `submit_result` 在场（工具清单/自检），插件加载失败必须是显式失败而非 warning。
3. attempt 号可与 `turn` 对齐（同一会话 turn N = attempt N），旧轮次只增不改。
