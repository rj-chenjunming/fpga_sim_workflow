## 2 第 1 次真实轮：`RUN-20261022-173237` — N9 作业被判 dead（缺陷，已修）

| 节点 | 结果 |
|---|---|
| N0–N3 | ✅（N1 allfiles 4491；N2 1 个改动文件，offset `0xd04`；N3 **live** 语义摘要） |
| G1 | ✅ 人签 `human:chenjunming` |
| N5 / N6 / N6_apply / N7 / N8 | ✅ 必改 3 例；live 修订；3 例沙箱；**真机编译 rc=0**；live pass |
| **N9** | ❌ 作业 `JOB-0f3710bd9b21` 耗时 **1892s**，日志显示 **3 个用例全部 `rc=0`**（`tc_pcie_rw_02` / `tc_pcie_rw_smoke` / `tc_rtc_05`，证据齐全），但作业被判 **dead（rc 缺失）** ⇒ run failed（fail-closed 行为正确） |

**根因（实测）**：`JobRunner.submit` 把命令与 rc 写入拼成同一段 shell；N9 real 的命令串以 `exit 0` 结尾
（单例 rc 记进 summary，交 N10 三分类），该 `exit` 先退出 shell，追加的 `echo $__rc > <rc>` 永远不执行。
**真机全跑此前从未真正执行过**，所以这个缺陷从未暴露。

**修复**：`loop/host/job_runner.py` 把命令包进**子 shell** `( … )` 后再写 rc；新增回归
`tests/test_admission_and_jobs.py::test_job_command_ending_with_exit_still_writes_rc`（先红后绿）。
软件层复跑：**533 passed, 3 deselected**（`bash loop/spikes/run_software_checks.sh --ignore=tests/browser`）。
