# B1b 复核：G2「未通过报告」的 403 文案统一（2026-10-27）

> **本轮是否修复：是（仅措辞）**。拒绝条件、判据函数、闸门枚举、账本字段**一律未改**。
> 上游：`doc/STATUS.md` §82.1 的 B1b 登记（当时"只改界面、不改 403 串"，理由是该串已被冻结证据引用）。

## 1 为什么要改

B1 裁决（`§82.1`）把界面警示统一成「接受**未通过**报告」，但服务端 403 的 `detail` 仍写
「接受**失败**报告」——同一事实两套措辞，且界面说 A、服务端说 B 容易让人以为是两回事。
`§82.1` 当时不改的理由是：该串被 [`SPEC_REV05_VERIFY_20261026.md`](SPEC_REV05_VERIFY_20261026.md)
（md5 `e1eccd7749296c66366588f0a72157d7`）按原文引用。本轮按"改串 + 出新证据 + 旧证据不回填"处理。

| `loop/workflows/chunks/gates.py` | `838c265658e1ec9f675b915fc92ceb53` | `10ccf191cbbe4aab4e289e1d34bbb30d` |

改动点（3 处，全部是**措辞**）：

1. `precheck_decision` 的 G2 分支 403 文案：`接受失败报告必须给出理由` → `接受未通过报告必须给出理由`；
2. 同分支成功路径的 warning：`accept 作为失败收口` → `accept 作为未通过收口`；
3. 该分支注释：`失败报告允许接受` → `未通过报告允许接受`。
   另：`loop/tests/test_fix_lifecycle.py` 两处**提示文案/测试数据**同步（`已阅失败报告` →
   `已阅未通过报告`、断言消息同理），断言语义未变。

## 3 实测（命令 + 输出）

用一个临时脚本构造"报告 `not_passed`"的 run 目录后直接调 `precheck_decision`
（脚本已删；复现方式 = 在 `loop/` 下 `python -B` 调用同两个函数）：

```
403_TEXT=D：本轮报告结论为 not_passed（未通过）⇒ 接受未通过报告必须给出理由（reason）。仍有 1 个用例「已修订待验」：接受报告不等于判据通过，N16 仍受 I3/I4 阻断。
WITH_REASON_OK warnings= ['报告结论 not_passed：accept 作为未通过收口（已给理由）；1 个用例仍待验，不得称跑通']
```

⇒ **无理由仍被拒（同一条件、同一异常类型）、给理由仍放行并留告警**：判据没动，只有措辞变了。

`loop/tests/test_fix_lifecycle.py` 相关用例：**45 passed / 8 deselected**（本轮改后实测）。
