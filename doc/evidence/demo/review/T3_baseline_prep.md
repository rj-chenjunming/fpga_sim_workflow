**地址粒度核对（我自己推的，标注为推断）**：`sr_init_addr` 在 `:669-676` 从 0 自增到 `'hff`（255），比较键是 `'h0/'h1/'h2/'hc`；而 CPU 侧读地址是 `{3'b000,cpu_addr[7:2]}`（`:204`）即**字节偏移 >> 2**。
⇒ 键 `'h0/'h1/'h2/'hc` 对应字节偏移 `0x00/0x04/0x08/0x30`，与 `I2C_SCALE/I2C_FILTER/I2C_TIMEOUT/I2C_REG_LEN` 的 localparam **逐一对齐**（`'hc`=12 → 12×4=**0x30**）。这三个 key 的初值 `0x4e/0x7c/0x7c` 与**位定义表**一致，**与汇总表 `0x00` 不一致**。

**写路径优先级（对探针设计有用）**：`ram_wraddr = sr_init_wen ? sr_init_addr : ...`（`:765-766`）、`ram_wdata = sr_init_wen ? s_init_data : ...`（`:767`）。
⇒ 初始化窗口（`sr_init_wen` 高，`:678-688`，持续到 `sr_init_addr` 达到 `'hff`）内**CPU/BMC 写被 init 覆盖**（`sr_init_addr == 'hff` 时 `sr_init_wen` 转 0）。这是"复位后立即读"必须留足够时间的 RTL 侧理由（**不是**断言依据）。

## 5 "`0x2000` 段用 PCIE 通道是否正确" —— 我给出的**检索域 + 可验证判据**（不下断言）

**检索域（已查）**：

1. 接口文档 RTC 段全文（L737—L1066）：无访问路径用语（见 §3）。
2. `06_iface_doc_regmap.md` §A.1 18 条主清单（L765—L784）+ §A.2 通道归类（L797—L804）+ §A.3 缺口表（L806—L815）：`0x2000` 段**只在缺口表**出现（L812，29 个寄存器，❌无）。
3. `09_iface_doc_vs_case.md` §A.0（L22—L31）：`0x2000` 在**一级译码**里无独立判决，落 **sys 兜底**（`TCS9620_MAC_TOP.v:701`/`:752`）；经 `cpu_bus_mux`（`:1032`）→ `cpu_addr`（`cpu_bus_mux.v:155/:175`）分发到 `i2c_master_scheduler_top`（`TCS9620_MAC_TOP.v:1269`/`:1306`）。
4. **RTL 读窗口的归属（我自己读的）**：`TCS9620_MAC_TOP.v:1270/1272`（及 `:1307/1309`）把
   `.CPU_REG_BASE_ADDR` 与 `.BMC_REG_BASE_ADDR` **赋成同一个基址** `OUT_9548_I2C_ADDR + OFFSET*j`；
   `i2c_data_ram.sv:201`（CPU 命中）与 `:455`（BMC 命中）**是同一范围的两条译码**。
   ⇒ RTL 层面 `0x2000` 段**CPU 侧与 BMC 侧都能命中**（不是单通道）。
5. `TB/tbtop.sv:64/65` `` `FPGA_OT9548_ADDR(32'h2000) ``、`` `RTC_OFFSET(32'h200) ``（经 `09` §A.1 L43 转述）。

**我拒绝下的断言**：文档**没有** `0x2000` 段的通道标注 ⇒ 无法用文档判定"PCIE 通道**正确**"。同时 RTL 显示双通道都命中 ⇒ 也**不能**据此判定"PCIE 是唯一/错误通道"。

⇒ **本条必须标 `待确认`**，并给**可验证判据**（用例侧应能同时失败）：

- **正判据（通道确实打在该块上）**：`0x2000+0x04`（`i2c_filter`，位定义 Reset `0x7c`，汇总 `0x00`）读回必须是 **`0x7c`**。
  若读回 `0x00` ⇒ 需区分两种假说：(a) 打在**汇总表语义的 0x00**；(b) 通道未命中导致落 `0xffffffff`/`0x0`。
  ⇒ **判别测量**：同时读一个 RTL 里初值非 0 且汇总/位定义**无冲突**的旁证寄存器（见下条 **`0x2000+0x78` = `0x1`**；`0x0c i2c_9548_opt` 位定义 Reset `0`，**不可用**），并读一个**确定无应答**地址（如 `0x3800`）作落空对照。
- **落空对照（通道打空的可判别特征）**：`TCS9620_MAC_TOP.v:640` 的 `: 32'hffffffff;` 是 CPU 读回**默认值**（我本机复核；**注**：`09` P0-1 转述为 `:641`，实测 `:641` 是空行 ⇒ 该笔记此处行号**差 1 行**，以我复核的 `:640` 为准）。
  ⇒ "读回 `0xffffffff`" = **通道未命中**，与"命中但复位值不同"可区分。
- **更强的非零旁证探针（我复核为三方一致）**：`0x2000+0x78 pca_rst_n` = **`0x1`**
  （位定义 L1046 `Reset 0x1`；汇总 L770 `Reset 0x1`；RTL `i2c_data_ram.sv:269` `sr_i2c_9548_rst_n <= 1'b1`）⇒ **两表不冲突、非零**，是最干净的"通道确实打在该块上"判据。
  对照项 `0x2000+0x7c i2c_m_rst` = **`0x0`**（位定义 L1056 / 汇总 L771 / RTL `:188` `sr_i2c_m_rst <= 1'd0`）⇒ 全 0，**不能**单独用来区分"命中"与"落空"。
  ⚠ 这两条的位定义表头写作 `Offset： 0x0078` / `0x007c`（**缺 `+`**，L1043/L1053），`06` **C22** 已登记"相对/绝对混用，`0x0078` 易被误读为全局 `0x0078`（全局应为 `0x2078`）"⇒ 复核用例时须确认它写的是 `0x2000+0x78` 而不是 `0x78`。
