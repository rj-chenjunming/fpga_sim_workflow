## 1 为什么不能自动收敛

样式收敛的验收是**视觉等价**：默认/hover/focus/disabled/告警/模态态，以及断点交界宽度、
键盘焦点、缩放后的可达性。合并同名声明、删除「疑似未使用」规则、合并同范围媒体查询，
都会改变层叠顺序或命中条件；没有截图/计算样式对照就无法证明等价。仓库红线禁止用
`!important` 掩盖层叠，也禁止「先改再录基准」。

## 3 未来执行时的验收条件（留给可运行浏览器的执行端）

1. 固定四页 + 目录 + Agent 窗口 + 旧页 + 空/错/加载态的截图与关键组件计算样式
   （1280/1440/1920；窄屏 390/768 只做溢出检查，不新增移动产品目标）。
2. 按 框架布局 → 通用控件 → S0 → 运行/闸门 → Agent 窗口 逐段整理；每类组件一个基础声明 +
   明确状态/断点修饰；颜色/间距从令牌引用。
3. 一次合并一个组件，核对 specificity 与源码先后顺序；只有动态状态、旧页面与键盘路径都覆盖后才删规则。
4. 合并同范围媒体查询时检查交界宽度与缩放可达性；不得新增 `!important`。
5. 每次改动跑现有浏览器特征集（`tests/browser`），对照 GET/POST 目的地、次数、草稿身份与焦点；
   截图差异需人工解释，不能自动重录基准。
