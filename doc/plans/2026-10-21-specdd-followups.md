# 后续优化与特征重构实施路线

状态：**已整理，待分切片实施**。本轮仅文档和只读复核；不启动下面全部功能。依据 [本轮审计](../audit/AUDIT-20261021-specdd-followups.md)、[AGENTS.md](../../AGENTS.md) 和现行 [规格索引](../README.md#2-spec-契约)。验证状态统一在 [STATUS §11](../STATUS.md#11-后续优化与特征重构整理2026-10-21)。

## 推进顺序

1. **正确性**：F01 基线准入/身份 → F02 能力投影。每项独立规格变更与可回退提交。
2. **验证基础**：F03 测试隔离与文档解析；基线修复可先用临时目录测试，后续广泛重构以此为前置。
3. **按特征重构**：F05 从闸门 UI 开始；F06 从模型单次请求边界开始。两个 owner 不同时编辑同一文件，每次只提取一个功能。
4. **S0 闭环**：F04 先做协议与受控适配器，内网驱动验证通过后再开放执行联动。其进度由内网条件决定，不阻挡云端 UI/软件验证。
5. **Agent 工作台增强**：F07 测量与增量读取、F08 记录发布 → F11 观察体验；F09 持久暂停依赖记录语义与恢复规格；F10 先做预算/经验展示。
6. **暂缓**：F12 并行委派；无具体用例时不引入第二套调度框架，不作整仓重写。

## 每个切片必须交付

规格差异和未决项 → owner/文件清单 → 既有可观察特征通过记录 → 缺陷/新行为失败断言 → 保持行为提取 → 独立行为修改 → 受影响回归 → 四道门状态 → 冻结证据与 STATUS。

“特征重构”在这里包含两层：按用户功能边界拆分；用不读源码也能判定的特征测试固定行为。保持现有缺陷的测试只用于识别变化，规格修正后须明确替换预期。**禁止用源码字符串检查或快照全绿代替业务断言。**

下面是目标验收，不是已运行结果。若要改变公开 API、产物格式、恢复行为或闸门判据，先更新对应 spec 并记录契约评审。现有冻结 kb 工具/Schema 语义若必须修改，另开 kb owner 变更。

## F01 基线准入与全链身份

- **规格/owner**：先修订 [WEB_UI_SPEC](../spec/WEB_UI_SPEC.md) 的 valid/创建契约，与 [ENV_PLUGIN_SPEC](../spec/ENV_PLUGIN_SPEC.md)、[编排规格](../spec/LOOP_ORCHESTRATION_SPEC.md) 明确同一基线身份。Host 负责有效性；编排只传递；kb 保持账本唯一写者。
- **落点**：config_api 的只读投影、RunManager.start 的统一准入、N0/N1/N2 的参数传递。避免 API 和直接调用 manager 走不同判据。仅复用/传参不足时才提出 kb 独立变更。
- **先固定**：默认基线、时间注入、运行 ID 冲突、跨环境拒绝、drill 标签、有效运行的既有产物。
- **新验收**：Given 不存在、坏 manifest 或缺必要资产的基线，When 通过 API 或直接 start 创建，Then 在新建 run、写事件、隔离旧投影、占槽前拒绝。Given 非默认有效基线，Then N0 引用、N1 parent、N2 来源、view/闸门材料同值。Given 准入后源发生变化，Then 重新核验或明确失败，不能静默使用另一版本。
- **验证/回退**：临时基线目录 + 截获工具参数 + 现有配置/生命周期测试；内网补一次非默认基线真实链路。身份链未闭合时不放开新路径；回退独立软件切片，不改历史账本。预计规模：中，先拆准入与身份传递。

## F02 能力投影与状态文案

- **规格/owner**：WEB_UI 与编排 spec 定义实现状态、当前环境可用性、执行模式、验证范围；Host/服务投影唯一输出，UI 只展示。验证证据不能由布尔“已实现”推导。
- **落点**：agent_view、contracts、health/详情 API 与 UI 提示；保留现有消费者字段兼容。
- **先固定**：事件到工作中/失败/完成的映射，checker 当前节点选择，门/作业/槽等待区别。
- **新验收**：N11 无事件显示“未开始”而非“未实现”；有实现但缺 provider/plugin 时准确显示原因；standin 不显示真模型结论；历史真机部分验证不能变成全链通过。旧 guardian 文案测试先由新契约触发失败，再更新实现。
- **验证/回退**：agent_view/config/浏览器测试；接口缺新能力字段时显示未知，不默认 ready。规模：小。

## F03 验证分层与文档解析

- **规格/owner**：编排/环境 spec 明确测试运行根与外部依赖判据；验证工具 owner 修改测试/驱动/扫描器，不修改业务结论。
- **先固定**：原测试中真实环境门的要求；扫描器三根、行号后缀、历史例外及模板跳过行为。
- **新验收**：纯软件测试在未挂载内网的干净临时根运行；测试只清理本次创建资源；受控插件明确替身；真实环境集成缺件返回“未运行/阻塞”及原因。扫描本仓工具/Schema 正确解析到 TOOL_ROOT，外部缺件和真实本仓断链分栏且均保持可见。Markdown 链接及锚点另有检查。
- **落点/验证**：conftest、验收脚本、check_doc_links 与对应测试；旧完整验收仍保留。先注入独立根并验证零越界清理，再启用分层命令；不靠批量 skip 或改冻结文档消除红灯。规模：中。

## F04 S0-b 与准出消费者

- **规格/owner**：S0/环境/编排/UI spec；Host 派生与应用唯一写者，模型只提建议，人通过现有 GATE-1 复核。先明确附件 GATE-1 与既有 G1 的身份/材料映射，不默认为相同，也不新增旁路门。
- **切片**：接口差异与 TB 登记 Schema → 范围核验和副本逐 hunk 应用/否决回滚 → 版本化三库驱动/日志归档 → 新版执行准出消费者。逐切片交付，入口最后开启。
- **先固定**：完整复制/RTL 替换、只读基线、非 RTL 见证、失败记录、漂移和历史只读。
- **新验收**：越界 TB/TESTLIB/PKG 修改在写前拒绝；空登记不算已核对；否决仅回滚登记 hunk 并重跑冒烟；缺任一库日志、warning 评估、复核或基线见证时 ready=false；通过材料必须属于同一准备记录、基线和环境。校验和真正执行间发生漂移必须阻断。
- **验证/回退**：云端受控文件树/假驱动仅证明协议；内网真实三库与合法/越界接口用例证明能力。失败保留新副本与证据，撤销入口不删除用户资产。规模：大，依赖内网适配；不承诺当前条件下完整交付。

## F05 UI 按功能拆分

- **规格/owner**：WEB_UI / AGENT_WINDOW 现有行为；前端实现 owner。
- **顺序**：先闸门决策视图，再运行监控，再配置/目录选择；保留 app 作为导航与会话装配入口。只在重复行为已经一致时提取公共请求/会话工具。
- **特征验收**：切换 run/gate/session/attempt 后旧 GET/POST 不能改新窗口；提交中切走再返回仍禁重复提交；409 保留草稿；轮询保持焦点；API 动作枚举权威；键盘关闭不终止任务；窄屏可用。按网络请求与 DOM 行为断言，不要求具体函数名/目录布局。
- **落点/验证**：app.js 及新功能模块，复用 test_run_sessions / test_agent_window；每次提取后跑同一特征集，保持端点/载荷/状态码一致。纯提取与新 UI 功能分开提交，失败可逐片回退。规模：中，不整体换框架。

## F06 模型节点按功能拆分

- **规格/owner**：AGENT_CONTEXT / AGENT_WINDOW / 编排 spec；Host 请求机制与模型语义节点分别保持原 owner。
- **顺序**：请求契约/单次请求/校验提取为独立模块；N6 上下文与修订、N10 分类、N11 守护依次拆分；原入口留兼容导出，TriggerFlow 拓扑和消费者不动。
- **特征验收**：相同输入产生相同提示词/Schema 指纹；逐节点输入覆盖、顺序和 offered 集合一致；每次新 agent；指令只能进入新尝试；非法输出不得到消费者；N10/N11 返工、用例状态与产物内容一致。声明为版本字段的实现指纹允许随代码变更，不能因此跳过语义比较。
- **验证/回退**：context_memory/control/fix_real_chain 特征；使用受控 provider 验证机制，真实语义仍需内网/provider 复验。不要同时搬动公共类型、改提示词和改台账判据。规模：中，分节点提交。

## F07 Agent 增量读取与服务响应

- **规格/owner**：AGENT_WINDOW 定义分页/游标/稳定排序、当前状态与历史快照；Host 只读投影 owner。性能目标先按选定运行规模测量后记录，本文不虚构延迟指标。
- **先固定/测量**：完整历史查询、指纹损坏拒绝、幂等旧回执、旧响应隔离；在增长的尝试/事件集记录读取字节、请求耗时及控制响应分位数。
- **新验收**：重复/断线续读不漏不重，新增尝试可发现，选定旧尝试稳定；读取大历史期间控制仍达约定响应预算；缓存过期不隐藏损坏/新事件。将只读 I/O 移出事件循环时，不能把 _ACTIVE 的命令执行一起无锁转到线程。
- **验证/回退**：受控历史规模与并发请求测试；保留兼容完整读取路径，游标不可用时明确重载，不静默跳过事件。规模：中；先测量再决定是否引入 SSE，默认不需要 WebSocket。

## F08 封存记录发布与故障收敛

- **规格/owner**：AGENT_CONTEXT / AGENT_WINDOW 定义发布状态、完整性与兼容读。调用记录仍归 agent_memory，控制记录仍归 agent_control；公共存储原语不成为业务 owner。
- **先固定**：独占编号、只增不改、校验和/身份验证、审计失败不能确认命令、取消后不消费旧结果。
- **新验收**：在目录创建、数据写入、校验写入及命令 accepted/applied 之间逐点杀进程，恢复读取能区分未完成与已损坏；不得消费未提交记录、回填旧证据或自动重发请求。拒绝替换已存在编号，旧格式可读，格式升级有迁移说明。
- **落点/回退**：先用故障注入确定必要改动，再将私有 `_sealed` 依赖变为公开窄接口；临时文件/原子提交标志等具体方案由规格评审决定。回退使用兼容读，保留所有已写证据。规模：中。

## F09 Agent 持久暂停与恢复

- **规格/owner**：先更新 AGENT_WINDOW 与编排恢复契约；TriggerFlow 独占 durable 调度，Host 独占调用/控制记录。依赖 F08 的发布与恢复语义。
- **先固定**：当前暂停不进入消费者、终止显式失败、取消超时不重叠、重启历史只读。
- **新验收**：暂停后杀服务，新进程显示可验证的暂停及待处理命令；未经新的有效续跑意图不调用 provider；旧会话控制被拒；accepted 未 applied 的命令有确定收敛规则；重新发起的尝试身份独立；旧远端响应不得进入消费者。不能靠恢复 _ACTIVE 字典模拟持久恢复。
- **验证/回退**：真实服务进程终止/重启 + 受控 provider，内网补真实 provider 取消语义。快照缺失/不兼容时显式失败且只读，不能回退为自动执行。规模：大，独立功能轮。

## F10 记忆与预算可解释性

- **规格/owner**：AGENT_CONTEXT 明确模型预算、预估不确定性及经验诊断展示；Host 计算/筛选，人工维护经验，UI 只读解释。
- **先固定**：完整输入、不静默截断、来源/事实/提示词/Schema 精确匹配、经验无法绕过 Host 校验。
- **新验收**：用户可见本次输入的预算组成及经验为何采用/拒绝；provider 不支持 token 计算时显示未知并保留现行字节门；超限在请求前拒绝。分块必须另有覆盖清单、结果汇合和唯一消费者验收，默认不自动启用。新增经验管理 UI 前先定义人工写入的审计与确认流程。
- **验证/回退**：边界输入/来源变化/版本变化/超限测试及浏览器展示；移除展示不改变筛选结果。规模：展示小，token/分块能力另拆。

## F11 Agent 观察体验

- **规格/owner**：WEB_UI / AGENT_WINDOW 定义摘要、事件范围、来源排序和窗口布局；前端 owner，服务只提供事实投影。历史分页依赖 F07。
- **先固定**：run/node/session/attempt 隔离、服务端动作枚举、草稿与回执互斥、键盘/窄屏行为。
- **新验收**：从命令回执定位到应用状态和对应新尝试；两次尝试差异可回溯原始输入/输出；筛选明确范围且可访问完整历史；失联/读取错误时动作禁用且展示最后更新时间。多窗口不能把另一个窗口的动作发送到当前任务，也不能绕过同会话重复提交保护。仍不声称提供隐藏推理或独立终端。
- **验证/回退**：延迟/乱序/失败 API 浏览器场景，移动与键盘检查；先增强现有窗口，再单独试侧栏布局，保留原始记录视图。规模：中。

## F12 并行委派的立项条件

先给出可获益的独立任务和测量，再更新编排 owner/汇合/取消/冲突契约；验证多个只读结果的唯一消费者、父任务终止传播、部分失败收敛与单槽约束。未经这一步不引入跨 Agent 自动经验写回、共享文件编辑或新调度框架。预计规模：大；当前暂缓。

## 验证与退出条件

- **本轮文档**：检查新增/修改的链接、锚点、来源定位及 git diff 空白；只读探针说明受控范围。无需为文档整理编造实现红灯。
- **后续实现**：每片先运行相关特征基线；新行为必须有先失败用例；再执行受影响测试和仓库四道门。通过、失败、跳过、未运行分别登记，数字只写 STATUS，原始输出落冻结证据。
- **内网部分**：仍需真实插件/基线/历史夹具与 provider；未具备时交付可审查的软件切片及内网验收步骤，完整验收保持阻塞。不得把受控模拟升级为真机证据。
- **完成定义**：每条 F-ID 在后续新证据中关联规格、提交和结果；旧审计/证据不回填。本轮“已整理”不表示各项“已修复”或“四道门全绿”。
