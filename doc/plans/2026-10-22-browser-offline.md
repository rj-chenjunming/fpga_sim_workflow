# Rocky Linux 浏览器验证离线包

用户授权：将浏览器验证相关依赖放入 Git，内网拉取后本地安装。目标为用户确认的 Rocky Linux 8.10 / x86_64 / glibc 2.28，仓库现用 CPython 3.11；另附 CPython 3.12 wheel 用于云端复验。

- owner：验证工具 owner。本轮允许修改离线资源目录、浏览器检查工具/对应测试、安装说明、环境规格、STATUS 与新增证据；不修上轮代码复核的业务缺陷，不改冻结 kb 或环境资产。
- 来源：Python wheels 从 PyPI 下载，版本/哈希锁定；官方 Chrome 发行包从 Google 下载，保留版本、来源与 SHA-256。Playwright 官方浏览器 CDN 在当前云环境被策略拒绝，改用公开 Chrome 可执行文件接口，不绕过网络策略。
- 交付：普通 Git 文件，不依赖 LFS 或安装时外网；大浏览器归档按小于 GitHub 单文件限制的片段保存，清单提供每片和整体 SHA-256。
- 行为：安装前检查 Linux/x86_64、CPython 小版本及 glibc；所有本地资源先验哈希；pip 强制 no-index、固定 wheel 和哈希。优先复用显式路径/系统 Chrome，缺浏览器时解开随包运行时至软件缓存，不调用 rpm/dpkg 安装，不需要 root。
- 验证入口：真实启动浏览器，受控本地页面冒烟通过才执行浏览器 pytest；缺包/动态库/可执行文件、校验失败显式非零，不通过整组 skip 冒充完成。系统共享库不从 Debian 复制到 Rocky，不自动联网安装系统 RPM；缺件列出名称。
- 步骤：先写兼容/完整性/提取失败断言；再实现安装与检查；准备锁定资源和来源清单；在干净 CPython 3.11/3.12 环境断开索引安装，执行浏览器回归；记录实际验证及 Rocky 主机尚需实测的边界。
- 回退：删除工具管理的独立浏览器缓存；依赖在独立 venv 中验证后再安装到项目 venv，原环境可保留切换。不会修改系统浏览器、RPM 数据库、基线或运行账本。

命令、版本、大小与实际结果统一记录到 STATUS；离线说明不能将本机 glibc 较新的通过结果写成 Rocky 真机已通过。
