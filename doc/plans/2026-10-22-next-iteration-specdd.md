## 2 写权与 SpecDD 提交规则

Lead 是计划与规格 owner；各任务卡指定唯一实现 owner，表中为**职责分配，人员待执行时填写**。前端只展示 Host 事实，不另建预算判据、闸门枚举或恢复状态机。独立验证者只写新报告、不修被测代码；尚无独立验证者时登记为同一执行者复验。

每个切片按以下顺序留提交，禁止把整阶段合成一次行为大改：

1. **规格/计划**：列可观察行为、不变量、唯一 owner、允许修改文件、验收 ID 与未决决策。契约改动先在对应 spec 完成显式评审，再开始实现；本计划中的建议不自动成为现行契约。
2. **特征/红灯**：纯重构先固定旧行为并运行通过；缺陷增加确定性失败用例，确认因目标缺陷失败，不能把测试写错或缺环境算作缺陷红灯。
3. **实现**：先保持行为的局部提取，再单独修行为；保护历史数据和兼容读取。测试期望若需要改变，退回规格评审、单独记录，不改断言掩盖缺陷。
4. **验证**：受影响集合 → 软件层/浏览器 → 适用的完整四道门。记录通过、失败、跳过、排除、未运行及原因；有环境阻塞可以交付软件切片，不能标完整完成。
5. **归档**：原始命令、提交、环境、退出码、日志与来源指纹写入新增证据；冻结并在 STATUS 记 MD5。代码修复、复验及残余分别关联到同一任务。

共同禁区：不修改冻结的 kb 工具/Schema、不回填旧审计/证据、不写环境 RTL/TB/PKG/TESTLIB 原件。若需要改变 kb 语义，另立变更；S0 派生副本仅适用现行 S0 规格限定的写权。

## 3 阶段 B：先关闭可复现缺陷

### R1 / F08：原子发布与历史可读性

- **owner / 落点**：Host 记录 owner；`loop/host/agent_memory.py`，必要时只读消费方 `loop/host/agent_control.py`，对应封存/记忆/控制测试。
- **先确认规格**：[AGENT_CONTEXT_SPEC](../spec/AGENT_CONTEXT_SPEC.md) 的 M1、封存与恢复。明确唯一发布点、临时件命名、同文件系统原子操作、不覆盖既有文件、数据和目录同步顺序；本轮承诺进程中断，断电持久性不能未经验证一并宣称。
- **方法**：完整写入并同步私有临时件，再原子且不可覆盖地发布最终校验/提交凭据；读者仅消费可核验记录。不用「所有 corrupt 当 incomplete」掩盖真篡改。
- **验收 R1-A**：在数据写入、校验临时件创建/部分写入、发布前后逐个固定故障点终止子进程；旧 committed 尝试仍可读，半件不可消费；发布完成的件可核验。
- **验收 R1-B**：竞争写同编号只有一个成功；已提交记录零覆盖；真实坏校验/JSON/符号链接仍显式失败。保留 SIGKILL 压力测试，偶然单次转绿不能关闭缺陷。
- **迁移/回退**：旧格式读取保持兼容；旧空 checksum 不自动修补。若引入新标记，先确定旧读者是否兼容，再决定是否允许回退；不删除旧尝试来恢复页面。

### R2、R3 / F01：基线边界和错误隔离（分两次行为提交）

- **owner / 落点**：Host 准入 owner；`loop/host/baseline.py`；API 仅消费该结果，相关测试为 baseline_admission、api_baseline_detail、admission_and_jobs。
- **规格入口**：[编排规格](../spec/LOOP_ORCHESTRATION_SPEC.md) §3.1、[环境规格](../spec/ENV_PLUGIN_SPEC.md)、[网页规格](../spec/WEB_UI_SPEC.md) 的基线列表/准入。
- **R2 方法与未决**：先写明允许根集合及相对路径解析基准，评审现有工作区父目录兼容规则是否保留；所有绝对/相对候选统一 resolve 后检查范围，先判边界再读取/哈希。不得为兼容任意扩展根集合。
- **验收 R2-A**：同一允许根外文件的绝对路径、`..` 路径、相对符号链接全部拒绝；合法根内路径成对通过；断链/循环链接给结构化错误。拒绝的 real 启动没有 run、作业、事件写入。
- **R3 方法**：将 UnicodeDecodeError 归入该基线的 errors；保留错误原因，不用忽略编码错误后解析的方式修改输入语义。
- **验收 R3-A**：坏编码与合法基线并列时列表仍成功，坏项 invalid、好项仍在；real 选择坏项按现行错误协议拒绝且零副作用。保持数组/空对象/坏 JSON/缺文件的原回归。
- **回退**：按 R2、R3 分别 revert 软件提交，基线原件零写入；修复回退后将对应缺陷重新标未关闭。

### R4 / F16：按真实编码成本选择 N8 表示

- **owner / 落点**：N8 上下文 owner；`loop/workflows/chunks/model_steps.py` 及 n8_context_budget 测试；预算编码继续复用 Host 唯一实现。
- **规格入口**：[上下文规格](../spec/AGENT_CONTEXT_SPEC.md) C1。先区分「强制 changed_regions 的大文件」与「允许全文或片段的文件」，不能借修复解除前者的既定规则。
- **方法**：对合法候选的完整序列化字节计成本，包括 coverage 与外层结构；禁止假定片段一定更短。保持文件名确定性顺序，设计可行性计算与选择策略，说明并列成本的稳定选择。
- **验收 R4-A**：全文在预算内而片段更大时可选全文；中文/转义/密集变更/删除/多文件/临界相等均有断言；相同输入得到相同字节。所有合法候选都超限才拒绝，绝不丢文件/丢变更或虚报 complete。
- **回退**：仅回退算法提交；保留超预算显式失败，不靠增大默认预算使红灯消失。

### R5 / F10：窗口采用 Host 的预算事实

- **owner / 落点**：Host 上下文 owner 唯一产生计量；UI owner 只消费。分开提交 Host/API 投影与 `loop/web/context-explain.js`、Agent 窗口接线；预算与控制测试覆盖连接处。
- **规格入口**：[上下文规格](../spec/AGENT_CONTEXT_SPEC.md) C1、[窗口规格](../spec/AGENT_WINDOW_SPEC.md) 可解释性；先评审总量、字段分项、序列化开销、旧记录缺值的 API 契约。
- **方法**：推荐复用请求准入时的 Host 编码/计量结果；offered/scope 等非计费材料不能混入。旧记录如需重算，只由 Host 使用同一算法完成，无法确定则 unknown，不回写旧记录。前端不保留第二套判据。
- **验收 R5-A**：Host 准入字节与 API/UI 总量完全相同；空值、中文、转义、外层键名/标点和人工指令覆盖；分项加显式开销等于总量；上限未知不显示假比例，token 仍 unknown。
- **回退**：先回退 UI 消费、再回退新增 API 字段；保留旧客户端兼容，不改历史 request 文件。
