## 第一版：复用现有后端

| 切片 | owner / 落点 | 实施与验收 |
|---|---|---|
| P0 特征基线 | 前端实现 owner；既有 Agent/节点详情浏览器用例 | 固定入口、身份、原始状态、草稿、重复提交、取消与历史只读；采集桌面/窄屏截图及人工任务基线 |
| P1 信息与成果 | 前端 owner；纯展示适配层，服务投影 owner 核对字段 | 保留原弹窗，主区合并概览与成果；先 N3/N6/N8，技术信息折叠；当前身份/所选尝试分开，无记录不推断未开始；U02/U03/U04/U10 |
| P2 统一 AI 入口 | 同一前端 owner；app.js、agent-window.js、index.html | AI 节点与角色卡同入口，复用现有会话/幂等/旧回包保护；不同时改执行后端；U01 |
| P3 操作与历史 | 前端 owner；复用控制 API，后端 owner 核对语义 | 按 available_actions 提供动作，解释重发；回执分层、历史只读、终止确认；先保留现有草稿隔离，跨窗口恢复后置；U05/U06/U08 |
| P4 稳定性与实用性验证 | 前端 owner；受控浏览器与人工任务对照 | 断连/乱序/新结果、滚动、键盘/窄屏不回归；对照查看成果、补充要求、追踪新版的效率与误操作；U07及U09既有行为 |

一次仅一个 owner 修改面板控制状态；展示适配层不能发送控制命令或重复判定业务通过。
先运行特征基线，保持行为提取再做交互变更，每片补可观察的先失败用例。
不通过快照重录掩盖状态/焦点/身份错误，截图变更必须说明与设计的对应关系。

## 第二版：独立依赖

- 布局与草稿：比较相同任务在现有弹窗与停靠/全屏中的表现，再决定四标签、尺寸和跨窗口草稿恢复；不预设换布局即改善。
- 其余角色成果：按使用反馈扩展 N10/N11/N12，明确验收覆盖范围。
- 版本对比：先确定两版输出及实际产物的身份/来源对齐，不将 N6 候选与落盘版本混比。
- 证据预览：先建立受限只读接口、类型/大小/编码限制和路径/秘密过滤，再做 UI；首版仅探测存在性。
- DSH 动态：依赖 [SPEC-08](../spec/DSH_AGENT_RUNTIME_SPEC.md) 的真实工具事件和能力探测，按 U11 验收。

## DSH 接入的协调顺序

已有 Agently 默认保留；DSH 按其计划先做 N3 技术探针，再用 N6 同任务/模型/权限对照决定是否有限采纳。
普通成果展示不等待该试验；依赖 DSH 的执行控制与历史重构先确定 SPEC-09 §8.1 的统一投影。
不能把 DSH 原生完成、工具退出、Host 校验、实际应用和人工放行混成一个状态；
不能因前端隐藏技术字段就假定后端全量读取成本已改善。性能优化按现有测量门单独启动。

## 验证、边界与回退

依次运行受影响浏览器与展示适配测试；涉及服务字段时补 API 合约测试。
按仓库要求执行软件层、kb 自测、端到端、文档门；内网资产缺失时明确记录未运行/失败，不造历史夹具。
UI 的受控验证不等于 live 模型、DSH 或真机仿真验收。同一执行者的测试不声称独立复核。

每片保留可回退提交，回退界面不重发任务、不回填或删除历史记录。生产热更新前处理在途表单与命令，
不能在提交途中替换面板控制器；历史 API 保持兼容。

本轮设计检查限于链接、代码围栏、文档路径增量和补丁格式；产品测试与用户任务测量留实施阶段。
结果写入 STATUS，设计推送不代表实现上线或环境发布。
