## 预期实现落点

- 请求机制由现有 [model_request.py](../../loop/workflows/chunks/model_request.py) 调用统一执行接口；
  Agently provider 解析留在原后端，DSH 使用自身受管连接。
- 拟新增模块放在 Host 下的 agent backend 子包；具体文件在 D1 定义，不提前建立空壳模块。
- 由 [agent_control.py](../../loop/host/agent_control.py) 持有结果接受资格与控制序列，
  [agent_memory.py](../../loop/host/agent_memory.py) 独占记录发布。
- 节点业务校验继续从 model_steps 注入；DSH 不复制判据。N6 候选最终由原 Host 应用路径落盘。
- 环境能力通过 API 提供给现有 Agent 窗口；默认配置维持 Agently，按节点逐步启用 DSH。

## 验证与回退

每片先运行受影响特征用例，新能力先红后绿；依次验证软件层、kb 自测、端到端和文档门。
云端缺内网资产时，运行独立协议/路径/控制测试并保留未运行项；不造历史资产，也不把替身算真 DSH。
真实试验使用独立 state/运行目录，记录环境冻结件前后指纹，停止本轮创建的 DSH 会话和工具子进程。
输出版本、后端、节点、运行方式、失败/通过及审计引用；数字归 STATUS，原始证据只增不改。

回退先确认 DSH 执行终止，再为新尝试/运行选择 Agently；保留原失败尝试、候选与审计供追踪。
并行子 Agent、持久恢复、通用终端和 DSH 直接启动仿真不在首版切片内。
