# 节点模块化与环境适配重构评估

日期：2026-10-28；基线：4bb01d3；性质：设计建议、只读分析，未实施或执行测试。

## 目标与范围

开发者在源码中增加或调整节点，由既有 TriggerFlow 维护唯一拓扑；节点封装本职逻辑及输入输出；环境差异经适配器提供。不做画布、动态用户流程、第二套状态机。工作量为单人有效工程日的粗估，不是承诺；真实环境接入、独立终验和未发现缺陷另计。当前仅一个已登记环境，第二种目标环境的工具、日志、许可证和资源模型尚无事实，因此接口通用性待用第二环境验证。

## 所有权与接口

- 顶层 TriggerFlow：节点顺序、事件分支、有界回边、中断和执行关闭。运行状态及快照沿用现有机制。
- 节点：声明必要输入、输出、失败和副作用，持有本阶段业务职责；模型只做语义，Host 负责校验身份、授权、计数和应用。
- 环境适配器：工程发现、路径映射、编译和运行命令、资源需求、日志转规范证据；不得复制 kb 判据、改闸门或直接晋升。缺能力显式失败。
- kb/Host：原有业务台账、签署锚、准入、证据身份、晋升唯一权威；环境冻结区不写。旧事件名称、run 产物及快照先保持不变。
- 人：G1/G2/G3 决策和 N16 真实触发；UI 保持只读投影与有限传输。

接口先从现有 N7 输入/结果提炼，包含用例身份、候选路径与哈希、环境能力与版本、日志引用、退出状态和错误；副作用及单槽控制仍由 Host 持有。不可先设计一个包罗万象的插件框架。日志解析的规范数据必须保留原始日志引用和来源身份。

关键数据边：N2 diff → N3/G1/N5；G1 签署 → N5；N5 目标 + 事实 → N6；N6 edits → Host 应用、哈希 → N7/N8/N9；N9 原始证据和身份 → N10/N11；N10/11 + 台账 → N12/G2；G3 决策 → N15 → N16。N8/N11/G2 的返工信号进入 N6，计数和终止规则保留。每个输出有下游消费者；恢复时须校验运行身份、版本与证据新鲜度。

## 验证环境与实施前置

本机只读核查：WSL 仅列出 docker-desktop（stopped）；Docker CLI 已安装但引擎连接失败；Windows Python 3.10。仓库默认环境为 Linux 绝对路径，workspaces 无业务数据。该探测不是安装或权限诊断。

首选已有可访问的 Linux 云端/内网开发机：仓库已有 loop/remote/README.md 所述 SSH 隧道；可直接使用目标环境与历史夹具，Windows 只负责操作。需先核实该机器的访问权、Python、数据根及工具，不将历史记录视为当前可用。

本地方案：安装 WSL2 Ubuntu（或启用 Docker Desktop Linux 引擎）；Python 3.11 建独立 venv，按 loop/requirements.txt 固定依赖。代码和测试工作区使用 Linux 文件系统，保持软件、可写数据和真实环境分离。提供来源可核验的历史夹具和基线副本，设置 LOOP_ENV_ROOT 与 LOOP_WORKSPACE；不复制敏感凭据，也不将软件替身当作仿真器。实际安装、网络和权限需验证；当前尚未建立。

验证分层：① 不依赖真实工具的单元与受控替身；② 可写数据根与完整夹具下的软件层和 drill 端到端；③ 派生环境副本上的环境层和 kb 自测；④ 有真实工程、UVS/许可证及必要模型配置时的真实链路。环境层入口 run_env_layer_checks.sh 会复制和写派生环境；accept_v1_run.sh 会清理 state 和 drill 标记运行，必须使用独立工作副本与隔离数据，先检查实际脚本路径和现有数据。不能在共享或历史数据上直接运行。四门及浏览器附加门遵守当前 AGENTS.md，缺项如实记录。
