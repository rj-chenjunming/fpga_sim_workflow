## 3 三片设计

### 3.1 S3a WM（REV-13 §6；必测 WM-01～05）

**落点**：新文件 `loop/host/agent_working_memory.py`（唯一构造者）+ `model_request.run_attempt` 接线
（`working_memory` 与 `input_data`/`approved_experiences` 同级放进 `request_input`，随 `AM.Attempt` 封存）。

**接口**（实现时以此为准）：

```python
WM_VERSION = 1
ENTRY_KINDS = frozenset({'observed_fact','human_decision','model_proposal','open_issue','constraint'})
ROLE = 'N3'|'N6'|'N8'|'N10'|'N11'|'N12'
build(ctx, node, input_data, *, instructions=(), gate_projection=None) -> WorkingMemory
# WorkingMemory.payload -> {"version":1,"availability":"verified"|"unavailable",
#                           "snapshot_sha256":...,"entries":[...],"unavailable":[...]}
# WorkingMemory.source_map -> 冷存进 request（不进模型输入）：逐条 source key/字段路径/指纹/node 消费者
# WorkingMemory.mandatory_bytes -> 强制条目（fact/issue/constraint）的紧凑序列化字节（用 AM.encoded）
```

- **确定性（WM-01）**：条目按 `(kind, 稳定 entry_id)` 排序，`snapshot_sha256 = AM.fingerprint({version, entries, unavailable})`；
  同一明确来源重建 ⇒ 同一 sha。条目带 `resource_versions`（各源字段的 `AM.fingerprint`）；源版本变化 ⇒ 新投影指纹，
  调用方持有的旧快照**不得**被当当前事实消费（快照本身不提供"重新校验旧快照仍有效"的能力）。
- **条目五类（WM-02）**：只投影**现有字段**，不做语义压缩/总结模型/向量检索。
  `model_proposal` 保留建议类别（例如 N8/N11 输入中的 `author_handoff` 回应、`rework_handoff` 里模型来源的意见），
  **不得**写成 `observed_fact`。`open_issue` 直接复用 H1/H2b 的 `issue_id`/`follow_up`，不重写关闭/重开算法。
  `human_decision` 只读投影已核验闸门事实（`host.gate_authority.authority_view(run_id)`，仅投影、不判定、不重签）。
- **载体与 `input_ref`**：`{version, availability, snapshot_sha256, entries[], unavailable[]}`；每条**二选一**
  `value` 或 `input_ref`。`input_ref` 是 JSON Pointer，指向**同一请求 `input_data`** 的既有字段；Host 校验：存在、
  不以 `working_memory` 为根、无循环、不是外部未读材料。已在 `input_data` 中的正文**不复制**（WM-05），只用引用。
- **预算（WM-03/04）**：强制条目总量超 `AM.MAX_CONTEXT_BYTES` ⇒ **调用前失败**并报缺口（不截断/不抽样/不丢弃）；
  总预算准入仍唯一走 `AM.check_budget`（红线 8）。索引不等于材料已送达：Agently 无补读工具 ⇒ 必需正文留在热输入
  （`input_ref` 只允许指向本次**实际发送**的 `input_data` 字段，天然满足）。
- **失败显式**：源半件/篡改/越界/跨 run 引用 ⇒ `ValueError`（节点失败）；旧格式/缺来源 ⇒ **不标 verified**
  （`availability="unavailable"` + 逐条 `unavailable[]` 原因 + 保留当前权威事实）。
- **不做**：语义摘要、向量检索、第二套 issue 规则、第二套预算判据。

**测试**（新文件 `loop/tests/test_agent_working_memory.py`，先失败）：WM-01 确定性 + 源版本变化、WM-02
proposal 不晋升 + H2b ID/follow_up 保持、WM-03 半件/篡改/越界显式失败 + 强制条目超预算不调用模型、WM-04 材料预载
（ref 指向已发送正文）、WM-05 大事实不复制 + pointer 可解析无循环 + 预算按真实序列化、旧格式不标 verified。

### 3.2 S3b IL（REV-13 §7；必测 IL-01～04）

**落点**：`loop/host/agent_control.py` 新增 run 作用域指令事件面（`agent_controls/run/` 下独立子目录，只增不改）
+ `loop/services/api.py` 两个端点 + `model_request.run_attempt` 注入有效指令并记录 revision + 接受门。

**事件形状**（版本化，落盘复用 `AM.seal_record`）：

```json
{"format_version": 2, "run_id": "...", "revision": 1, "operation": "create|revoke|supersede",
 "request_id": "client-id", "actor": "human:operator", "at": "...",
 "replaces_instruction_id": "old-id",
 "instruction": {"id": "host-issued", "version": 1, "message": "...", "scope": "attempt|node_rework|run",
                 "target_nodes": ["N6"], "dependencies": []}}
```

- **写前拒绝**：未知字段/枚举、空 message（>4000 字符或纯空白）、非法 node、`expected_instruction_revision`
  与当前目录 revision 不符（CAS）、revoke/supersede 目标不存在或已失效、跨 run 引用。
- **幂等（IL-02）**：同 `request_id` 同 payload ⇒ 返回原回执；同 `request_id` 不同 payload ⇒ `ControlConflict`（409）。
- **原子性（IL-02）**：单个 `supersede` 事件原子包含"旧 ID 失效 + 新条目"，读取器绝不观察到"双生效"或"都失效"的中间态。
- **scope（IL-01）**：`attempt` 绑定 Host 预留的一次替代尝试（该尝试终态即到期，不滚到后续返工）；`node_rework`
  同 run 同节点后续显式尝试；`run` 同 run 节点白名单；**绝不跨 run**。旧 `/control` 的会话内语义保持、不自动升级（IL-04）。
- **接受门（IL-03）**：请求封存 `instruction_revision`/采用 ID/未采用原因；结果返回后核验"当前 generation + 指令
  revision"仍与请求时一致，不一致 ⇒ 结果标为丢弃并留审计，**不进入消费者**（显式失败，不静默交付）。
- **单写者**：沿用 RunManager 写权；无"经验证的单写者协调"时**拒绝指令写入**（显式 409/400，不猜测）。
- **API**：`GET /api/runs/{run_id}/instructions`（当前有效条目/版本/来源/失效原因；历史只读）、
  `POST /api/runs/{run_id}/instructions`（create/revoke/supersede，必带 actor/request_id/expected_instruction_revision）。
  错误映射与既有 `/control` 一致：400 数据错、403 actor 错、409 冲突/过期、404 未知 run、503 审计写失败。
- **UI 投影**：本片**不改** `loop/web/**` 与 `services/contracts.py` 的界面字段 ⇒ 浏览器门不并入；
  `accepted`/`applied`/`effective` 的服务端投影只提供给 S4，不在本片做界面（§5 缺口）。

**测试**（新文件 `loop/tests/test_agent_instruction_lifecycle.py`，先失败）：IL-01 scope 边界、IL-02 原子 supersede +
幂等键冲突、IL-03 重启重建/迟到结果丢弃、IL-04 旧 `/control` 行为保持 + 新字段参与签名 + accepted≠applied、API 路由与状态码。

### 3.3 S3c EXP（REV-13 §8；必测 EXP-01～03）

**落点**：`loop/host/agent_memory.py` 增加 v2 分支（v1 行为逐值保持）+ 新文件 `loop/host/experience_migrate.py`
（离线迁移/校验 CLI，**不进 `kb/`**）+ `model_request` 记录选中条目/适用条件/检查结果/目录指纹。

- **两类适用性（EXP-01）**：`exact_fact` 绑定资源当前内容/环境/基线，逐项由 Host 事实解析器核验，变了就拒用
  （`dependency_changed`）；`general_advice` 绑定已批准节点/任务类别/环境策略/契约兼容范围，不要求整请求字节相同。
- **审计指纹 ≠ 适用条件（EXP-02）**：`scope_for` 仍是请求审计指纹（v1 语义不变），**不得**用它直接判 v2 经验是否可复用；
  不用模型/关键词猜相似性。
- **源完整性与适用性分开检查（EXP-02）**：先核验目录格式/版本/人工批准/条目 revision/来源路径+sha256（复用 v1 的
  路径逃逸与锚规则），再核验 typed 依赖与适用环境；两阶段诊断分别记录。
- **拒用整批（EXP-03）**：可选经验批次超预算或使必需上下文超限 ⇒ **整体不采用** + 记录候选 ID/原因
  （`budget_batch_rejected`）；不截断、不静默取前 N 条；必需事实/问题/指令不受影响。旧版数量/大小规则（≤10 条、
  advice ≤4000）保持；v2 限制是**显式常量**。
- **不自动晋升**：`human` 只是单机元数据；模型不得写回 `adjudication/agent_experiences.json`；迁移工具只产出
  候选草稿（新文件），人确认后才替换目录；原请求/源归档零改动。
- **拒用原因枚举**：`not_approved`/`revoked`/`source_missing`/`source_corrupt`/`dependency_changed`/
  `unknown_dependency`/`contract_incompatible`/`environment_mismatch`/`budget_batch_rejected`（只报非秘密 ID/规则）。

**测试**（新文件 `loop/tests/test_agent_experience_applicability.py`，先失败）：EXP-01 v1 保持 + exact_fact 依赖变化拒用 +
general_advice 在批准范围复用、EXP-02 源坏/未审批/未知兼容版本不注入 + 审计指纹变化不直接使通用建议失效、
EXP-03 超预算整批拒用有诊断 + 强制事实保持 + 不自动晋升；迁移工具：只读校验、草稿不覆盖人工目录、坏件拒用。

## 6 缺口与未决（实现前登记；实现期内只追加）

1. **运营开关**：REV-13 §11 要求"WM、IL、EXP 分切片提交和开关"。本片**不实现**运行时开关，
   兼容性由"新字段可缺省 + 缺字段=legacy + 旧记录只读"保证；风险：无法在不回滚代码的情况下关闭单项。
   如实现期发现必须开关才不破坏旧行为，则升级为本片必做并补用例。
2. **UI 投影**：IL 的 `accepted/applied/effective` 与 WM/EXP 的解释面属 S4（`loop/web/**` 未改）；
   本片只交付服务端投影与请求记录，不声称界面已可用。
3. **general_advice 的"契约版本"**：本仓没有独立的契约版本号体系 ⇒ Host 提供**唯一显式 token**
   （请求/经验契约 `CONTRACT_VERSION = 1`）参与比对；更细的兼容声明（按节点/提示词版本）登记为后续。
   `environment_policy` 用 Host 已有身份（`P.ENV_ID` + `ctx.mode`）成串，不自造第二套环境标识。
4. **WM 的 `human_decision` 来源**：只投影 `gate_authority.authority_view`（已实现、只读）；不复算闸门、不重签。
   N10/N12 的 `human_decision` 如无已核验来源 ⇒ 该条目出 `unavailable`，不编造。
5. **IL 单写者**：仅在"本进程为 run 的活跃执行者"时接受写入；跨进程/部署形态的单写者协调未实现 ⇒ 显式拒绝写入
   （契约允许"没有经验证的单写者协调时拒绝"）。
6. **WM 冷材料补读**：Agently 无补读工具 ⇒ 本片只做"热输入 + input_ref"；DSH 补读能力未接（S5），
   `input_ref` 不声称可替代材料送达。

### 6.1 实现期登记（S3a 收口，只追加）

7. **WM 源核验失败早于 attempt 落盘**：源半件/篡改/跨 run 在 `AM.Attempt` 创建**之前**抛 `ValueError`，
   该次失败只有 flow 的 `node_failed` 事件、**没有 `agent_calls` 封存记录**（与既有 H1/H2b 预请求失败同行为）。
   要"M1 式留痕"需调整 run_attempt 顺序（先建 attempt 再核验），本片未做。
8. **`human_decision` 只给 N10/N12**：按设计 §5 表"按消费需求"实现；N3/N6/N8/N11 不注入闸门事实
   （N6 的人工约束走会话内 `instructions`→`constraint`）。扩到其它节点需同时交代闸门/G1 时序，未做。
9. **`source_map` 不含 attempt 号与 request/result 指纹**：`source_map` 在 request 封存体内，
   attempt 号与指纹由 request 顶层身份键 + `request.json.sha256`/`result.json.sha256` 锚承担（§6.2 由
   "source_map + 外层封存记录"共同满足）；不把自身哈希塞进自身。
10. **N10/N12 新增"闸门权威投影"前置依赖**：`gate_authority.authority_view` 不可用/锚不一致 ⇒ 节点显式失败
    （fail closed）；其余节点不受影响。这是 WM 接线带来的新依赖，不是第二套闸门判据。
11. **`availability` 保守口径**：任一条 `unavailable` ⇒ 整份快照 `unavailable`（不标 verified），
    其余当前权威事实照常保留；这是对"旧格式/缺来源不标 verified"的保守实现，避免逐条 verified 的过度声明。
12. **写权例外（Lead 授权，S3a）**：`loop/host/agent_review.py::prepare` 的机制字段排除元组加
    `'working_memory'`（**只此一个字面量**）。理由：WM 是派生投影不是节点业务事实，与既有
