## 3. 内网四道必备门：固定版本后执行

先按 [AGENTS.md](../../AGENTS.md) 的四门及 [内网验证手册](2026-10-22-intranet-validation.md) 准备环境。下面命令均在**被测软件副本的 `loop/`** 执行；先确认 `.venv`、三根、夹具和独立状态/数据根。每项单独记录命令、退出码、完整日志；不要用管道末端成功掩盖测试退出码。运行前先读脚本、确认其操作路径与写入范围。

1. **单测**：以所需 `LOOP_LLM_MODE=standin` 和已核验的隔离数据根执行 `.venv/bin/python -m pytest -q`。先记录收集结果，再完整运行；统计失败、错误、跳过及排除。浏览器和环境层若需要专门环境，分别按仓库入口执行并明确是否包含在本轮单测结果，不能重复计算或把缺件当通过。
2. **kb 自测 + 环境层**：`bash spikes/run_env_layer_checks.sh --with-kb-selftests`；入口负责复制新派生 ENV_ROOT，按脚本确认副本位置、数据和原环境零写入检查。三个自测的判据与环境层期望以当前 [AGENTS.md](../../AGENTS.md) 为准；保留各自汇总、退出码和原环境保护结果。
3. **drill 端到端**：先按 `spikes/provision_dev_workspace.sh` 准备**独立可写数据根**，并核验其实际使用的历史夹具及基线/索引/冲突；再在确认安全的独立软件副本中执行 `bash spikes/accept_v1_run.sh`。核对脚本全部 phase、断言与最终退出码。若使用替代夹具，明确相关断言是否仍适用，不以替代成功推断默认历史夹具通过。
4. **文档门**：在干净的文档扫描范围、正确三根下运行 `python doc/audit/check_doc_links.py`（从仓库根目录），逐项核实路径引用、迁移记录/历史横幅以及数字与 STATUS 一致；按当前项目判据要求零断链。保留完整日志和退出码。

**浏览器是附加门**：当前本地改动涉及合并后的 UI 相关功能需确认是否在本次交付变更范围；只要本轮改变 `loop/web/**` 或 UI 投影字段，就必须单独运行 AGENTS.md 中 `tests/browser` 门。先检查真实 Chromium 启动、路径、HOME/TMPDIR，记录缺件；界面行为与单测结果分别报告。即便本地改动未触及 UI，内网验证远端新增 UI 时建议按其交付范围另跑，不把历史远端记录当本次通过。

以下每项记录输入、预期、输出、失败与证据；测试名以被测版本实际文件为准。节点接口回归先在隔离根验证，再结合真实资产验证，不能把假数据结论扩展到真机。

- **N7、N9、N15**：编译/运行适配器参数、日志定位、缺日志、失败和超时；单槽互斥及释放、长任务提交/停放/重启重附着、取消/死任务、结果身份和正确归档。结合 `tests/test_compile_adapter.py`、`tests/test_run_adapter.py`、`tests/test_admission_and_jobs.py` 与流程测试；先确认文件存在和当前标记。
- **N10–N12、G2/G3、N16**：对账数字和原始日志同源、失败分类与身份校验、证据不一致 fail closed、报告引用、返工/升级、G2/G3 预检和签署锚；N15 选集与 N16 条件拒绝及零副作用。drill 的 N15 no-op 和 N16 dry-run 不代表真实仿真或晋升。
