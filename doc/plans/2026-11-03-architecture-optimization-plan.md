## 1 目标与保留的架构

目标是让现有闭环更容易部署、验证、维护和升级：先得到可信的测试输入和当前操作入口，再收敛职责边界，最后按实测需求改善性能和扩展能力。

保留当前模块化单体和以下权威边界：

| 对象 | 唯一责任方 | 优化约束 |
|---|---|---|
| 图、分支、等待与恢复位置 | TriggerFlow，图由 `workflows/main_flow.py` 定义 | 不新增平行状态机；移动入口前验证兼容 |
| 业务台账、闸门、基线写入 | `kb/tools/*` | 冻结目录语义变化必须另立变更并留证 |
| 请求、身份、计数、执行与校验 | Host | 不交给模型或前端计算权威结论 |
| 差异语义、修订、复核、分类、报告 | 模型节点 | 每个输出须有消费者；保留 Host 校验 |
| 审批、覆写、正式晋升触发 | 人 | 既有授权与签署条件不因重构放宽 |
| 展示与传输 | services/web | 只消费权威结果；缓存可丢弃、可重建 |

当前 DSH 已接入模型执行后端；仿真适配器已有默认实现，任意环境插件和定制恢复仍不能宣称可用。N16 图节点默认做晋升预检查，正式晋升仍走人工入口。

## 3 各工作包的执行与完成条件

### O1：测试资产与准备入口

1. 对照现有失败、错误、跳过列表，登记每项所需的软件版本、源件、历史运行身份、基线、日志及数据根；不能将所有失败笼统归为环境问题。
2. 在既有准备脚本上补充资产清单与检查：来源、哈希、必需路径、可写位置、适用场景。原始源件与修改后沙箱件分别标记。
3. 为适合独立验证的行为补显式合成夹具；历史回放仍使用原历史身份，不能改名冒充。生产准入行为变化先修订相应契约。
4. 缺件一次性明确报告；软件、历史回放、环境和浏览器范围分别输出结果，保持既有必备门标准。

**完成条件：** 在干净源码和专用数据根中可复现准备步骤；缺件、身份错配、哈希损坏被明确拒绝；合成用例覆盖真实断言；历史用例未被删除或伪装通过。实际原件仍缺失时，本包只能记部分完成。

### O2：文档入口校正

1. 将根 README 的 kb 自测入口与现行 `AGENTS.md` 对齐，明确统一入口使用派生副本。
2. 更正 drill 端到端的写入前提：准备专用可写数据根；检查脚本清理范围，不让复制命令指向共享历史数据。
3. 将默认环境能力与任意插件目标分开；将当前实现、历史验收、未验收分别标注。
4. 修正 N15 旧 for_each 注释；保留旧证据和历史文件，不将历史记录改成当前结论。

**完成条件：** 当前入口的命令、路径、能力与权威规格一致；增量链接检查通过，完整文档门的既有问题继续记录；未取得环境前置时不声称命令已运行通过。

### O3：业务规则与投影分离

1. 按消费者列清 `contracts.py` 内的数据读取、确定性判据和纯展示函数，确认每个规则唯一 owner。
2. 先用特征测试固定许可动作、拒绝原因、闸门材料、人工覆写和读视图行为。
3. 将共享规则迁到合适的已有 Host/业务模块；原调用入口通过兼容导出指向同一实现，不复制规则。
4. 更新工作流和服务依赖；按现有规格修订职责落点。规则语义变化必须单独登记。

**完成条件：** 同样事实下迁移前后结果一致；前端仍无判据写权；缺失材料和身份不匹配仍拒绝；业务规则可脱离网页投影验证；受影响软件与浏览器测试通过。

### O4：生命周期提取

1. 基于 O5 建立现有运行状态和恢复特征测试，不改变图入口位置。
2. 依次提取恢复/快照、作业完成交接、投影组装，每次只调整一个职责；保留 RunManager 对外接口。
3. 对启动、签署、取消、槽释放、重复通知和持久化失败逐项回归，记录前后状态及副作用。

**完成条件：** 等待闸门、等待作业、排队、结束、失败可以正确恢复或显式拒绝；失败不会显示为等待人工；重复通知不重复推进；取消后槽释放；没有新增状态权威。

### O5：兼容基线与升级规则

1. **先做基线：**登记已验证源版本、固定依赖、图指纹、路径条件、快照与关联台账；区分受控快照和真实历史运行。
2. **再定契约：**在编排规格中定义支持/不支持的升级组合、失败处理和操作指引。显式节点身份能力先核对固定依赖的实际 API，不预设可用。
3. **最后验证：**覆盖空闲、闸门等待、作业等待、取消、终态和损坏快照；真实历史实例在取得合法资产后单列执行。

**完成条件：** 支持组合恢复正确，未知组合明确拒绝且不改旧快照；执行失败与等待有明确区别。删除兼容壳需另有可复验的迁移证据，不能篡改指纹强行载入。

### O6：节点契约收敛

1. 按节点标明输入生产者、字段约束、输出消费者、写入副作用和失败事件。
2. 先整理纯校验与格式化依赖，再收敛大型函数注入；对关键边界引入明确类型，避免创建无实际职责的包装层。
3. 保留模型请求预算、封存、人工控制和后端执行的公共路径；图入口保持兼容。

**完成条件：** 正常、缺字段、身份错配、旧结果和失败产物均有行为断言；取消后旧响应不进入下游；节点结果有消费者；没有第二份业务台账。

### O7：性能测量与有条件优化

1. 使用显式合成事件历史，测量不同历史规模与订阅数量下的读盘、CPU、响应延迟；记录环境、输入规模和测量方法。
2. 只有存在瓶颈时才实施增量读取或可重建缓存，性能目标在测量后、改动前写定。
3. 缓存失效覆盖事件 seq、闸门/覆写/控制记录及时间相关展示；不能仅依赖事件序号。

**完成条件：** 同条件对照显示可解释的收益且符合预定目标；重启、文件替换、签署、覆写、取消后没有旧结论；缓存损坏或丢失可以重建。无瓶颈则记录“无需实施”。

### O8：环境能力与模型效果

环境方向先确定第二环境的真实需求，再定义编译/运行/日志身份与恢复差异，绑定适配器身份和版本；没有明确目标时暂缓插件扩建。

模型方向复用现有封存材料，建立有来源的代表性样本，分别评价差异覆盖、修订正确性、静态复核、FAIL 分类、证据语义增益和报告引用。真实请求需有可用后端及运行授权，记录模型、提示词、输入版本与耗时；未知结果不补默认值。

**完成条件：** 第二环境覆盖编译、运行、取消和重启；模型效果按真实执行样本评价，standin 只证明软件机制。N11 是否需要收窄职责由实测和契约评审决定，不能先删除证据守护。

实现前保存源码提交和专用测试数据身份。代码回退只处理本次切片，不覆盖他人变更；如果新版本已经产生运行数据，必须先按兼容契约判断旧版本能否读取，不能仅回退 Git 后直接恢复生产运行。旧快照、台账和冻结环境不为回退而重写。
