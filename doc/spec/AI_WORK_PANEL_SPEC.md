# SPEC-09 · AI 工作面板体验设计（草案 v0.1）

> 日期：2026-10-23。用户要求将讨论方案整理成文档并推送。
> 状态：**设计交付，尚未实现；不代表界面、接口或 DSH 能力已上线**。
> 关联：[SPEC-REV-03](SPEC-REV-03-20261023.md)、[实施计划](../plans/2026-10-23-ai-work-panel.md)。
> 本文细化 SPEC-04/07 的拟议交互；现行行为仍以原规格、实现和 STATUS 为准。

## 1 目标与当前问题

用户点击 AI 节点后，应首先看懂：**它在做什么、做出了什么、现在需要我做什么**。
目标用户是查看差异、审查候选修订、跟进任务与补充要求的工程人员。
高级诊断仍可访问，但不占据默认阅读路径。

依据现有 [页面结构](../../loop/web/index.html)、[Agent 窗口](../../loop/web/agent-window.js)
与 [节点详情](../../loop/web/node-detail.js) 的静态检查：

| 当前表现 | 对用户的影响 | 拟改进 |
|---|---|---|
| 节点详情与 Agent 窗口分别打开，AI 节点需跨窗口阅读 | 同一任务信息分散，容易丢失流程位置 | AI 节点与角色卡统一进入工作面板 |
| 输入、输出、事件 detail 主要按 JSON 展示 | 需要理解内部字段才能找出成果和问题 | 按角色展示摘要、差异、检查项和报告 |
| 会话 ID、预算、提示词、能力说明与任务信息混排 | 首屏缺少清晰的关注顺序 | 概览优先，原始数据集中到技术详情 |
| 观察和干预表单同时常驻，历史尝试也显示整组按钮 | 用户不易判断当前能做什么 | 按状态提供主动作，历史版明确只读 |
| 尝试编号与原始事件名主导历史记录 | 难以理解为何重跑、哪版有效 | 使用有依据的版本说明、控制回执和校验结果 |

这些是基于源码的设计判断；本轮未进行用户可用性实验，不声称已经测得操作效率提升。

## 2 范围与职责

首版覆盖 N3、N6、N8、N10、N11、N12 的工作面板。点击这些节点或对应角色卡进入同一个面板，
直接绑定所选 run/node；checker 的 N8 与 N10 分别定位，不默认跳到另一个任务。

Host/内部节点继续使用只读节点详情；人工闸门继续进入现有闸门视图。
模型节点面板可链接“查看当前闸门”，但只有实际存在、身份匹配的人工决策入口才显示该动作。
面板不能新增签署方式，也不能将 AI 返回、Host 校验与人工放行合成一个通过结论。

| 事项 | 唯一 owner |
|---|---|
| 调用、控制可用性、业务状态、闸门与计数 | 原 Host / TriggerFlow / kb / 人工 owner |
| 面板选择、标签页、草稿、滚动、加载和错误展示 | 统一面板控制器，原 app.js 只转交导航 |
| 角色成果的显示字段与文案映射 | 一份纯展示适配层；不重新计算业务判据 |
| 结果与历史文件 | 原 agent_memory，只读消费、不得回填 |
| DSH 能力事实与工具事件 | SPEC-08 后续实现；界面只消费真实投影 |

首版不提供通用聊天、任意工具终端、文件写回、历史结果重新应用或模型/权限配置入口。

## 3 入口、布局与导航

### 3.1 桌面与窄屏

- 视口宽度至少 1280 CSS px 时使用右侧停靠面板，主流程保持可见、当前节点高亮；
  建议宽度 `clamp(560px, 44vw, 760px)`，可通过“展开”切到全屏阅读。该数值是设计参数，需实测校正。
- 小于上述宽度直接使用全屏面板；窄屏为单列布局，正文可滚动，底部操作区不遮挡正文或软键盘输入。
- 停靠面板不设置模态焦点圈，用户可以返回流程选择节点；全屏模式按模态管理焦点和背景不可交互状态。
- 同一时刻仅一个 AI 工作面板。切换节点更新同一容器，避免节点详情与 Agent 弹窗层叠。
- 关闭只收起视图，不停止任务；再次打开同一身份恢复标签、滚动和未提交草稿。
  切换运行后不自动重开旧面板，不把旧身份的内容暂留在新任务首屏。

### 3.2 页面结构示意

下图仅为布局示意，不是实际执行数据：

```text
用例修订 · N6                       执行中  [展开] [关闭]
任务：依据已确认差异，修订分配给本节点的用例
最新动态：等待模型返回                  真实模型

[概览]  [成果与差异]  [执行记录]  [技术详情]

当前成果
  尚未生成候选修订

需要关注
  输出返回后仍需通过系统校验

────────────────────────────────────────────────
补充要求
[ 请重点检查……                                    ]
发送后将停止当前请求，再发起一次新尝试。
[发送补充要求并重新执行]                       [暂停]
```

首屏标题使用中文任务名 + 节点号。显示简短运行标识，完整 run/session/attempt ID 可在技术详情复制。
顶部始终保留状态、执行方式和最后更新事实；不能把 standin/夹具来源藏进技术区。

### 3.3 标签页与默认位置

| 标签 | 内容 | 阅读规则 |
|---|---|---|
| 概览 | 任务目标、当前阶段、最新成果摘要、需关注项、可用下一步 | 首次打开默认进入；运行中和失败时优先明确当前事实 |
| 成果与差异 | 按角色排版的结构化结果、校验问题、来源引用 | 结果未生成时说明原因；不拿上一次结果冒充当前成果 |
| 执行记录 | 版本选择、节点事件、人工控制与回执 | 当前版本和历史版本明确区分，显示所见记录范围 |
| 技术详情 | 完整输入、提示词/Schema、原始输出、原始状态、预算、标识与诊断 | 按块折叠、搜索与复制；按需渲染，完整数据可访问 |

打开成果链接时可直达“成果与差异”；轮询到新结果时显示提示，由用户选择跳转，不能自动切页或抢焦点。
同一身份已选择的标签优先于默认位置。

## 4 状态表达与主动作

分别展示 **执行状态、系统校验、流程位置**。前端只翻译已知值，保留原始值入口；
未知状态显示“状态未识别”并附原值，不能擅自映射为成功。
模型建议 pass、result validated、节点终态与人工闸门通过是不同事实。

| 当前事实 | 首屏文案/重点 | 主要操作 |
|---|---|---|
| 首次加载 | 正在读取任务；保留标题，正文骨架 | 不启用执行操作 |
| 尚无调用记录 | 尚未开始，任务输入/成果未生成 | 可查看已知节点信息，不提供伪造的启动按钮 |
| 正在执行 | 当前阶段 + 最近一次真实事件；没有工具事件则写等待模型返回 | 补充要求；暂停作为次要动作，均以 available_actions 为准 |
| 正在干预 | 补充要求/暂停已接收，正在处理 | 防止重复提交，不将 accepted 当成 applied |
| 已暂停 | 当前请求已暂停；恢复将发起新尝试 | 恢复执行，或发送补充要求并恢复 |
| AI 已返回、系统校验未明确 | AI 已返回；系统校验状态未确认 | 查看候选结果，不显示通过 |
| 校验通过 | 系统校验通过；明确节点/流程仍处于什么位置 | 查看成果；仅在有真实当前闸门时提供闸门入口 |
| 校验拒绝 | 候选结果未通过校验，首先显示具体问题 | 查看问题与原文；没有服务端动作则不显示“重试” |
| 已中断/执行失败 | 显示原因及已知可恢复范围 | 查看详情；失败不伪装为等待人工 |
| 历史版本 | 正在查看第 N 次结果，历史只读 | 返回当前执行；不允许向历史尝试发指令 |
| 刷新失败 | 当前连接异常，显示最后成功更新时间与旧数据标识 | 重试读取；旧数据显示只读，不保留可点击的执行按钮 |

“系统校验通过”只用于已有 Host 校验事实。`standin` 显示“演练替身”，不能因有完整结果结构而显示真实 AI 成功。
DSH 的 execution_unknown 仅在未来接口明确支持时展示“执行状态待核查”，操作按服务端关闭。
Agently 当前取消仅保证本地旧响应不被消费，不能用“已停止计费”等文案暗示远端终止。

## 5 各角色的成果阅读

首版复用 [node_schemas.py](../../loop/prompts/node_schemas.py) 的现有结构和 Host 校验结果，
不为展示摘要额外调用模型。字段缺失显示“未记录/未生成”，不补造风险、理由、行号或已修改事实。

| 节点 | 默认呈现 | 现有结构来源 |
|---|---|---|
| N3 差异分析 | 摘要、变更分组、需要人工关注的问题 | summary / groups / risky_points |
| N6 用例修订 | 按用例列候选 edits，old/new 双栏或逐项对照，附依据与限制 | revisions / edits / rationale / rework_resolution / notes |
| N8 静态复核 | AI 建议与系统校验分开；检查项、依据、必须修复项 | verdict / findings / must_fix |
| N10 失败分类 | 摘要、各 bucket 的分类和依据、未归类项 | summary / items / unclassified；数量只取 Host 权威 |
| N11 证据守护 | 建议结论、证据依据、返工请求与限制 | chain / reasons / rework_requests / caveats；实际完整性由 Host 判定 |
| N12 报告 | 报告标题、章节、未闭环项与引用 | title / sections / claimed_verdict / open_items / counts_quoted |

结果来源优先为 Host 已接受的结构化结果；只有原始返回时标为“候选/未通过校验”，不能混入正式成果。
具体 JSON 嵌套适配在实施时对照真实记录固定，不假设所有旧记录有相同包装。
N6 的 old/new 对照是候选编辑，不是文件已落盘证明；实际应用状态只能来自 N6_apply 的明确事实。
首版不承诺完整文件 diff；版本间 diff 与实际产物对比留第二版。

N12 Markdown 采用禁用原始 HTML 的安全渲染，链接走允许协议与受控资源规则，
默认不加载外部图片/脚本；未具备安全渲染时以保留段落的纯文本呈现。
所有模型字符串和事件内容都是展示数据，不能直接执行为 HTML、命令或文件路径。

## 6 补充要求与操作反馈

- 活跃任务允许干预时，在固定底部操作区提供“补充要求”。输入旁直接解释发送会取消旧请求并创建新尝试。
  普通发送不增加重复确认弹窗；按钮文案准确描述影响。
- 操作者为现有 human 元数据，首次使用明确填写，可在当前页面会话内复用并随时修改；
  不自动填成系统身份，不把该元数据当登录认证，也不在草稿中保存凭据。
- 发送时冻结 run/node/session/attempt、expected_revision 和 request_id；有在途命令时禁止重复操作。
  回执分“已接收”“已应用”“被拒绝/失效”，从记录追踪到新尝试。
- 409/校验拒绝保留当前身份的文字并显示原因；重新读取能力后才允许再次操作。
  超时不能生成新 request_id 盲目重发，先核对原命令状态。
- 未提交草稿按 run/node/session/attempt 绑定，存在当前页面内存；重开同一身份可恢复。
  会话或尝试变化时不自动继承草稿，旧草稿可提示“复制到当前任务”，复制是显式用户操作。
  已应用命令只清理其对应草稿，不能覆盖用户随后输入的新文字。
- 终止放入“更多操作”的危险操作区；仅在服务端允许时出现。
  点击后就地确认目标节点和“本轮将按失败收敛”的影响，可取消，不默认聚焦确认按钮。
- 历史只读时收起干预表单，用“返回当前执行”替代；无活跃请求时不显示不可用的大表单。

## 7 执行记录、刷新与无障碍

版本名称使用有来源的说明：有控制记录时可写“补充要求后重新执行”，只有编号时写“第 N 次尝试”。
不从相邻结果差异猜测重跑原因；无记录的原因显示“未记录”。当前版本与跟随最新是显式选项，
查看历史时不随新结果自动跳回。首版展示已有输入差异和摘要，完整双版本成果对比留第二版。

节点事件与控制记录保留来源分组，时间用于定位；不同来源的 seq 不合并为一条虚构的全局顺序。
首屏可只显示近期记录，但标明“已显示/已加载”范围；未取得总量时不声称“共 N 条全部记录”。
提供展开已加载记录入口；分页、全量检索及大记录性能优化需按 SPEC-07 的测量触发规则实施。

轮询只更新变化内容，不能重建正在输入的表单、改变滚动或重置折叠状态。
用户阅读较早事件时提示“有新动态”，点击后才跳转；旧回包通过选择代次与身份守卫拒绝。
组合节点与 Agent API 时分别标记加载/错误，部分接口失败不能把另一部分旧状态当作当前完整快照。

键盘可访问入口、标签和全部动作；标签支持方向键，焦点始终可见。
全屏模式保持焦点圈，Escape 关闭，关闭后焦点回到触发节点，节点重绘时按身份找回有效入口。
停靠模式有可访问名称和明确关闭按钮；不劫持页面焦点。新状态使用礼貌播报，日志不逐条抢读。
颜色配文字/图标，支持减少动画偏好；320 CSS px 与放大阅读时正文不产生页面级横向溢出。
代码/差异块可独立横向滚动，并提供换行显示选项。

## 8 API 复用与明确的后续依赖

| 数据/能力 | 首版做法 | 后续或缺口 |
|---|---|---|
| 当前会话、尝试、请求/结果、控制记录、预算 | 复用 `GET /api/runs/{run_id}/agents/{node}` | 先固定不同历史包装的展示适配 |
| 节点摘要、来源、原始状态、事件与引用 | 复用 `GET /api/runs/{run_id}/nodes/{node}` | 与 attempt 数据不能混用；缺关联时明确标为节点级信息 |
| 工作流位置、当前闸门和 blockers | 复用运行详情 | 无当前闸门即无决策跳转，不由 AI 结果推断 |
| 控制命令 | 复用现有 control API 与 available_actions | 不新增重放/失败重试语义 |
| 证据 | 首版只展示合法引用与现有存在性探测 | 正文预览须另定受限读取接口、大小/编码/类型/权限及脱敏规则 |
| 版本差异 | 首版使用现有摘要与输入差异 | 任意两版输出/文件对比需要只读历史取数及对齐契约 |
| DSH 工具时间线 | 首版未接入时不展示“正在读文件”等动作 | 依赖 SPEC-08 的真实工具事件、能力与取消语义 |

历史字段缺失不回填。展示层保留原始数据入口，不能只保留经过美化的摘要。
技术区与日志同样遵守已有路径、身份、审计和秘密过滤规则；不可用“调试模式”绕过它们。

## 9 分阶段落地

**第一版：可独立交付，不等待 DSH。** 统一 AI 入口与面板、首屏信息层次、角色成果渲染、
状态及操作反馈、历史只读、刷新稳定性、键盘与窄屏支持。优先复用现有服务契约。

**第二版：按依赖逐项交付。** 任意两版成果对比、受限证据正文预览、DSH 工具执行记录。
每项独立补规格和受控测试，不以第一版界面完成声称这些能力已可用。

实施必须先固定当前会话/控制/未知字段行为，再分离展示组件，最后改变交互；
避免同时改执行后端和界面，导致失败无法定位。详细 owner 和切片见实施计划。

## 10 可判定验收

| 编号 | 验收场景与预期 |
|---|---|
| U01 | 从 AI 节点与角色卡各点击一次，进入同一面板且 run/node 正确；N8/N10 不串角色任务 |
| U02 | 首屏可找到任务、状态、成果/等待原因和下一步，无需展开 JSON；缺失字段明确显示 |
| U03 | AI 返回、校验通过、人工待确认分别表达；standin、未校验和未知不能显示真实业务通过 |
| U04 | 六类输出按对应结构可读，未知/旧字段可在原文查看；拒绝结果显式标候选，N6 不误称已落盘 |
| U05 | 补充要求接收→生效→新尝试可追踪；拒绝保留草稿，重复提交不产生第二命令 |
| U06 | 历史版本无执行操作；切回当前取得新能力后才启用；旧响应/旧回执不污染新任务 |
| U07 | 轮询、新事件和结果到达不丢输入、不抢焦点、不跳滚动；断连保留旧数据并禁用操作 |
| U08 | 终止确认清楚显示目标和影响；关闭窗口不会取消任务；取消回执不冒充远端已停止 |
| U09 | 桌面停靠/全屏与窄屏切换不丢身份；键盘、焦点返回、缩放和减少动画行为正确 |
| U10 | 恶意 Markdown/HTML、外部图片、无效证据路径不会执行或越界读取；原始区同样受限 |
| U11 | 未有 DSH 事件时无伪造工具进度；有真实能力后才能开放相应状态和动作 |
