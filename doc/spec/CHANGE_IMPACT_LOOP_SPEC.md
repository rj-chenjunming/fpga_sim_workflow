## 1. 业务目标与完成不变式

**目标**：把「FPGA 收到新的 RTL 包 + 寄存器文档 → 与当前基线自动对比 → 人机共同确认差异 →
派 agent 修订/补充受影响用例 → 验证修订点跑通 → 报告人评估 → 返工到双方认同 → 决定是否全量回归 →
（可选）把整轮成果保存为新基线」做成一个**带严格人工确认闸门、证据可回放、身份可 join、基线可链式晋升**的工具。

**完成不变式（缺一条即不收敛）**：

| # | 不变式 | 谁保证 |
|---|---|---|
| I1 | 每个差异条目最终态 ∈ {已确认 / 已忽略(带理由) / 有疑义(转人工裁决)}；**存在未决条目不得进入修订阶段** | Human Gate 1 |
| I2 | 每个受影响用例态 ∈ {未改 / 已修订待验 / 已验证通过 / 已退回}；**存在「待验」不得称跑通** | checker + runner |
| I3 | 「跑通」= 编译卡点B rc=0 ∧ 静态卡点C 通过 ∧ 全跑卡点D 产完整 UVM 汇总 ∧ **两套口径均为 0** ∧ **预期观测点留下通过印记且计数三向一致** | checker（结果对账） |
| I4 | 冲突/待裁决清单是**一等公民**：断言以文档位定义表为准，冲突显式登记，**清单未清零不发版** | guardian + Human Gate |
| I5 | 每步证据带身份（manifest / md5 / run_id / 时刻），归档**只增不改**，可回放 | runner + guardian |
| I6 | 三道人工闸门（差异确认 / 评估 / 回归决策）**都必须显式通过**，模型不得越过、不得替人做发版决策 | Host（闸门控制） |
| I7 | 返工有界：修订↔退回循环设次数上限，超限升级为人工裁决，**不死循环** | Host（压力控制） |
| I8 | 每轮收敛后**可晋升为新基线**（人触发、Host 原子执行）：新基线必须自洽完整（新RTL快照 + 新文档指纹 + 新用例 md5 清单 + 冲突清单态 + 冻结变更结果 + 证据包指针），旧基线保留，**基线链可回放** | Host（晋升归档）+ 人（触发） |

---

**I2 与「失败报告收口」（2026-10-26 增补，[SPEC-REV-12](SPEC-REV-12-20261026.md) R1 方案 D 已实现）**：
当 `n12_report.md` 的 `claimed_verdict = not_passed` 时，闸门 2 的 `accept` **允许**，但**必须给出理由**；
它只表示「接受这份未通过的报告」，**不等于判据通过**——I2 仍成立（不得称跑通），N16 仍受 I3/I4 阻断。
报告缺失或结论为 `passed`/`undetermined` 时，按原规则：本轮「待验」≠ 0 不得 `accept`。

## 3. 所有者 / 不变式台账（Owner & Invariant Ledger）

| 所有者 | 职责 | 独占写权 | 不变量 | 冲突时谁裁决 |
|---|---|---|---|---|
| **Host 工具**（脚本/确定性） | 快照、md5、diff、影响分析、执行、计数、闸门控制、**N16 基线晋升归档** | `kb/` 索引、manifest、快照、闸门状态、基线链 | 数字/清单一律由命令输出，可复算；晋升原子、旧基线只增不改 | 与模型冲突时以 Host 实测为准 |
| **`simenv-analyst`（新增）** | N3 差异语义总结 | 差异摘要草案 | 每条必带证据行号，不凭空断言「影响」 | 人（Gate1） |
| **`simenv-author`** | N6 用例修订/补充 | `TESTLIB/<tc>.sv`（或沙箱） | 先卡点A检索；地址=段基址+块内偏移；失败双写 `*E`+`` `uvm_error `` | checker |
| **`simenv-runner`** | N7/N9 编译+全跑+采证 | `SIMLIB_RUN/`、证据件 | 串行；两套口径都记；日志用内容指纹 | guardian |
| **`simenv-checker`** | N8/N10 静态复核+结果对账 | 复核意见 | 非作者；逐条「怎样才能失败」；不替作者背书 | guardian（口径守护） |
| **`simenv-guardian`** | N11 证据链/冻结件/台账 | 台账与冻结清单 | 不兼任执行；内容 md5；归档只增不改 | — |
| **`simenv-reporter`（新增，可由 Lead 兼任）** | N12 评估报告 | 报告件 | 结论必须区分编译口径/功能口径；引用必须可解析 | 人（Gate2） |
| **人（使用者）** | N4/N13/N14 三道闸门 + **N16 晋升触发** | 闸门裁决意见、晋升指令 | 未确认范围不得进修订；未评估不得发版；回归与晋升由人决定 | — |

> 说明：新增 `analyst` 与 `reporter` 两个角色。**边界理由**见 §4 —— 它们各是一个
> 「模型决策 + 授权消费者 + 独立重试边界」，不能用 Host 脚本替代（diff 是确定性的，但
> 「diff 意味着什么」是语义的），也不宜塞进 author（author 的消费者是 checker，而它们的
> 消费者是人）。

## 4. 节点台账（Planned Node Ledger）

| 节点 | 类型 | 边界理由（为何在此切一刀） | 输入 | 输出 | 失败/重试行为 |
|---|---|---|---|---|---|
| N0 建基线 | Host | 纯确定性，无模型决策 | 交付包+文档 | manifest v₀ | 缺包/缺文档 → 拒绝并提示 |
| N1 输入摄取 | Host | 完整性校验是确定性 | 新包+新文档 | manifest v₁ | 校验失败 → 拒绝 |
| N2 差异对比 | Host | 精确 diff，模型不参与（模型只会「猜 diff」） | v₀,v₁ 两版 | 原始差异清单 | 无差异 → 直接结束并报告「无变化」 |
| **N3 差异总结** | **Model:analyst** | **语义工作**：把 diff 翻译成「影响」；消费者是人的 Gate1，独立重试边界 | 原始差异清单 + 冲突清单 | 差异摘要 | 证据不足的条目必须标「待确认」而非编造 |
| N4 差异确认 | Human Gate1 | **授权边界**：变更范围必须人拍板 | 差异摘要 | 冻结的变更结果 | 人可挂起/恢复；未确认不得前进 |
| N5 影响分析 | Host | 确定性命中计算（段粗筛→offset交集），模型参与只会引入幻觉 | 变更结果 + KB索引 | 必改/待查清单 | 索引缺失 → 标「索引缺口」转人工 |
| N6 用例修订 | Model:author | 写代码是语义+规范工作；卡点A强制检索 | 必改清单 + 模板 | 用例 v（冻结 md5） | checker 退回 → 重改（有界） |
| N7 编译 | Host+runner | 执行确定性，采证是 runner 职责 | 用例 v | 编译证据 | 编译失败 → 回 N6 |
| N8 静态复核 | Model:checker | 非作者语义判断；「怎样失败」是模型判断 | 用例 v + 编译证据 | 通过/退回 | 退回 → 回 N6（≤N 次） |
| N9 全跑 | Host+runner | 执行确定性（≈50min），重执行有成本故必须 N8 通过才跑 | 用例 v | run.log+两套口径 | 跑挂/超时 → 采证并三分类 |
| N10 结果对账 | Model:checker | 断言实效性/三分类是语义判断 | run.log + 观测点清单 | 通过/FAIL+分类 | 与 N8 同作者无妨，但口径须 guardian 复核 |
| N11 证据守护 | Model:guardian | 独立审计；「成链」判断 | 全证据件 | 成链/不成链 | 不成链 → 回 N7 重采 |
| N12 评估报告 | Model:reporter | 面向人的语义归纳；引用可解析是硬约束 | N2~N11 全部 | 评估报告 | 引用不可解析 → 拒发 |
| N13 评估 | Human Gate2 | **授权边界**：返工/接受由人定 | 评估报告 | 接受/返工意见 | 返工可回 N4 或 N6 |
| N14 回归决策 | Human Gate3 | **授权边界**：花 13~14h 机器费由人定 | 评估报告 | 要/不要/里程碑 | 人可改期 |
| N15 全量回归 | Host+四角色 | N7~N11 的批量形态 | 全量用例 | 回归报告 | 复用 run_tc.py 多机调度 |
| **N16 晋升新基线** | **人触发 + Host** | **授权+确定性**：晋升由人点，归档由 Host 原子执行；下一轮以它为「上一版」 | 整轮成果（新RTL快照+文档指纹+用例md5清单+冲突态+变更结果+证据指针） | 新基线 manifest vₙ₊₁（parent=vₙ） | 归档失败 → 不晋升并提示；旧基线不动 |

## 5. 值 / 事件边台账（Value & Event Edge Ledger）

| 边（生产者 → 消费者） | 值/事件 | 校验 | 失效/新鲜度规则 |
|---|---|---|---|
| N0→N2 | manifest v₀ | sha256+md5 复核 | 基线冻结后不可变；变了判「移动靶」 |
| N1→N2 | manifest v₁ | 同上 | 每次摄取新版本 |
| N2→N3 | 原始差异清单 | 每条带文件/行号 | 与 manifest 版本号绑定 |
| N3→N4 | 差异摘要 | 每条带证据行号 | 人确认前为草案，可重生成 |
| N4→N5 | 冻结变更结果 | 人签名/版本号 | 冻结后不可静默改 |
| N5→N6 | 必改/待查清单 | 每条带「段→RTL文件→用例」依据 | 与冻结变更结果绑定 |
| N6→N7 | 用例 v（md5） | md5 冻结 | 改了 md5 → 本轮证据作废重跑 |
| N7→N8 | 编译证据 | 两段 rc + 内容指纹 | 只编译口径 |
| N8→N9 | 通过判据 | 逐条依据 | 未通过不进 N9（省 50min） |
| N9→N10 | run.log + 两套口径 | UVM 汇总 + `*E` 计数 | 运行对象 md5 必须 == 审的 md5 |
| N10→N11 | 对账结论 | 三向一致 | — |
| N11→N12 | 成链/不成链 | 身份四方同值 | — |
| N12→N13 | 评估报告 | 引用可解析 | 过期证据不得进报告 |
| N13→N14 | 接受 | 人签 | — |

## 6. 生产必要性台账（Production Necessity Ledger）

| 项 | 为何需要 / 为何不能省 |
|---|---|
| N2 diff 用 Host 而非模型 | diff 是精确查询；模型会幻觉「改了哪个文件」。**确定性程序足够，不上模型** |
| N3 analyst 用模型 | 「RTC 控制器数 9→12」这种 diff 语义，必须模型从文件+文档联合推断；但证据行号必须 Host 提供，模型只做语义 |
| N5 影响分析用 Host | offset 交集是确定性集合运算；模型算会漏会错 |
| N6/N8/N10/N11 用四角色 team | 已实证：非作者复核才是真正抓错的一环（D-1/D-2/D-10/D-12） |
| 三道人工闸门 | 授权/发版/花钱（回归）都不可由模型代签；模型只准备材料 |
| 双轨冲突裁决 | 铁律 3（预期值只认文档位定义表）+ 未清零不发版，防把漂移固化进用例 |
| 证据身份（md5/manifest/内容指纹） | 已实证：只比大小必误判（六轮编译日志字节数相同）、锚漂了没人知道（commit_id.log 指向不存在提交） |
| **N16 晋升为「人触发 + Host 原子」而非自动** | 晋升=把成果固化为「真相」；自动晋升会把半成品当基线。人触发、Host 原子归档，才能保证基线链可回放、旧基线不丢 |

## 7. 身份与证据设计（Identity & Evidence）

1. **版本 manifest**（一行一版，**含 parent 链**）：交付包 sha256 + 自研代码清单 md5 + 文档条目集指纹 + 日期 + 可解析 commit（不可解析记 N/A）+ parent 指针。
   —— 取代已漂移的 `BIN/commit_id.log`，三个锚互相交叉验证，且每版能链回上一版。
2. **文档条目集指纹**：入快照时跑抽取（126 条目 + 属性/复位值/位定义），规范化成行文本再哈希 → diff 定位到具体 offset。
3. **用例 md5 冻结**：进入 N7 前冻结；改了即作废重跑。
4. **编译日志内容指纹**：`Compilation starts at` + 用例行号位移 + 与归档 diff 行数（**不看字节数/mtime**）。
5. **两套口径**：脚本 `egrep -c '(\*E|\*F|\*e|ERROR:)'` 与 `UVM Report Summary` 的 `UVM_ERROR` 计数**都记**，谁也不替谁。
6. **运行对象身份 join**：审的 md5 == 跑的 md5 == 对账的 md5（四方同值，缺一判断链）。
7. **归档只增不改**；归档件置只读并把 md5 记到文件之外。
8. **串行信号**（不用 `ps`，它在本机沙箱里看不到外部仿真进程）：`uvs.setup`==夹具 / `wave/*.usdb` mtime 滚动 / `.compile_only.lock` 存在。
9. **基线晋升（N16）**：新基线 = 新 manifest + 新 RTL 快照 + 新文档指纹 + 新用例 md5 清单 + 冲突清单态 + 冻结变更结果 + 证据包指针，**七件套原子归档**；旧基线只增不改。

### 7.1 闸门材料充分性（Gate Material Sufficiency）

> 来源：[SPEC-REV-01](SPEC-REV-01-20261022.md) R2。人工闸门的价值取决于材料能不能让人**当场判断**；
> 材料不充分时，"人签了字"只是形式合规，不是实质确认。

**要求**：每道人工闸门下发的材料，必须让操作者在不读代码仓、不猜路径的前提下回答三问：
① **改了什么**（before/after 原文级，而非"某文件 md5 变了"）；
② **影响到什么**（条目 / 用例 / 段 / offset 与证据出处）；
③ **凭什么同意或不同意**（未决条目、冲突清单、双口径计数、返工轮次）。

**G1（N4）逐条最低字段**：

| 字段 | 要求 |
|---|---|
| `entry_id` / `kind` / `change` | 必填；`kind` 用 `n2_diff.json` 原值，不自造类型词 |
| `before` / `after` | 必填（原文或结构化差异原值）；不得以路径字符串代替变更本体 |
| `diff_hunk` | 有文本 hunk 时必须下发；行号按原文件 |
| `encoding` | 源文件非 UTF-8 时**显式标注**（如 `gbk`），并说明解码方式 |
| `lines` / `offset` / `segment` | 有则填；取不到的必须说明**为什么**（编码/二进制/夹具），不得静默留空 |
| `evidence` | 出处（文档/清单的哪个文件、哪一行、哪个 md5） |
| `unresolved` | 未决原因原文；未决条目不计入"已核对" |
| `drill_fixture` | drill/夹具条目必须显式标注，界面不得让操作者误以为是真实变更 |

- `doc_entry`：必须列出**变化字段**（before→after），其余字段折叠为"未变（N 项）"，并给源文档行号。
- `rtl_file`：尽量下行级 hunk；确实无文本时，必须同时给出**可替代的行号证据**（如 Host 留痕记录的行号与片段）。
- 未决条目必须提供**逐条处置途径**（界面输入，或等价 API），处置结果落 `gates.json`（`entry_decisions`），不得只靠一句随意的 reason 糊过去。
- 材料里必须给出 N3 摘要（`n3_digest.md`）与 Host 留痕（如夹具的 `mock_change_applied.json`）的入口；入口只做存在性探测，缺失显式标注。

**禁止**：用"路径字符串 + md5 变化"代替变更本体；把"无 hunk"呈现为"无变化"；把夹具数据当作真实变更呈现；材料不足以判断时仍诱导签署。

## 8. 生命周期、收敛、压力

| 关注点 | 设计 |
|---|---|
| 人工闸门暂停/恢复 | N4/N13/N14 是持久化状态点，人可挂起、恢复、改期 |
| 修订↔退回循环 | N6↔N8 循环设上限（建议 ≤3 次）；超限升级到 N13 人工裁决，**不死循环** |

| 全量回归 | 里程碑/发布前，`run_tc.py` 5 机 ×2 LIC ≈10 并行 ≈13~14h；串行 135h 不可接受 |
| **基线晋升** | N16 由人触发；新基线必须自洽完整、旧基线只增不改；manifest 成链（v₀→v₁→…），每轮可回放 |

| 收敛判据 | I1~I8 全满足 + 三闸门全过 + 所有用例态无「待验」+ 回归决策明确 + 晋升（若触发）原子完成 |
