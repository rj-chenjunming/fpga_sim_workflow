## 1 问题定位

本工具的真实节奏是「小时级等待被分钟级人工决策打断」：real 模式 N9 单用例约 19 min、修订后全跑可达 22.8 h（历史采样，唯一数字源 STATUS），而闸门开启/失败的感知目前完全依赖人主动盯面板。

现状事实（2026-10-24 代码快照）：

- 数据通道为纯轮询：可见标签 1.5 s、隐藏标签 10 s（`loop/web/app.js` 的 `POLL_MS`/`HIDDEN_POLL_MS`）；Agent 工作窗口另持一套 1.5 s 轮询（`loop/web/agent-window.js`）。
- 全 `loop/web/` 无浏览器通知、无服务端推送（无 `Notification`/`EventSource`/`WebSocket`）。
- `human:<name>` 操作者在闸门表单、Agent 控制窗口、S0 三处各自重填。
- 「错误/阻断/作业/证据的下一步动作分散 → 任务路径改版」已在 [AUDIT-20261021-workflow-priorities](../audit/AUDIT-20261021-workflow-priorities.md) 登记为后续产品改进，至今未排期。

本提案**不推翻任何既有测量结论**：F07 实测未达阈值 ⇒ 不动服务端分页/缓存；F11 维持后置；F05-b/c 既有编号不变（U3 并入，不另立）。

## 2 约束（继承红线）

1. 范围冻结：浏览器工作台（1280/1440/1920）；不做整站重设计、移动端、桌面客户端。
2. 零外链、零构建：`Notification`/`EventSource` 均为浏览器原生 API，不引入依赖或构建链。
3. 服务端唯一权威：本提案全部改动限于**投影消费与传输层**；前端不建第二状态机、不做判绿判红/预算/枚举判定（红线 8）。
4. 不新增业务事件 kind：推送内容 = 现有投影函数的输出；新 kind 须另行修订 SPEC-02。
5. 归档/证据纪律不变；本提案不含任何新增数字声称。

## 3 切片提案

### U1 等待送达（P0；纯前端 + 既有 API，零契约变更）

- **U1-a 浏览器通知与标题闪烁**：run 进入 `waiting_gate` / `failed` / 作业终态时，前端对比前后两拍投影触发 `Notification`；权限未授予或页面隐藏降级为标题闪烁 + 徽标计数。通知是投影的又一个消费者，不携带判定、不可回放为签署凭据。
- **U1-b 「在等我」行动条**：侧栏常驻条聚合所有 run 的待决策闸门、`failed` 待处置 run、S0 阻断，点击直达对应面板；数据全部来自既有 `list_runs`/`run_view` 投影，纯前端只读派生，不新建账本。
- **U1-c 操作者身份会话记忆**：应用级「当前操作者」（localStorage），闸门/Agent 控制/S0 三处预填、允许单次覆盖；权威仍以 `gates.json` + `human_signed` 为准，本项只是输入预填，不改 I6/身份契约。

验收：状态跃迁后一拍内触发通知且可关闭；行动条与 `list_runs` 同口径一致（测试同源断言）；预填不覆盖已填值；权限被拒时功能不报错、降级可见。

### U2 SSE 传输（P1；需先修订 SPEC-04 §6/§7）

- **U2-a** `GET /api/runs/{run_id}/stream`：SSE 下行，推送现有 `run_view` 投影（仅变化时推送）；客户端 `EventSource`，断线自动回退现有轮询，不双通道并发写。
- **U2-b** Agent 工作窗口轮询收编至同一通道（复用 `/agents/{node}` 投影，控制协议 SPEC-07 不变）。
- **U2-c** 作业日志尾巴流式追加（投影 `JobRunner.tail_log`，不新增权威日志）。
- 边界：仅传输层；四个写动作仍走既有 POST；不承诺 exactly-once，重连后以一次全量投影对齐。

验收：闸门开启的界面感知不再依赖轮询节拍；断线回退后行为与现状一致；单测以受控 generator 断言推送内容与轮询口径**逐字节一致**（同源投影，红线 8）。

### U3 渲染分段签名（P1；并入 F05-b/c 单一切片；设计详案见计划 §A）

- 现状：每次轮询/推送全量重画运行视图，输入子树保活依赖手工 signature diff 与表单 reconcile，epoch+request 并发守卫已有 4 套独立实现。
- 提议：按节（header/侧栏/运行{stages, agents, counts, blockers, job, events}/闸门{材料, 表单, 逐条}/横幅）计算**规范化内容签名**，渲染前比对、只重画变化节；与 `app.js` 拆分（F05-b/c）**同片执行**——先提纯模块（app-format / request-guard / dir-picker / gate-diff / agent-cards，每步一个提交、行为保持），再上节签名；并发守卫统一为共享模块。
- 边界：不改服务端契约；DOM id 与结构不变（browser 测试选择器不变）；含输入的节其签名**不含输入值**（输入保活由签名天然保证）；拆分次序与现状行号锚点见计划 §A。
- 验收：行为保持（现有 browser 特征测试全绿，断言不改）；焦点/草稿保活既有断言不变；DOM 变更量以 Playwright 计数断言下降（实施前先测量现状并登记阈值，不预写数字）。

### U4 G1 引导流（P2；纯前端；设计详案见计划 §B）

- 闸门作业动线「读材料 → 逐条处置 → 选决策 → 签署」改为线式 checklist：处置进度条（已处置/总数 + 每条状态 chip）、「下一条未处置」跳转（滚动+聚焦）、J/K 键盘跳转；全部处置且 `GateDraftBridge.counts().complete === true` 时提交按钮转高亮——**数据已有，不新算判据**。
- 边界：逐条处置判定唯一实现仍在 `GateSession.validateEntryDecisions`（口径同 gates.py），服务端 `gate_entries_view` 四态与 `entry_decisions` 载荷契约不变；**不扩大到 N13/N14**（用户裁决维持只读待确认，见 STATUS §50）。
- 验收：处置 n-1 条时提交仍禁用、全部处置后可用、跳转落点正确（browser 特征测试）；`POST decision` 载荷契约断言不变。

### U5 事件流客户端过滤（P2；纯前端）

- 事件列表加 kind/node 筛选 chips（纯客户端过滤，清除过滤即还原全量）；不动 F11 的服务端分页结论。

### U6 既有后置项收口（P2；每项独立小片，按各自既有编号执行；设计要点见计划 §C）

- **SPEC-09 后置**：AI 面板停靠/全屏（纯 CSS 切换，无数据变更）、跨关闭草稿（sessionStorage 按 `run/node/session` 身份键，提交成功或身份变化清除；草稿是**会话工作记忆非权威**，不落 run 目录）、N10/N11/N12 专用成果渲染（沿用 agent-results.js 既有模式，数据全部来自现有投影）。
- **attempt 输出 diff**：需在 `/agents/{node}` 投影**小契约增补**（相邻 attempt 结果摘要字段）——实施前按 SpecDD 先修订 SPEC-07 的 API 行，不得先改实现。
- **F14 欠账**：人工视觉验收矩阵 V6（125%/150% 缩放、hover/focus 动态态；自动工具已就绪，按 F14 既有验收执行并留证）。
- **legacy 清退**：删 `legacy.html`/`legacy.css`（「保留一个迭代」已过期；`test_web_smoke` 的 legacy 断言同步移除）；`mockup.html` 移出 StaticFiles 可达范围或加显著访问说明。

## 4 非目标

不做 WebSocket 双向通道（写动作沿用 POST）；不做前端业务判定；不做整站重设计/移动端/桌面端；不实现持久暂停与跨重启续跑（归 F09，另行契约）；不引入 UI 框架或构建链；不改动 Agent 上下文/记忆契约（SPEC-06）与控制协议（SPEC-07）。
