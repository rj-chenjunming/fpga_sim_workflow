## 3 偏离条款 D1–D4

> 每条都必须包含：差异、理由（含证据）、残余风险、**复评条件**。复评条件未满足前，按本偏离执行。

### D1 凭据投放：env + 显式风险记档（偏离 REV-13 §5.4）

| 项 | 内容 |
|---|---|
| 差异 | REV-13：attempt 资源不挂凭据文件，且"无法阻止工具读取原始秘密或宿主其他数据 ⇒ **带工具准入失败**"。本仓：凭据只经 attempt 进程 **env** 注入（不落 home），**带工具准入不以此为前提**。 |
| 理由 | 实测（P3）：沙箱只拦**写**，不拦**读**（`AGENTS.md`、`~/.dsh/settings.yaml` 均 `rc=0`）；`$HOME` 只读使"凭据副本同步"不可行；env 对 agent 的 bash 工具可见。强行满足 REV-13 需等价强制沙箱，本阶段不可得。 |
| 残余风险 | **实测更正（P0）**：dsh 会剥离工具 env 里的 `PUBLIC_API_KEY`（`KEYLEN=0`），未包裹时真正的洞是**文件可读**（`~/.dsh/.credentials.yaml` 237 B）；包裹后文件被遮蔽，但同 uid 下 **`/proc/<dsh-pid>/environ` 仍可读出 key**（`LEAK:/proc/6/environ`）。⇒ 秘密暴露面存在，仅靠审计发现，不靠技术阻止。 |
| 复评条件 | 出现能**挡读 + 清 env + 挡 `/proc` 读 environ** 的等价隔离并通过 `DS-04` 实测 ⇒ 立即重评是否恢复 REV-13 口径（届时 D1 作废）。**Q8 裁决（2026-10-28）**：维持 D1，但 **attempt 进程一律套 bwrap 缓解**（见 B8）；残余风险"key 可经 `/proc` 读出"显式记档，不称已解决。 |**P0 进展（2026-10-28）**：bwrap 包裹已能挡宿主数据 + 清 env（[证据](../evidence/DSH_P0_20261028/README.md)），但同 uid 下 `/proc/<dsh-pid>/environ` 仍可读出 key ⇒ 复评前提**未满足**；处置待 Q8 裁决（见 STATUS §108.3）。 |

### D2 自动压缩：保留 DSH 压缩 + Host 落账（偏离 REV-13 §5.4 / DS-07）

| 项 | 内容 |
|---|---|
| 差异 | REV-13：受限 profile 关闭自动压缩。本仓：保留压缩，Host 从 session log 读 `compaction/summary`（`time`/`compactionId`/`shadowedTokenCount`）落账并在投影展示。 |
| 理由 | P7：压缩可低成本触发且**事实可读**（session log），但**事件流与 projcache 都没有**；REV-13 的"关闭"在本版本需靠配置键钉死，且会让长任务更易因超窗失败。选择"允许 + Host 落账"以保留可追溯性。 |
| 残余风险 | 压缩后"是否读完输入包"**不可证**：覆盖责任收缩为"Host 输入包 + 提交回传"；业务结论不得依赖未提供材料（继承 SPEC-06 的覆盖纪律）。 |
| 复评条件 | ① DSH 在事件流/投影提供 compaction 事实 ⇒ 改"事件流优先、session log 兜底"；② 若压缩导致可观测的业务误判 ⇒ 关回 REV-13 口径。 |

### D3 attempt home 共用 + 会话 `resume` + 人可在 GUI 说话（偏离 REV-13 §5.3 / §2）

| 项 | 内容 |
|---|---|
| 差异 | REV-13：每 attempt **私有** `DSH_HOME`/`DSH_AGENTS_HOME`、不连接在用会话、**不使用 `session/resume`**、不实施共享聊天历史。本仓：**共用同一实例 home**；同 `(run,node)` 跨 attempt 用 `--session-id`/`session/resume` 复用；人可在 DSH GUI 对会话说话（**只能在该 attempt 进程退出后的空闲期**）。 |
| 理由 | 产品动机：人要"看得见对话、能当场指正"。实测（P1）：共用 home 时 Web 能列出/打开他进程创建的会话、并发写安全（`sessions=10 ok=10 bad=0`）；`resume` 跨进程/跨 cwd 可用；**写句柄互斥**（`already owned by an active write handle`）恰好把"人说话"限制在两次 attempt 之间——与"指正只在下一个请求边界生效"（体检表裁决 #10）一致。 |
| 残余风险 | ① 孤儿资源可能落在共用 home（需按 intent 标签清理，REV-13 §4.3 的 intent 机制必须保留）；② 会话历史跨 attempt 累积，跨 run 仍不继承；③ 人话未经 Host 准入即改变模型行为（只记元数据，结果校验兜底）。 |
| 复评条件 | ① DSH 支持"只读挂载他人 home 会话"或写句柄仲裁原语 ⇒ 重评是否需要共用 home；② 出现会话库损坏/锁冲突实测 ⇒ 退回私有 home + 导出副本。 |

### D4 子 agent：全开放 + 配额 2（偏离 REV-13 §2 / §5.4）

| 项 | 内容 |
|---|---|
| 差异 | REV-13：不实施并行子 Agent、默认关闭自动委派。本仓：允许会话内 spawn，**配额 `maxActiveSubagents=2`** + 工具白名单 + 记账。 |
| 理由 | P6：sdk 协议稳定发出 `subagent.started/finished`（含 `parentSessionId`/`childSessionId`/`stopReason`/`lastAssistantMessage`），越额**显式拒绝**（原文 `active child limit: 1`），可审计。 |
| 残余风险 | 成本/时延未测；后代可能残留（P5：SIGKILL+full-access 留孤儿）⇒ 记账与终止契约必须先于放开配额。 |
| 复评条件 | ① 成本/时延/后代残留实测超阈值 ⇒ 收紧为节点白名单或关闭；② 配额实际生效值须**运行时回显**（默认 8 不能当生效值，P6 实测提示 1）。 |

## 9 DS-09 来源判定（S8b 收口；**只增，不改写 §4-B3 与 §3-D3 原文**）

> 背景：§3-D3 的契约是「**共用同一实例 home**，人可在 GUI 看到会话并说话」。S7c 实现时发现
> `dsh --profile web` 会在 home 里**自生成** `.credentials.yaml`（会话签名 secret），而 §4-B3 的
> `DS-09`（`dsh_assets.FORBIDDEN_HOME_ENTRIES`）把它一律判成「attempt home 含宿主件」。
> 两者冲突 ⇒ S7c 临时把 Web 实例 home 改成与 attempt `dsh-home` **并列**的 `dsh-web-home`，
> 代价是**人在 GUI 里看不到该 attempt 的会话**（产品目标 D3 未落地）。
> 2026-10-29 人工裁决（S8 计划 §2-B1）：**保留 B3 的禁令语义，新增"来源判定"**，据此取消并列目录。

### 9.1 判据（`DS-09` 修订；四档，全部可观察、可测）

对 attempt home（含共用后的同一目录）里出现的每个 `FORBIDDEN_HOME_ENTRIES` 条目，逐条判定来源：

| 档 | 来源 | 识别依据（判据） | 处置 |
|---|---|---|---|
| `host_settings_copy` | Host 把宿主 `settings.yaml` 复制进来 | 该文件名命中 `settings.yaml`（§4-B3 的唯一禁止对象；Host 侧**不存在**任何写入路径，dsh 也**不生成**该名） | **拒绝** |
| `host_credential_value` | 宿主凭据被复制/写入 | 文件内容包含**任一宿主凭据值**（Host 在内存中持有的 secret 集合，逐条子串比对；比对在内存完成，**不落盘、不进错误消息、不回显**） | **拒绝** |
| `dsh_generated` | `dsh` 自己为本次实例生成 | ① 内容**不含**宿主凭据值；② 内容形态符合 `dsh` 自生成登记形态（键集合 ⊆ `DSH_GENERATED_CREDENTIAL_KEYS`，该常量由 S8b 真机实测登记并由"常量漂移"用例钉住）；③ 文件位于本 attempt 的 home 内 | **放行**，并在准入记录登记 `source` + `basis` |
| `unknown` | 形态不认识 / 读取失败 / 无判据可用 | —— | **拒绝（fail-closed）** |

**不变量**：

1. **`settings.yaml` 无例外**：任何来源都拒绝（B3 原文语义不变）。
2. **凭据值优先于形态**：即使形态像 `dsh` 自生成，只要内容含宿主凭据值 ⇒ `host_credential_value` 拒绝。
3. **`unknown` 即拒绝**：没有"看不清就放行"的档。
4. **零回显**：判定结果、错误消息、日志、准入记录里**不得**出现凭据值或 secret 片段；只允许
   `source` 枚举、文件名与"第 N 个宿主凭据命中"这类**不含值**的描述。

### 9.2 记录与可审计

- 准入记录（`agent_calls/**` 的 attempt 记录 / 自检回显）新增 `home_provenance[]`：
  `{name, source, basis}`。旧记录可缺省（缺失 = 未判定，**不等于通过**）。
- 判定入口仍只有 `dsh_assets.home_problems(...)` 一处（红线 8）；调用方只消费结论，不重算。

### 9.3 与 D3 的归属

- `dsh_assets.workspace_root` 的 `dsh-home` 是**唯一** attempt home；`dsh-web-home` 并列目录**取消**
  （S7c 的临时偏离在此收口；旧元数据仍可被 `stop` 识别，只读兼容）。
- home 共用带来的残余风险沿用 §3-D3 登记（写句柄互斥、跨 attempt 累积）；不新增第二条隐性写权。
- 本判据**不**声称挡住恶意进程在 home 内伪造"自生成形态"的文件；`bwrap`（B8）与凭据只经 env 注入（D1）
  仍是隔离主体。**不把 DS-09 写成"home 不可信内容已被隔离"**。
