## 1 问题与现状（实测）

- `gates.sha256` 的锚只覆盖 `gates.json` **自身**：`kb_lib.py:667-701` 对"去 anchor 的 JSON"求 sha256。
- 签署时 Host 会把 `gate_artifacts()` 的 `<相对路径> md5=<…>` 传成 `--artifact`（`workflows/chunks/gates.py:288`），
  但 `gate.py` **只打印/保存清单**（`gate.py:219-220`、`kb_lib.py:642-643`），`require-signed` **从不复算**。
- 结论：**批准之后改件不会让批准失效**——证据是假的（体检表 §3-#6 判定"偏离"）。

## 2 定义（唯一口径，只在本文件与实现处出现）

### 2.1 材料集 `M(run)`

递归遍历 `kb/runs/<run>/`，取**普通文件**，按 POSIX 相对路径字典序；**跳过符号链接**（不跟随，避免逃逸）。
排除项（都是签署之后会合法变化的记录/缓存，不是"材料"）：

| 排除 | 理由 |
|---|---|
| `gates.json`、`gates.sha256` | 本记录自身（由 anchor 保护） |
| `agent_calls/**` | 模型调用审计，只增不改，每 attempt 都变 |
| `agent_controls/**` | 控制审计，只增不改 |
| `decisions/**` | 逐条处置落账，**签署之后**由 Host 写入（G1 决策即写） |
| `view.json` | 界面投影缓存，可重建 |

每件记 `{path, size, md5}`；`materials_digest = sha256(canon(M))`（`canon` = `kb_lib.canon_json`，与锚同一实现）。

### 2.2 闸门摘要 `gates_digest`

`{gid: {decision, status, actor, actor_kind, human_signed, signed_at}}` 覆盖三道闸门全部条目；
`gates_digest = sha256(canon(该映射))`。**不含** `history`（只增，不作指纹）。

### 2.3 `state_hash`

```text
value = sha256(canon({
  "schema": "kb/gate-state-hash/1",
  "run_id", "gate_id", "decision", "actor", "actor_kind", "signed_at",
  "manifest_from", "manifest_to",
  "materials_digest", "gates_digest"
}))
```

存储：`gates.json → gates.<gate>.state_hash = {algo, value, computed_at, materials_digest, gates_digest, materials: [{path,size,md5}], gates: {…}}`。
该对象**被 `anchor` 覆盖**（anchor 对整份 `gates.json` 求 sha256，无需另加锚）。
`algo` 常量：`sha256-of-materials+gate-summary`（单一定义，两处共用，禁止字面量漂移——F-SCHEMA-01 的教训）。

## 3 签署（`gate.py sign`）

1. 先按现行规则校验（闸门/枚举/actor_kind/human 留痕/I6），状态不合法不写盘。
2. 写入决策字段与 `history` 追加（不变）。
3. **计算并写入 `state_hash`**：材料集全量 md5 + 当前闸门摘要（含本次签署）。
4. 落 `anchor` 与 `gates.sha256`（不变）；写前 `check(st,"gate_state")`。
5. 任何材料不可读（权限/IO）⇒ **显式失败 rc=4**，不跳过、不抽样、不用 mtime 代替内容。

## 4 校验（`gate.py require-signed`）

对每个待校验闸门（`--gate` 或全部）：

| 情形 | 结果 |
|---|---|
| 闸门已签且**有** `state_hash`，复算 materials_digest / gates_digest / value **全等** | 通过（沿用既有逐门判定） |
| 任一不等 | **rc=3**，输出 `[FAIL] STATE_HASH_MISMATCH`：该门 + `changed`/`added`/`removed` 三组路径（最多各 5 条 + 总数）+ "旧签署不再有效，须重跑闸门；gates.json 未改动" |
| 闸门**无** `state_hash`（legacy 或 pending 未签） | 闸门已签 ⇒ `[WARN] legacy 状态无 stateHash（未校验）`（与 anchor None 同口径）；pending ⇒ 仍按未签拒绝（不变） |

- 复算只读磁盘，**不写** `gates.json`；失败不消耗中断、不改任何状态。
- 材料缺失/不可读 ⇒ 视为 `removed` 并失败（不得"读不到就当没变"）。

## 5 边界与不声称

- **不**引入第二套判据：文件遍历/md5/canon 复用 `kb_lib`（`canon_json`/`sha256_text`）；
- **不**设体积上限、**不**抽样；实测体量：drill run `5546` 文件 / `752 057 424` B / `1.445 s`（含 `sandbox/` 690 M 与 `baseline_drill/` 22 M），小 run 约 3.2 MB / 30 文件。阈值：单次 `> 5 s` 或 `> 2 GB` 再议缓存（缓存不得成为权威）；
- **不**保护 `agent_calls/agent_controls/decisions/view.json`（它们是记录，不是材料）——攻击面留给 anchor；
- **不**改变 `human_signed` 铁律与闸门枚举（那是 I6 / `kb_lib.GATE_DECISIONS`）；
- **不声称**：旧 run 自动回填（不回填，标 legacy）；不承诺防篡改强度超过 sha256 + anchor。

## 6 兼容与迁移

- `gates.json` 的 gate 条目 `additionalProperties: true`（schema 现状）⇒ 新增 `state_hash` 不需迁移；
  schema 同步补一个**可选** `state_hash` 定义，仅为契约可读性，不设为 required。
- 旧 run 无 `state_hash`：保持 legacy 语义（WARN），**不回填**；需要强校验时由人重签一次。
- 冻结件（`doc/evidence/**`、历史 run）不改；本轮只对**新签署**生效（"新范围只对新行为生效"）。

## 7 验收（先失败用例；TDD）

| 用例 | 断言 |

## 8 未决

- 材料集体量增长后的耗时上界：本轮实测 `1.445 s`（§9），暂不设缓存；触发条件见 §5 阈值。
- `sandbox/`（N6 工作副本）纳入材料：它是修订件本身，改它就应该让旧批准失效；`baseline_drill/` 同理。若将来 `sandbox/` 出现"每次重生成但业务等价"的文件，再按证据评估是否拆出。
