## 3 无进展告警（`OBS-03`）

### 3.1 判据（唯一实现，纯函数）

- 阈值常量 `NO_PROGRESS_THRESHOLD_S`：**显式常量、单一来源**（`services/agent_view.py`），初值 **600 秒**；界面只显示服务端下发的 `threshold_s`，不自己带一个数。
- `t_last = max(last_event.ts, last_result.ts)`（有哪个取哪个，都有取最大）。
- `silence_s = now_epoch - t_last`（`max(0, ...)`）。
- `no_progress.state`：
  - `"n/a"`：`state != "working"`（idle/done/failed/闸门 waiting 都不告警）；
  - `"warn"`：`state == "working"` 且 `silence_s >= NO_PROGRESS_THRESHOLD_S`；
  - `"ok"`：`state == "working"` 且 `silence_s < NO_PROGRESS_THRESHOLD_S`；
  - `"unknown"`：`state == "working"` 但 `now` 未注入或 `t_last` 缺失（**不猜**）。
- `no_progress.since_ts` = `t_last`；`reason` 为可读短句（`warn`/`unknown` 时非空）。

### 3.2 只告警不收敛

- `warn` **只**产生投影字段与界面红字：不得改节点状态、不得发 `/control` 命令、不得终止执行、不得重发请求（"卡死只告警不自动收敛"，体检表 §2 裁决 #12）。
- 运行/节点状态仍由原 owner 决定；告警不是状态。

### 3.3 界面文案（`OBS-03`/`OBS-07`）

- `warn` 时红字必须同时含：**无进展 N 分钟**（N 由 `silence_s` 取整）+ **最后事件**（kind/状态/时间）+ **最后错误**（有则显示，无则明确"无错误记录"）。
- **禁止**任何把 Agent 停滞伪装成人工介入的措辞：`在等人工`、`等待人工`、`等待处理`、`待人工确认`——**作用域 = Agent 运行状态面**（角色卡状态、Agent 窗口的状态/摘要/无进展区、`execution_unknown` 文案）。用例断言以 Agent 窗口容器与角色卡为准。
- **不适用范围（明确排除）**：**闸门视图**的既有文案（如"等待人工决策"）是闸门事实（真的在等人裁决），**保留原词**，不得为本条改写；把闸门语义改写成别的词属越界改动。
- `failed` / `execution_unknown` 必须如实显示（失败显式纪律），不得降级成"运行中"。

## 4 时间口径（`OBS-03`/`OBS-04`）

- `now` **唯一入口**：`host/paths.py::now_iso`（优先 `LOOP_NOW`，其次 `KB_NOW`，否则系统时间）。`run_view` 与 agents 窗口都从该入口取 epoch 传入投影，**不得**在 `agent_view`/`contracts`/前端各自取墙钟。
- 测试**不得**用墙钟：`now` 由参数注入或在进程内固定 `LOOP_NOW`。
- 未知时间显示 `unknown`；上限/比例未知时**不显示比例**（沿用 SPEC-07 §可解释性 4）。
- 时间的比较与差值全部用 epoch 秒（浮点）与整数秒输出，禁止字符串比较。
- **事件时间源（实现期补充）**：事件流 `ts` 由 `host/progress.py::ProgressLog.append` 用系统时钟写入，与 `now_iso()` 的注入时钟**可能不同源**（drill 固定 `LOOP_NOW` 时）。判据口径：差值以 0 夹紧（`max(0, ...)`），**不得因此产生假告警**；真实运行不注入时钟，两者同源。把事件 `ts` 改为走注入时钟属共享判据面变更，登记 §9-8，不在本片做。

## 5 同源反代（Q7，`OBS-05`/`OBS-06`）

背景：跨站 iframe 不可用（P8 实测：匿名 401、只有 `?token=`→`SameSite=Strict` cookie、`/api` 跨权威 403）⇒ 必须**同源反代**。朴素反代是开放代理/SSRF/凭据泄露面，故本节的拒绝矩阵是交付主体。

### 5.1 路由与可用性元数据

- `/{GET|HEAD|POST|PUT|PATCH|DELETE|OPTIONS} /instance/{run_id}/{node}/{attempt}/{path:path}`（`path` 可为空）：唯一反代入口。
- **方法口径**（2026-10-28 实现期修正）：反代是"人在 GUI 里看/说"的**旁路会话面**通道（REV-14 D3），DSH Web 的 `/api/*` 是 POST RPC ⇒ 若只放行 GET/HEAD，iframe 会"能打开但点不动"，违背开工提示词 §4.1 的"iframe 内 `/api` 不 403"验收。因此 **HTTP 方法原样透传**（`GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS`），但：
  - 目标仍然只能来自受管元数据（§5.2），客户端任何目标信息无效；
  - 透传写的是**上游实例自己的会话状态**，不是本仓业务状态；业务写权仍在 Host（`kb/**`、闸门、计数、`agent_memory` 封存一律不经反代）；
  - `CONNECT`、`TRACE` 与 WebSocket/`Upgrade` ⇒ **405**（升级支持登记为 §9 未决）。
- `GET /api/runs/{run_id}/agents/{node}/instance`：可用性元数据（见 §6.1），只读。

### 5.2 目标来源（受管元数据，**绝不接受客户端传目标**）

按序取第一个存在者：

1. `<run_dir>/agent_instance.json`（Host 落账：`{node, attempt, host, port, token, session_log?, written_at}`；`session_log` 可选，**相对 run_dir**，越界/符号链接拒绝）——**本片唯一实现的来源**；
2. ~~`SETTINGS.yaml` 的 `loop.agent_runtime.dsh.web`（常驻实例）~~ —— **本片不实现，登记 §9-6**：该键会被 `dsh.config_from_settings` 的 `CONFIG_KEYS` 判为未知字段（`test_dsh_backend.py` 会红），而 `SETTINGS.yaml` 与 `dsh.py` 都不属 S4 写权。S5 真机接入时与 `agent_instance.json` 的写入方一并落地，沿用同一 loopback/token 判据。

判据：`host ∈ {127.0.0.1, ::1, localhost}` 且 `1 <= port <= 65535`；否则 `target_not_loopback` / `target_invalid`。**客户端**的 query/body/header 里的任何目标信息（含 `url`、`port`、`token`）一律忽略。

### 5.3 拒绝矩阵（解码后校验；拒绝即不转发）

| # | 输入 | 判据 |
|---|---|---|
| R1 | 路径段含 `..` | 拒绝 |
| R2 | 百分号编码后解码含 `..`（`%2e%2e`） | 拒绝（解码一次后判） |
| R3 | 双编码（`%252e%252e`）解码两次后含 `..` | 拒绝 |
| R4 | 编码的 `/`（`%2f`）导致段边界变化 | 拒绝 |
| R5 | 路径以 `/`、`//` 开头或在 authority 位置含 `://`、`@` | 拒绝（绝对 URI / 协议相对） |
| R6 | 含控制字符（`<0x20`、`0x7f`）或 `\` | 拒绝 |
| R7 | `Host` 头不是本服务的 loopback 名（`127.0.0.1[:port]`/`localhost[:port]`/`[::1][:port]`） | 400 拒绝 |
| R8 | 路径长度 > 2048 或 query 长度 > 4096 | 拒绝 |
| R9 | 目标非 loopback / 端口非法 | `unavailable: target_not_loopback`/`target_invalid` |
| R10 | 目标元数据缺失 | `unavailable: target_missing` |
| R11 | 上游连接拒绝/不可达 | `unavailable: upstream_unreachable` |
| R12 | 上游超时（连接 1.0 s / 读 15 s 显式常量） | `unavailable: upstream_timeout` |
| R13 | 上游 401/403 | `unavailable: upstream_auth`（不得伪装成需要人操作） |
| R14 | 客户端试图用 `token`/`url`/`port` query 指定目标 | 参数被丢弃，不进上游 |
| R15 | 上游 `Location` 含受管 token 或指向上游绝对地址 | 改写为同源相对路径并剥离 token（否则 token 经 302 进浏览器地址栏） |
| R16 | 客户端 `Forwarded`/`X-Forwarded-*`/`Via`/`Proxy-*` 头 | 不转发（与 hop-by-hop 同组） |
| R17 | 上游 `Set-Cookie` 含 `Domain` | 删除 `Domain`，其余属性逐字保留 |
| R18 | 上游**多个** `Content-Security-Policy` 头 | 逐个做 `frame-ancestors 'self'` 替换，其余指令逐字保留 |
| R19 | 上游 5xx | 状态码透传但**加** `X-Instance-Proxy: unavailable` + `reason=upstream_error`，不伪装 ready |
| R20 | 上游 `text/html` 且 `X-Frame-Options` 缺失/有值 | 一律删除 XFO（同源 iframe 需要），并有用例点名 |

### 5.4 转发与凭据

- 上游 URL = `http://{host}:{port}/{path}` + 原始 query，**丢弃**客户端 `token` 参数。
- 受管 token 注入：仅当（a）元数据有 token 且（b）本次客户端请求**没有** cookie ⇒ 上游 query 追加 `token=<受管值>`；响应侧 302 到去掉 token 的同路径（让浏览器只保留 cookie）。
- **token 永不出现在**：本服务日志、错误体、JSON 响应、`X-Instance-Proxy-*` 头、错误页 HTML。
- 请求头：不转发 hop-by-hop（`connection`、`keep-alive`、`proxy-*`、`te`、`trailer`、`transfer-encoding`、`upgrade`）与 `Forwarded`/`X-Forwarded-*`/`Via`（R16）、不转发客户端 `Authorization`；`Host` 改写成目标 authority。
- **同源改写**（否则 DSH Web 的 `/api` 会按 Origin/`sec-fetch-site` 围栏回 403，P8 实测）：把 `Origin`/`Referer` 改写为上游 authority；`Sec-Fetch-Site` 有则改写为 `same-origin`。这是**为了在同源反代下恢复"看起来同源"的上游语义**，不是放宽上游判据（上游自己仍会校验 cookie）。
- 响应头：删除上游 `X-Frame-Options`（同源 iframe 需要，R20）；若上游 `Content-Security-Policy` 含 `frame-ancestors` ⇒ **只**把该指令替换为 `frame-ancestors 'self'`，其余指令逐字保留，多头实例逐个处理（R18）；上游无 CSP 则不新增。`Set-Cookie` 透传但删除 `Domain`（R17）、`Path` 限定为 `/instance/{run}/{node}/{attempt}/`。`Location` 按 R15 改写。
- 不缓存、不落盘、不写 run 目录。

### 5.5 不可用态（显式，**不是** 500 空白、不假装可内嵌）

- `state ∈ {ready, unavailable}`；不可用时 HTTP **503**，带 `X-Instance-Proxy: unavailable`，`reason ∈ {target_missing, target_not_loopback, target_invalid, upstream_unreachable, upstream_timeout, upstream_auth, upstream_error, health_unknown}`（`upstream_error` = 上游 5xx，状态码透传，R19）。
- 内容协商：`Accept` 含 `text/html`（iframe 导航）⇒ 极简 HTML 错误页（原因 + 「在新标签页打开」链接）；否则 JSON `{"available": false, "state": "unavailable", "reason": ...}`。
- 拒绝（§5.3 R1–R8、R14）⇒ 400/404，`X-Instance-Proxy: rejected`，同样不回显 token。

## 6 界面与降级（`OBS-06`/`OBS-07`/`OBS-08`）

### 6.1 可用性端点

`GET /api/runs/{run_id}/agents/{node}/instance?attempt=N` ⇒
`{"available": bool, "state": "ready"|"unavailable", "reason": <§5.5 枚举>|null, "url": "/instance/<run>/<node>/<N>/"|null, "embed": "iframe"|"new_tab_only", "attempt": N, "authority": "projection"}`。
**可用性是 (node, attempt) 粒度**（2026-10-28 复核 P1 修正）：`attempt` 必须是**当前窗口选择/活跃的 attempt**；界面必须显式带 `?attempt=`，**不得**依赖服务端默认值（否则多 attempt 下恒 `target_missing`）。元数据的 `node`/`attempt` 与请求不一致 ⇒ `target_missing`（不跨 attempt 借用实例）。`session-copy` 同理必须带 `attempt`，且**校验归属**（不得导出别的节点/attempt 的会话日志）。
**不返回** token、端口之外的宿主细节。

### 6.2 降级（Q5 降级线）

- `available=false` **或** iframe 加载失败（error/超时）**或** 上游 401/403、CSP/响应头变化 ⇒ 必须显示降级块：明确「不可内嵌」+ 原因 + 「在新标签页打开」+ 「导出会话副本」。
- 不得静默白屏、不得假装已内嵌、不得把 401 显示成"需要人操作才能继续"。
- `GET /api/runs/{run_id}/agents/{node}/session-copy`：`{"available": bool, "reason": ..., "kind": "session_log_facts"|null, "facts": {...}|null, "bytes": int|null, "truncated": bool, "attempt": int|null}`。
  **语义修正（2026-10-28 实现期）**：既有 `dsh_sdk.read_session_log` 返回的是**压缩等会话日志解析事实**（`CompactionFacts`），**不是对话原文**⇒ 本端点只返回"解析事实 + `kind` 标签"，不得声称是"会话副本全文"；元数据无 `session_log` ⇒ `available=false, reason="session_log_missing"`。人类可读会话原文导出登记 §9-10（需要单独解码器，多帧 zstd 未验）。
  **reason 族（本端点专用，不进代理 503 枚举）**：`session_metadata_missing` / `session_metadata_invalid` / `session_owner_mismatch` / `session_log_missing` / `session_log_invalid` / `session_log_unavailable`；归属校验与 §5.2 目标解析同源（同一 `(node, attempt)` 判据）。

## 8 兼容、回退与不回归

- 新字段**可缺省**：旧 run/旧记录没有 `progress`/`explain` ⇒ 界面显示"未记录/未知"，不回填历史。
- 投影缓存（若引入）可丢弃、必须有明确重建路径，且不得成为权威（SPEC-07 F07 触发阈值未达前**不加缓存**）。
- 反代可以不部署（元数据缺失 ⇒ 恒 `unavailable`），此时界面走降级线，功能不受损。
- 回退：删路由 / 关配置即回到"仅投影 + 导出会话副本"，不改变任何既有端点语义。

## 9 未决（照实登记，不静默补实现）

1. **真实 DSH Web 实例的端口/令牌落账**（`agent_instance.json` 写入方）属 S5；本片只读，缺失即 `target_missing`。
2. **WebSocket / SSE 升级**未支持（一律 405）；DSH Web 是否需要，S5 接入时实测后再定。
3. **`scope_expiry` 的归约判定未实现**（计划 §6.4-39）：本片只显示"未判定"。
4. **会话副本解码**只到既有 `read_session_log` 能力范围（多帧 zstd 未单独验）；截断/超大按上限显式标 `truncated`。
5. **`node_rework`/`run` 作用域的到期判定**修复可另开小片；本规格不承诺。
6. **`SETTINGS` 常驻实例源（§5.2 #2）本片不实现**：该键会与 `dsh.config_from_settings` 的 `CONFIG_KEYS` 校验冲突（会红 `test_dsh_backend.py`），且 `SETTINGS.yaml`/`dsh.py` 不属 S4 写权；S5 真机接入时与 `agent_instance.json` 写入方一并落地。

9. **`last_tool` / `last_result.ts` / `session_log_ref` 的生产者待 S5**：S4 只按字段消费，缺则 `null`/`unknown`（计划 §6-8/§6-9）。
10. **iframe 内上游绝对路径未解决**：反代只做前缀剥离/头改写，**不改上游 HTML**。若 DSH Web 的 `index.html` 用绝对 `/assets/...`、`/api/...`，浏览器在 iframe 里会打到看板根（落到 `StaticFiles` ⇒ 404，页面能开、资源断）。S4 不实现 HTML 重写或 `<base href>` 注入（会改动上游内容、风险大于收益）；**登记为 S5 真机实测后再定**（备选：上游支持 base path 配置、或 S4-C 降级块承接）。
