# SPEC-REV-19 · 会话日志发现：元数据未声明 `session_log` 时按 attempt 的 dsh-home 解析（2026-10-29）

> 状态：**人反馈驱动，实现收口（S8l）**。基线 `9017887`（含 [REV-18](SPEC-REV-18-20261029.md)）。
> 关系：在 [REV-16 §6.2](SPEC-REV-16-20261028.md) 的 `session-copy` 上**只增**一条来源规则；不改 §5.2 的
> 越界/符号链接判据，不改 `reason` 族，新增 `OBS-11`。
> 依据：人 2026-10-29 —— S8k 上线后「刷新了，咋没涨？」。根因：`agent_instance.json` **从来没有** `session_log`
> 字段（S5 未落账），演示只能挂一份**快照副本**，人在实例里新说的话不会进那份副本。

## 1 问题与范围

- 现象：`人参与 N 次` 只在"元数据声明了 `session_log`"时才有真数；真实 attempt 一律 `session_log_missing`
  ⇒ 执行结果块恒显示「不可用」，人参与次数永远出不来。
- 本规格只改**读取来源**:在元数据缺失时，按 attempt 自己的 dsh-home 解析会话日志；不改写入方
  （S5 将来落账 `session_log` 时仍优先用它）、不改 UI（`人参与` 的渲染口径见 REV-18 §3）。

## 2 解析规则（唯一实现：`dsh_sdk.find_latest_session_log`）

1. 位置：`<attempt 布局的 dsh-home>/sessions/<cwd 编码目录>/session-*/session.v4.jsonl.zstd`；
   cwd = 该 attempt 的 `work`（`AttemptLayout.work`，路径唯一来源），目录名编码见下；
2. 编码：`/<a>/<b>` → `--a-b--`（去前导 `/`、`/`→`-`、前后各加 `--`）；**唯一实现**在
   `dsh_sdk.session_dir_name`，proxy 与服务不另写；
3. 只认目录名**逐字等于**该编码的会话（别的 cwd 的会话属于别的 workspace/attempt，借用会数错人）；
4. 同目录多个会话 ⇒ 取 **mtime 最新**（并列取名字最大，结果确定）；
5. 符号链接、非普通文件、非 `session.v4.jsonl.zstd` 一律跳过（不扩大读取面）；
6. 解析不到 ⇒ 仍 `session_log_missing`（不编造"空会话"）。
7. 元数据**已声明** `session_log` ⇒ 仍走 REV-16 §5.2 的既有校验（相对 run_dir、非符号链接、越界拒绝），
   解析器**不覆盖**它。

## 3 响应字段（只增）

`GET …/session-copy` 的可用响应新增 `session_log_source`：

| 值 | 含义 |
|---|---|
| `"metadata"` | 来自 `agent_instance.json.session_log`（原有路径） |
| `"newest_mtime"` | 元数据缺失，按 §2 解析到的该 attempt 最新会话 |
| `null` | 不可用（沿用既有 `reason`，不新增字段语义） |

不可用响应**保持六键不变**（`available/reason/kind/facts/bytes/truncated`），不新增键——避免把"来源"塞进失败体。

## 4 验收（新增 `OBS-11`）

| 编号 | 判据 | 方式 |
|---|---|---|
| `OBS-11` | ① 目录名编码唯一实现在 `dsh_sdk.session_dir_name`；② 同 cwd 多会话取 mtime 最新；③ 别的 cwd 的会话不被借用；④ 符号链接会话被跳过；⑤ 无会话 ⇒ `session_log_missing` 不变；⑥ 元数据声明时优先用元数据且 `session_log_source="metadata"`；⑦ 解析到的活日志**随写入增长**（`human_messages` 递增） | 单测 + proxy 用例 |

## 5 未决（只增）

- **多会话歧义**：同一 attempt 的 cwd 下可能有多条会话（人在 GUI 新开一条）⇒ 本规格取最新一条，
  记录为 `session_log_source="newest_mtime"`；若将来要"按会话选择"，需要选中会话的 id 落账（写入方改造）。
- S5 落账 `session_log` 后本解析器只作为兜底；未落账期间的"最新会话"可能不是 agent 主会话，界面已用
  「人参与」这类聚合事实呈现，不声称是"唯一会话"。
